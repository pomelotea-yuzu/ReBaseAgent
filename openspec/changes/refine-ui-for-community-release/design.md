# UI 整理设计

## Context

问题及依据见 proposal。当前单运行、辅助任务、比较对象、草稿和后台操作已有各自身份及恢复规则；全局栏直接使用当前加载 detail，容易在比较页表达错误对象。草稿库已有 dirty 判据，问题主要在 clean 条目与 modified 条目的命名和层次。现有说明去重、确认块、编辑器恢复及专注模式继续复用。

基线：文档整理提交 `afd60c9`，产品源码／主 spec 最新归档为 R2.1 `ac8729e`。本设计是新 change 的初稿，未实现。会话草图是讨论材料，包含简化示例及未接线动作，不是功能基线。

## Goals / Non-Goals

目标是统一信息归属及完整用户路径，在日常窗口能指出对象、找到动作、恢复输入和返回来源。修改页面外壳时保留已有单一事实源，不通过重置 store 或卸载编辑器获得简洁界面。

本轮不引入新的运行模型、记录格式或执行权限；设置继续使用真正模态。具体布局位置在首组原型中核对，涉及行为变化先同步设计／delta，不能把草图直接当实施模板。

## Decisions

### D1：分工明确的共享页面结构

全局栏保留品牌、运行记录／分支关系切换、新建、录制和设置（含运行配置）。主工作区对象头负责当前运行，编辑任务负责来源 run／调用／字段，比较负责左右对象，新建明确为新任务。会话活动入口是既有草稿会话入口、全局操作入口及全局结果未读提示的统一组织演进，不新增第四个并存入口或第二份状态；组内保留修改、操作及结果各自独立计数和可达动作。本运行草稿列表和调用旁标记继续保留，使用同一草稿事实。初始方案采用底部简短入口，异常不能只藏在面板中，代理恢复异常仍按现行契约留在顶栏。

采用共享外壳和既有 WorkspaceHeading／AuxWorkspaceFrame 的演进，避免每个功能重复造导航。底部活动区与顶栏分组都可在原型中比较；选择位置不改变全局可达性和状态语义。

活动入口继续分别遵守主 spec“草稿可定位且来源失效不丢输入”“跨页操作反馈展示真实等待与分层状态”“结果导航尊重用户当前阅读意图”：精确草稿定位及失效保护、真实等待／未知状态、全局未读标记和 polite live 通知不被一个合计数字替代。设置模态覆盖期间遵守既有焦点和背景隔离，关闭后可恢复活动入口，不为全局可达性放开模态背景交互。

录制入口改写属于文字对齐既有实现：`App.tsx` 的 `openRecording` 调用 `openRecordingWorkspace`，录制视图呈现 `RecordingWorkspace`，`GlobalBar` 的录制按钮调用该入口。已有独立录制契约不变，本 change 不创建第二条接入流程；索引 R07／N16 分别核对既有入口回归和本次入口整理。

### D2：呈现身份从实际任务派生

页面标题及来源摘要从当前工作区的真实绑定取值，不能统一拿 detail.meta.id 当当前对象。比较选择、侧栏选中和编辑来源继续独立；提供可读任务名及必要短 ID，完整 ID 可复制。重命名只作用于界面标签，不更改 trace 字段、IPC 或内部运行身份。

返回入口显示“返回运行概览／第 N 轮调用／比较／编辑”等实际目的地，动作仍使用现有来源引用和阅读／焦点恢复逻辑。来源失效保留说明，不显示能返回却落到其他对象的假入口。

规范分工：本 change 的“当前任务身份与返回目的地明确”定义呈现身份及返回文案；既有“双运行工作区保留比较对象和返回位置”定义比较选择与侧栏独立的状态规则，既有草稿／阅读条款定义恢复及失效保护。集成场景保留这几项的交叉核对，但不另建第二套返回或身份规则。“界面提供分支树与轨迹两种视图”的 requirement 标题只为 MODIFIED 锚定基线而保留，界面使用新文案，归档前不随文案重命名条款。

### D3：按任务提供空间，手动偏好保持

日常查看使用可调运行导航与概览／步骤／文件。编辑／实验／双运行比较进入主工作区，按任务和实际宽度施加临时导航覆盖；恢复入口始终存在。默认建议编辑与双运行比较优先正文，允许用户打开运行列表；离开任务解除临时覆盖，按当前空间恢复有效手动偏好。

既有专注模式单独保留，不能把任务默认适配等同用户已经进入专注，也不能复制一份草稿或布局库。容器变化不重建目标身份；适配叠加顺序和恢复由首组布局状态表明确。固定保留列表方案可以比较，但在窄窗必须继续服从可读空间及现有自动适配要求。

### D4：清洁编辑会话与修改草稿分开

复用 deriveDraftList 及 dirty 判据，入口主计数只表示未提交修改；列表区分“未提交修改”和“未修改的编辑会话”，先列需要处理的内容，完整会话条目仍可找回。未修改条目不增加警告或关闭保护；dirty、提交冻结、来源失效按已有事实分别表达。

不因为隐藏或移动条目删除 clean 记录；清空内容依字段基线判断是否 dirty，改回基线只恢复 clean，修订递增规则不变。录制草稿也使用其现有独立判据，活动摘要必须避免漏计录制未应用修改；设置模态的未保存字段继续由原机制保护。

### D5：初始引导、字段校验和执行确认分层

初始空表单以填写说明和下一步缺项引导，不直接铺满红色必填错误。字段交互后或用户尝试核对时就近显示输入问题；加载、来源、凭据、权限、主进程状态等真实异常即时可见，不能等待字段 touched。

有效性和执行资格继续来自现有校验，不新增“看起来可运行”的独立判据。确认块呈现一份当前目标、修改／计划、费用及副作用摘要，技术细节按需展开。A/B 计划、隔离预检、messages 凭据版本与每次授权继续按各入口契约获取并失效；初始减少提示不放开按钮或缩减正式核对。

说明去重遵循既有“工作区说明分层去重且异常不隐藏”；确认摘要和许可绑定遵循既有“核对与提交相邻且绑定纪律不变”。本 change 新增的是初始字段提示时机及其与即时异常的区分，集成场景只核对原有保障不被该变化绕过。

### D6：以完整路径验收

首组原型使用已有公开／脱敏 fixture 复现找错误、看文件、改后返回、比较和导出入口路径；先无模型请求地验证结构与状态，再按既有测试及实机 harness 覆盖真实执行反馈。实机数据不能为截图清爽而直接改 store 或伪造 operation。

使用 1440／1210／1024／800 CSS px 与独立 200% 缩放、纯键盘、长中文／日文／非法 JSON，覆盖后台完成、来源失效和迟到响应。既有主体高度、Monaco 离线挂载、光标／滚动及只读要求保留。任务计时如有记录，注明工具辅助、维护者熟悉度和资料条件，不据此宣称用户效率提升。

## Risks / Trade-offs

- 多套来源在共享标题中被错误统一 → 按工作区身份派生，并验证侧栏 A、编辑 B、比较 C/D 同时存在的状态。
- 默认收起与专注／手动偏好相互覆盖 → 首先建立进入、打开导航、改宽度、退出和窄窗回退状态表，复用既有布局机制。
- clean 条目分组造成输入找不到或 dirty 漏计 → 使用既有派生判据，覆盖改回基线、空输入、录制修改和失效来源。
- 初始提示变轻后隐藏真实异常 → 字段提示与外部／来源状态分离，前置拒绝和正式提交校验继续验证。
- 活动区新增占高或窄窗换行挤压正文 → 实测容器及键盘焦点，保留正文约束，必要时回到顶栏分组。

## Migration Plan

1. 完成身份／入口／布局状态表及同任务原型，记录推荐方案和受影响条款。
2. 先接共享外壳与对象标题，再整理列表、草稿和表单，逐单元验证并提交。
3. 对全部 delta 场景及相关既有场景建立证据索引，完成质量门禁，归档时核对既有条款／场景无遗漏。
4. 不修改数据格式，无持久数据迁移。回退可以按已提交单元恢复 UI，原 trace 与附件不需转换。
5. 归档后单独安排新版候选包、ZIP／哈希说明、portable 完整案例验收和第二轮材料；版本号、发布和实际宣发状态分别记录。
