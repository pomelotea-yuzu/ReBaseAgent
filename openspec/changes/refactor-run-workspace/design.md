# U1 设计：运行工作区与概览

## Context

问题与改造前证据见 [proposal](proposal.md)。本设计基于 2026-09-21 的已归档基线：

| 现有实现 | 约束与复用点 |
|---|---|
| App 固定挂载 RunList、SpanTree、DetailPanel | 文件页在 DetailPanel 内切换，外侧步骤目录仍占宽；将页签承载上移至运行工作区 |
| store 只有单份 selectedSpanId/expandedSteps | selectRun 清空选择，且请求无归属检查；增加按运行的阅读位置与详情请求序号 |
| RunSummary | 已有 task/model/reason/source/fork/自有指标，不为列表逐个读取详情 |
| RunDetail | 已有自有 events、合并 spans、leafSpanIds、chain；复用版本守卫先于 zod 的校验顺序 |
| shared/derive | buildSpanTree、deriveRunSummary、deriveCacheHitTotal、deriveMissingLlmErrorDetail 已有纯函数语义 |
| DetailPanel | 集中承载预算、隔离/来源说明及各种编辑器；拆阅读承载时保留其执行参数和能力 guard |
| WorkspaceFileView / BranchTree / ComparePanel | 已有文件读取与四条指标能力，U1 只调整承载和共用状态文字/颜色 |

## Goals / Non-Goals

阅读状态、原始数据和派生结果职责分开：store 保存原始响应及会话导航，纯函数计算概览，不把汇总复制到第二套可变缓存。工作区义务由本 change 的 desktop-ui delta 约束；节点状态文字/颜色同时在 branch-tree delta 明确，不修改底层状态枚举。

本轮不迁移持久数据、不添加 IPC，不借此建立通用路由框架或表单引擎。阅读恢复不保存输入、授权、密钥或执行状态；U2/U3/U4 后续分别拥有文件阅读、草稿和操作登记。

## Decisions

### D1. 由工作区拥有页签和运行身份

保留 App 的运行/分支视图区分，引入轻量 RunWorkspace 与 RunOverview。工作区页头展示 task、状态、来源与运行级操作，正文按 overview/steps/files 挂载；文件模式不挂 SpanTree。选择首次访问的运行时落到概览，进入步骤页才选择调用。预算地图保留现有整段轨迹的计算口径，在步骤页按需展开，点击点使用同一调用定位动作；不能为“放入模型详情”而只统计一个调用。

布局结构如下，仅为结构图，不是已验收原型：

```text
全局栏：ReBaseAgent | 新建运行 | 录制接入/状态 | 设置
运行导航             主工作区
搜索/来源/刷新        任务、状态、来源与现有运行级操作
任务/模型/短 ID       概览 | 步骤 | 文件（按能力）
运行列表              概览：结果/错误 -> 来源 -> 本次消耗
                      步骤：可收起目录 + 完整调用详情
                      文件：现有 WorkspaceFileView 占整个正文区
```

全局新建与列表标题区原入口共用一个 CreateRunDialog 实例的打开状态，收起列表后仍能创建。设置和录制打开现有设置弹层，录制入口允许用初始区域参数定位代理设置。prompt/A-B 入口移到稳定的运行级操作区，工具结果/messages 编辑仍靠近对应详情；现有能力判定不变。

分支树保留 header 入口和全宽承载，节点仍只改变共享选中 run；“返回运行”显示该 run 的已保存页签或首次概览。保留旧 ComparePanel 的最多四条指标能力，不在 U1 声称修复四列宽度。概览的父运行入口只打开父运行，不冒充双运行比较。

备选为继续在 DetailPanel 内嵌页签，但其无法卸下无关步骤目录，并继续让组件挂载控制页面状态，因此采用上述上移方案。

### D2. 导航宽度取决于实际可用空间

运行导航默认 264px，可调整 220–360px；步骤目录默认 232px，可调整 200–320px。拖动和键盘调整均夹到合法范围，正文不足时优先收起辅助区域。用户设置的宽度/折叠偏好仅存本会话，自动折叠另行计算，不覆盖宽窗口偏好；本次不引入本地持久化。

下表断点使用整个应用内容视口的 CSS 宽度（`document.documentElement.clientWidth`），不使用含边框的原生窗口宽度，也不使用扣除运行导航后的主工作区宽度。正文至少 480px 的二次约束则测量实际详情容器。验收矩阵的 1440/1360/1024/800 和“640px 内容宽度”均指应用内容视口在 100% 缩放时的 CSS 尺寸；640px 对应下表 <720px 档。200% 缩放为独立用例，记录缩放后的实测视口再判断断点，不能按原生窗口标称尺寸推断。

| CSS 可用宽度 | U1 外壳规则 |
|---|---|
| >=1280px | 导航可常驻，步骤目录需保证详情至少 480px，否则收起 |
| 960–1279px | 概览保留导航；进入文件页或现有编辑态暂时收起运行导航；步骤目录仍受 480px 约束 |
| 720–959px | 运行导航与步骤目录按需打开，正文单列 |
| <720px | 单工作区；辅助列表替换正文区域，明确返回当前运行/调用；工具栏换行 |

临时辅助面板使用替换区域而非叠加模态，关闭或选择后恢复正文焦点；同一时刻只打开一个辅助列表。改变窗口和 200% 缩放使用实际 CSS 内容宽度计算，不改变字号。正文 14px、代码 13px、辅助信息 12px、标题 18px，字距 0；全局栏可换行，局部代码/图表可滚动，页面不横向滚动。

文件内部继续使用 C 的断点和 diff 模式；U1 只证明外壳没有额外步骤列且主区可达，不用外壳截图宣布 U2 的正文宽度验收通过。主要控件使用现有 React/Tailwind，新增 lucide-react 图标配名称、tooltip 和焦点态；不使用新的面板或 UI 框架。

### D3. 列表直接消费现有摘要

搜索匹配完整 task/id（大小写不敏感，不修改原值），与 all/proxy/local 来源过滤求交集。展示术语使用“代理录制 / 本地记录”，不推断非代理是桌面或 SDK。task 展示折叠空白、最多两行；空任务回退为来源、时间和短 ID。模型使用记录值，换行并可展开完整值，空值显示未记录，不借用当前配置。

短 ID 从完整 ID 末尾 8 字符开始，在全部已加载记录中按需逐字符延长，必要时用完整 ID；一个 ID 为另一个 ID 的后缀时，较长者继续延长。输入按完整 ID 排序计算，结果不依赖列表排序或筛选。会话中已扩展的长度不因刷新删除碰撞项而缩短；新出现碰撞时只延长相关项。存的是界面标识长度，不是运行聚合。全文复制始终使用完整 ID。

紧凑条目优先 task/model/status/短 ID/时间/来源；既有 steps/tools/errors/token/duration/cache 不删除，可通过条目摘要展开访问，token 与已记录缓存命中保持同行。未知耗时不补零，部分缓存字段的列表值只称“已记录命中量”，不声称全运行命中率。

列表刷新在首次加载、手动刷新和现有执行收尾调用时发生。loadRuns 合并在途请求；若执行收尾发生在更早的列表请求期间，标记一次尾随刷新，确保新记录不会被吞掉，不启动轮询。刷新期间保留旧列表，失败保留旧列表和持续的未更新提示；首次失败独立重试。筛选隐藏选中项时正文不变，提示可清除条件。

首次成功列表加载无选择时只尝试最新可读摘要对应的运行；详情失败留在该项，允许用户选择下一条，不自动循环探测。刷新发现当前记录移入 failed 或消失时，标记已加载内容为源记录不可用并禁用依赖其执行的入口，详情重新读取通过才恢复。这里不新增 main 端执行保证，main 原有严格校验保持。

### D4. 结局、输出与错误均从自有记录派生

共享状态分类供列表、概览和已有树节点使用。列表以 status/reason，详情以自己的 status/events 派生；存储 status=completed 不能单独代表正常完成。

branch-tree delta 仅修改节点状态展示契约，保留该 requirement 的四个原场景并新增结局细分、中断/未知和工具错误恢复场景。节点消费已有 RunSummary，不增加 IPC、详情补读或新的 status 枚举。该 requirement 的边标注、点击及祖先高亮原文在 U1 保留，来源链术语、节点布局/聚焦和比较继续由 U7 顺序修订；U7 必须基于 U1 归档后的主 spec 起草。

| 记录事实 | 展示与颜色 |
|---|---|
| 无终止事件 / crashed | 运行中断，中性色；不推断仍在执行 |
| reason=completed | 已结束，正常色；不写测试通过/修复成功 |
| reason=error | 出错终止，红色 |
| max_iterations / budget_exceeded | 达到迭代上限 / 超出预算，琥珀色 |
| aborted | 已中止，中性色及独立文字 |
| 摘要出现未知或缺失 reason | 结束原因未知，保留原始值，中性色 |

详情 RunEventSchema 目前枚举 reason，非法/未知详情仍严格拒绝；上述摘要兜底不构成放宽 schema 的理由。终止 event 与 reason 相矛盾的合法结构也不包装成正常完成，显示记录不一致及原值。

先用 leafSpanIds 过滤得到 ownSpans，再派生本次输出、错误和消耗。正常 completed 的最后一条自有 llm.call 若无 error 且有非空 content、无待执行 tool_calls，则把其正文作为已记录最终输出；否则显示“未记录最终输出”。其余终止状态不把最后非空正文升级为最终输出：完整保留最近自有正文，并标为中止/失败/限制前输出；正常结束最后调用无正文时，较早正文同样只能作为中间输出。仅有 reasoning/tool_calls 分别说明并可打开调用。没有自有调用时不借祖先输出填空，不自动总结。

错误定位列出自有 llm.call.error（存在性判定）及 tool.invoke.error（非 null）的真实记录；优先展示已记录的 LLM 失败入口，工具错误单独计数与定位，不断言其为终止根因。error 终止且没有 LLM 错误详情时继续显示已有缺失提示，包括仅有工具错误的情况；不将末尾调用或祖先错误编为失败位置。点击定位同时选择 steps、展开父 step、选中 span，并在渲染后滚动和聚焦；目标不存在则提示失效，不跳到另一个同名调用。

### D5. 指标沿用自有口径，来源不伪装执行前缀

概览用 ownSpans 调用现有汇总派生，默认展示输入/输出 token、已记录调用时间跨度、工具调用/错误及缓存；从详情现算，不依赖列表是否包含选中运行。缺失 timing 保持未知或标为已记录区间，不把活动等待时间计作运行耗时。失败调用占位 usage=0 的原始值保留并附说明，不声称实际零消费。

缓存额外从 ownSpans 派生“带 cache_hit 的调用数 / 自有 LLM 调用数”。0 为有值、缺失为未知；部分记录称“已记录调用的命中量”，概览不生成整次确定命中率。调用详情保留 cache_hit/in、cache_miss 和既有模型变化提示。

来源区显示直接父 ID、真实 fork 字段与隔离说明，可跳到父记录。result 分支保留既有共享前缀说明；prompt/messages/model_params 使用独立执行/来源链术语，不能说共享执行前缀。本次不重复实现沿链累计算法：已有树/指标面板保留 deriveChainTotals 等事实与措辞，概览只显示本次新增消耗及其口径，不自动加总成总成本。隔离文件入口按有效 meta.workspace 能力出现，附件不可用时入口仍存在并由 C 说明原因。

### D6. 会话阅读位置与请求归属

store 增加以 run ID 为键的阅读状态，保留现有 selectedRunId 作为唯一当前运行：

```text
readingByRun[runId]
  tab: overview | steps | files
  selectedSpanId
  expandedSteps
  overviewScrollTop / stepTreeScrollTop
  detailReadingBySpan[spanId]: scrollTop / expandedSections / inputOutputTab
layout: 用户宽度与折叠偏好 / 当前临时面板
navigation: 运行或分支视图 / 来源返回位置
```

搜索条件和列表滚动为会话级，不混入每运行位置。存储界面位置而非 React 节点、原始消息副本或业务汇总。详情展开项用稳定字段键，消息项用当前不可变记录内的序号。LongText 的展开状态改为可受控；各阅读器在卸载前保存位置，重新装载内容后恢复并限制到合法滚动范围。文件内部位置暂不存入该模型。

优先级为明确目标 > 已校验恢复值 > 默认值。首次概览；首次进入步骤选择首个自有 llm/tool 调用，若没有则首个可读 span；空记录显示空态。对象不存在时清除失效引用、提示并采用同一默认规则，files 不再适用时回到概览。同 run 切换多个 span 不互相覆盖展开/滚动；不同 run 的相同 span ID 完全隔离。

详情读取使用单调递增 requestId，并绑定 runId；成功、信封失败、版本失败、schema 失败、异常和 finally 都只有仍匹配当前请求才修改可见状态。同一 ID 的显式重试/重读也递增 requestId，不能仅比较 ID，从而覆盖 A→B→A 的旧 A 响应。旧响应直接忽略，本 change 不增详情缓存。切换时先显示属于新 run 的加载占位，不能把旧正文贴到新标题；失败显示原位可重试状态，不由 selectedRunId 相等而短路重试。

备选为每次挂载初始化组件状态，其不能满足跨运行恢复；全量详情常驻缓存又引入数据失效和内存问题。本设计只保存阅读偏好，详情按既有请求获取。

### D7. 阅读安全、测试与过渡验收

输出先使用 React 安全文本及代码区，不引入 Markdown 渲染依赖；保留空白和复制原文，不执行 HTML、不自动加载外链图片。完整 messages/tools/params/reasoning/tool_calls、工具 args/result/error 和预算可从对应详情访问。主区不会把设置中的当前模型当作历史调用的模型。

测试按风险分层：纯派生覆盖结局、输出选择、自有过滤、缓存和短 ID；store 覆盖异步乱序、重试、刷新合并与位置恢复；真实 Electron/CDP 覆盖布局、焦点、Monaco/预算懒加载和现有入口。复用已有普通、隔离、多工具/二次分叉、prompt、代理、实验、旧记录和坏数据 fixture，新增缺失的确定性数据。缺父链仅验证现有错误页，不把旧宽泛降级当作 U6 成果。

第 6 组的主动执行回归先完成任务 6.0：复用 `apps/desktop/scripts/mock-llm-server.cjs --port <空闲端口> --script <剧本.json> --log <请求.jsonl>`，其现有能力为 SSE 文本/工具响应及 FIFO 请求日志。逐入口核对 stream 模式，非流式 JSON、HTTP 失败和延迟若为用例所需则先补相应测试能力并做协议探针；不能将统一 SSE 响应当成全协议模拟。每条流程重置剧本/服务、使用测试配置并恢复原配置，日志只存受控测试数据；请求计数和预期调用顺序通过后再运行 6.4–6.6。

阅读冒烟前后核对 trace、既有附件与隔离源目录哈希；执行回归单独记录新 trace/附件及受控模型请求，不能混入“阅读零写入”的结果。各主动执行入口至少验证可达、原门禁和一次受控提交；未改造的草稿丢失/跨页结果跳转仍单独记录为 U3/U5 待办。禁止用旧成功截图代替新外壳回归。

原型和桌面矩阵包括 1440×900、1360×860、1024×768、800×600、640px 应用内容视口宽度及 Electron 200% 缩放；系统 DPI 缩放若未实测须注明。原型先核对概览、错误跳转、步骤目录与文件承载区，实施后再用真实数据重复。证据索引逐 scenario 记录测试/截图/哈希和未验事项；每份布局证据同时记录原生窗口边界（含单位）、应用 CSS 视口、实际工作区/详情宽度、Electron zoomFactor、devicePixelRatio 和 D2 对应断点。CSS 视口为 640px 应对应 <720px 档；仅某局部正文为 640px 不能算作该极窄场景通过。

## Risks / Trade-offs

- DetailPanel 同时拥有阅读和执行表单，拆分可能卸载编辑器或丢入口 → 只迁承载与阅读状态，逐入口回归；不在 U1 宣称草稿保护。
- 运行/步骤/文件同时争夺宽度 → 文件页彻底卸下步骤目录；目录收起依据实际正文空间；文件内部问题留 U2 明确验收。
- 摘要与详情表示不同数据范围 → 状态读取自有事件，指标过滤 leafSpanIds；不沿合并轨迹计本次消耗。
- 会话状态随访问增长 → 仅存小型阅读位置，不存内容副本；刷新成功后清理已确认消失且非当前运行的位置，失效 span 在重读时清理。
- 既有主 spec 中“format_version=2 为未来版本”的旧场景与 A3 基线不一致 → 本次使用实际不支持版本 fixture，并以 A3 已归档 v1/v2 守卫验收；不顺便改写无关 requirement。
- 文档外观可正确而真实 Electron 缩放失败 → 任务保留真实截图与几何检查，缺环境时不得勾选通过。

## Migration Plan

1. 先固定 fixture 与关键布局原型，再实现纯派生和导航状态；不变更 trace/IPC。
2. 接入运行工作区、列表和概览，搬移步骤/文件承载，逐项保留原入口。
3. 完成单元、store、桌面回归、质量门禁和 desktop build，逐场景补证据。
4. U1 验收并归档后，U2 从主工作区文件承载继续，U3 从会话状态边界扩展草稿；后续 delta 基于更新后的主 spec 编写。

无数据迁移。若实施需回退，仅回退界面与依赖改动，记录和附件无需转换；本 change 不安排发布或自动归档。
