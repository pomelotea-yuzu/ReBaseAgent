# U2 文件阅读设计

## Context

依赖已完成、未归档的 [U1](../refactor-run-workspace/proposal.md) 和已归档 A3-C。App 已按页签挂载 WorkspaceFilesPanel，后者用 run ID 作为 WorkspaceFileView 的 key；保持卸载策略即可，恢复不能依赖组件常驻。U1 的 `readingByRun` 已保存页签/步骤位置，文件内部状态尚在局部组件。

C 的 `workspaces:inspect` 与 `workspaces:readFile` 已区分清单、UTF-8 文本、binary/not_found/missing/corrupt/rejected；无需扩展 IPC。当前初始侧将失败信封折成 null，加载与“不存在”混用；当前侧虽有内容 key，错误和 finally 的 loading 清理仍需同等请求保护。这里只依据源码提出修改，不把静态检查当作现有 GUI 缺陷的实测结论。

## Goals / Non-goals

目标是完整可读、往返恢复、状态真实，并保留 C 的引用读取与只读边界。范围与 proposal 一致；不增加文件写入、跨运行文件比较、缺父链兜底、草稿或执行协议。

## Decisions

### D1. 文件阅读状态扩展 U1 会话模型

在 `RunReadingState` 中增加可选 `files` 子结构，缺省表示尚未进入文件页；使用稳定默认引用及不可变 patch，避免 zustand selector 每次产生新对象。仅保存以下阅读信息：

| 状态 | 作用域与规则 |
|---|---|
| checkpoint | 按 run 保存 stepSpanId，null 明确代表初始，不能同时代表未初始化 |
| path、pane | 按 run 保存最后完整逻辑路径与 list/content 意图，不按 basename 匹配 |
| query、filter | 路径搜索词；筛选偏好 auto/all/changed，auto 在初始取 all、完成步骤取 changed |
| directoryWidth、directoryCollapsed | 每运行目录首选宽度与用户收起意图，自动布局不能覆盖 |
| diffPreference、wordWrap | auto/inline/sideBySide，默认 auto；换行默认开启 |
| listScrollTop、contentScroll | 列表位置按检查点保存；正文按 run/step/path/侧记录行列锚点与滚动偏移 |

不保存文件正文、清单、哈希派生统计、Monaco 实例/模型、草稿、授权、凭据或物理路径。Monaco view state 如使用，须提取阅读定位字段，不把其模型/装饰对象存入 store。滚动监听可节流，但切页、切运行和卸载前须提交最后位置；内容与布局准备好后恢复并夹取合法范围，不在每次 render 重置滚动。

重新挂载先拿会话选择，再 inspect，再按合法 path 读取两侧。Monaco 切 inline/并排或宽度变化时，优先恢复可见行锚点，再恢复适用的侧偏移。重载/重启从默认策略开始，持久事实仍由 IPC 重新读。

### D2. 检查点优先级与定位入口

`deriveCheckpointOptions` 复用当前详情的 `leafSpanIds` 与 `agent.step.n`，只列当前 run 已记录的自有完成步骤，不根据运行整体 completed 与否隐藏已有步骤。快照未录制的合法旧记录保留明确不可用结果，不伪造清单。最近步骤按当前 run 本地 n 选，不按合并 spans 下标或祖先轮号选。

优先级为一次性显式目标 > 有效会话选择 > 最近自有完成步骤 > 初始状态。在 U1 的 `ReadingTarget` 上增加文件专用分支 `{ tab: "files", file: { stepSpanId: string | null, path?: string } }`，外层 runId 使用既有 selectRun 身份。`file.stepSpanId` 只指自有 agent.step，null 明确指初始；既有调用定位的 `spanId` 与 `expandStepId` 保持原语义，文件分支在类型上禁止混传这两个字段，解析器按 file 的存在区分明确文件目标。仅有 `{ tab: "files" }` 是普通返回，不覆盖历史；不要求将所有既有导航入口迁移成新的 kind 协议。

自有步骤的文件入口提供明确轮末定位；对工具调用入口须先解析所属自有 step，不假定工具中间态。祖先步骤不提供冒充当前运行检查点的入口。概览已有文件入口沿用通用打开，只有真实指定检查点时才附目标。

目标随一次导航请求消费；同一 run 再定位同一目标仍生效。显式目标未指定 path 时清空旧文件选择并显示列表，指定合法 path 则显示内容、清空阻挡它的搜索并切 all。不能根据 source 路径或文本猜文件。异步消费目标受 run 与导航代次约束，旧目标不能抢回当前页。

保存的 step 不再属于该 run 时，清理 step/path/对应滚动并提示，回到上述默认检查点；新检查点仍须 inspect，读取失败展示失败而不静默换另一个“可读”检查点。path 在完整清单中存在则保留，即使附件不可用；不存在则提示、清空选择、显示列表，不选择另一同名路径。清单读取失败不能当作 path 已消失，保留选择意图以便重试。文件能力消失按 U1 回到概览；缺父链造成详情失败继续沿用现有错误，等待 U6。

### D3. 搜索、筛选与目录

只在 inspect 返回的完整逻辑路径上做不区分大小写的子串搜索，不改写 path 大小写或路径分隔形式用于请求。“有变化”只认 added/modified；missing/corrupt 独立显示，不能算作删除或修改。初始视图 auto 筛选为全部，完成步骤为有变化；用户明确选择 all/changed 后会话内保留，允许重置到默认。

依次区分：清单读取错误、合法零文件、完整清单有文件但无变化、搜索无匹配。无变化提供切全部；搜索无匹配提供清空搜索。文件数量/总字节/不可用数取当前 inspect，筛选计数单独标明，不把筛选结果当原清单规模。清单的 availability=ok 不保证 UTF-8，只有 readFile 的 binary 结果决定二进制标签。

筛选/搜索隐藏当前 path 时不丢其阅读状态或偷换内容；内容标题保留完整路径并提示被筛选隐藏，提供显示所选文件（清空 query、切 all）。长路径可换行或截断目录部分，但文件名及完整路径访问/复制始终可用。

### D4. 容器布局与正文宽度

使用文件页内部 ResizeObserver 测量宽度，不能用 window.innerWidth 或 Tailwind `lg` 决定目录/diff。布局先计算目录能否常驻，再根据实际编辑器正文宽度选择 diff；U1 外层导航仍使用既有折叠规则。

初始设计值：目录 232px，可拖动 200–320px。**正文宽度下限按容器宽分档**：容器宽足够（对应 960 CSS px 及以上视口）时，只有扣除目录、间距、内边距后 inline 的实际文字区域仍至少 480 CSS px 才常驻目录；否则目录与内容占同一主区域，保留切换入口。宽度足够时可主动收起目录。内容视图中不能为了保留目录而把正文挤成窄条；列表/内容意图与自动布局状态分开存储。

默认 auto：在目录决策后，Monaco 两侧各自实际文字区域均至少 320 CSS px 才并排，否则 inline。用户选并排但空间不足时自动 inline，控件说明空间不足，恢复宽度后恢复偏好；用户选 inline 则宽屏也不强制并排。计算须考虑行号/glyph margin/滚动条及内边距，最终以 Monaco 布局信息和实机测量确认，不把宿主盒子一半视为文字区。

目录常驻与并排是两个独立条件，不要求同时满足。原型须记录这两次决策所用的实际文字区尺寸。

**分档依据（2026-09-23 真 Monaco 0.56 实测，见 `docs/reviews/2026-09-23-u2-file-prototype/README.md`）**：inline 文字区随视口收缩，**「≥480px」的几何临界视口为 960px**（960px 及以上达标；960→720px 一路从 392 掉到 193，无一档达 480）。故 480px 下限**只对 960 CSS px 及以上视口成立**；**800px 及更低为窄档**：正文按可得主区自适应，不声称 480px，目录一律收起、diff 强制 inline，允许 inline 局部滚动。这是承认几何现实，不是降低验收。

极窄时目录和内容单独占可用区；窄档（800px 及更低视口，及 200% 缩放等可用空间不足的情况）不要求 inline 文字区达到 480px，允许工具栏换行和局部编辑器滚动，不造成整页横向滚动。默认字体复用 U1 阅读 token，代码正文至少 13px，不通过缩字号达标。编辑器 flex 填充剩余高度，页头/工具栏可换行，不锁死 420px。

这些尺寸以原型和桌面实测为准（1.2 已产出权威数字，5.1/5.2 实机复核）；若无法满足，先修设计再实施，不通过降低正文要求掩盖问题。

### D5. 两侧独立读取、比较资格与竞态

每次清单请求带 run/step 和递增 generation；每次内容请求带 run/step/path/side 和 generation。success、业务失败、抛出的异常及 finally 全部核对身份与代次。重新选择同一对象 A→B→A 或同对象连续重试也须区分，不能只比较文本 key。卸载失效请求不写入状态，旧清单不可按新检查点标题渲染，旧错误也不能清除新 loading。

两侧分别使用 idle/loading/ready/error 状态，ready 内保留完整 readFile 判别联合。两侧独立请求与展示，不能以当前侧成功为读取初始侧的条件；初始与初始相同时可复用本次读取。null 只表示尚未取得结果，绝不代表不存在；失败信封/异常保留为 error。局部重试重新调用只读接口，不用旧成功正文冒充已通过重新校验。

| 初始侧 / 所选侧 | 展示 |
|---|---|
| text / text | 完整只读 diff；相同初始选择可展示单份原文，保留基线说明 |
| 经校验 not_found / text | 新增文件；明确初始不存在后可用空左侧渲染 diff |
| text 空串且 bytes=0 | 标明 0 B 空文件，是有效文本，不等于不存在 |
| 任一侧 loading/error/rejected/missing/corrupt/binary | 双侧各标状态；另一侧 text 仍可独立阅读/复制，禁止把不可用侧置空比较 |
| 两侧均不可读或均不存在 | 显示各自事实，不挂伪空编辑器 |

not_found 只能来自成功读取结果，不从超时、缺 blob 或 JS null 推断。非法或越权请求继续拒绝，不扩大“新增文件”例外。内容比较只涉及同一 run 的初始与自有步骤，绝不把两个运行的初始差异拼成跨运行 diff。

### D6. 阅读工具与键盘

复用离线懒加载 Monaco 和现有 Lucide 图标，不新增编辑器/图标依赖。工具栏包括完整逻辑路径复制、各可读侧完整原文复制、当前活动可读侧查找、换行开关、上一/下一差异、inline/并排模式及返回目录；元信息可复制真实大小/完整哈希。原文复制只取已读取 text，不受折叠、搜索、高亮、换行和虚拟滚动影响；剪贴板失败就近显示，不假报成功。

编辑器未就绪、无可读侧、不可比较或无差异时，相应操作禁用并有可访问说明；查找只在读取完成的活动侧执行。差异导航等待 Monaco diff 计算完成，用当前安装版本的公开 API/动作，实施前核对类型声明，不引入私有 DOM 操作。readOnly 与 originalEditable=false 保持，查找不暴露替换/写入。

控件使用图标/分段模式/开关及可访问名称、tooltip、焦点环；模式和禁用状态不能只靠颜色。目录切换、宽度调整和选择支持键盘；返回列表聚焦原文件或有效列表项，关闭查找返回编辑器。视口变化不主动抢焦点，必要时从被隐藏的控件移至对应切换入口。局部错误持续可见，普通复制反馈可消失。

### D7. 验收和变更衔接

复用 C、U1 真实引擎隔离根/子/二次分叉 fixture，并补独立受控副本：零文件、无变化、新增、零字节、二进制、左右分别缺失/损坏、缺检查点、失败运行已有检查点、长路径/多文件/长正文。破坏性 fixture 仅改专用测试副本，不改既有附件。测试源/父/兄弟/既有 trace 与附件均逐文件记录前后 SHA-256，阅读期模型请求计数和工具执行计数为零。

纯函数测试验证默认/优先级、筛选和比较资格；延迟 promise 测试覆盖清单/两侧的迟到成功、失败、异常、finally、同对象重试。store 测试覆盖逐 run/step/path 隔离与卸载前保存；真实 Electron 负责 Monaco 命令、滚动恢复、键盘与布局，静态 renderToStaticMarkup 不替代交互证据。

evidence-index 分别列出 U1“快速切换及同运行重试不串响应”（详情请求回归）、U2“快速切换不串清单正文错误和加载”（清单与双侧请求）、U2“同对象重试与往返有请求代次”（同 key 不同代次）。可共用测试文件，但每项须链接对应的具体断言或实机步骤，不能用 U1 详情竞态证据代替 U2 文件竞态验收。

桌面矩阵为 1440×900、1360×860、1210px 宽、1024×768、800×600、640px 宽的 CSS 视口，另设真实 Electron zoomFactor=2。每项记录原生窗口单位、CSS viewport、文件容器、目录、Monaco 两侧文字区、zoomFactor/devicePixelRatio、短句可读性、长路径/工具栏溢出和截图。改变外层导航宽度但保持 viewport 不变，验证依赖容器而非窗口断点。

往返矩阵：文件→步骤→文件、运行 A→B→A、分支/设置返回；显式定位覆盖历史、路径失效/检查点失效、搜索隐藏选择；重启/数据目录整体迁移读真实附件（不要求恢复偏好），断网确认 Monaco 本地加载。普通记录及现有编辑/执行入口仍可达，不以本 change 宣称 U3–U8 通过。

U1 先归档，U2 再归档；合并时保留 U1 全部场景和本次 C 的原场景，文件专属新 requirement 定义后续增强。无存储迁移，回退仅影响阅读体验与会话状态。实现/原型若改变上述决策，先更新四件套，再继续；最终建立逐场景 evidence-index，未实测项留待办。

## Risks / Trade-offs

- 目录/Monaco 的可用宽度不同于宿主宽度，ResizeObserver 与 Monaco layout 应避免反馈抖动；相同决策不重复写 store。
- 大文件完整原文仍按 C 全量读取；本次不引入截断或持久缓存。滚动只存小型位置数据，组件销毁时释放编辑器与监听。
- U1 仍活动，主 spec 不是完整实现基线；实施必须同时读取 U1 delta 与当前源码，不能根据旧主 spec 恢复三栏。

## Open Questions

无阻塞性产品问题。具体 Monaco API 与宽度测量由任务 1.2 核实，形成原型记录后再落组件；尺寸调整必须同步 design/spec/tasks 的验收口径。
