# 修复代理录制与重发可靠性

## Why

外部应用已成功经过代理并写入 trace，桌面列表却不更新；main 已捕获凭据，重发编辑器仍按旧缓存禁用。用户必须到录制页手动刷新或重读，容易误判录制失败。代理上游 401/5xx 只落 meta 和终止事件，没有可读诊断；这一点是现行 llm-proxy spec 的明确行为，需要修订契约。

来源为 `D:/ReBaseAgentVideo/ReBaseAgent-实测反馈-2026-10-05.md` 第一节及本仓库源码核对。2026-10-06 实机检查见 `docs/reviews/2026-10-06-ui-density-review.md`。启动恢复已存在于 ProxyManager.autoStart，不作为缺失功能重写；当前缺口是失败被吞掉及 renderer 首次读取与恢复完成的竞争。编辑器 0 高只在原反馈的自动化路径出现，本次正常浏览未复现，须先定位可见宿主再修。

## What Changes

- 成功落盘、凭据捕获及监听状态变化通知 renderer，触发合并后的只读刷新；外部录制在 main 空闲时也能可见。
- messages 工作区打开/返回时回读真实代理状态，隔离迟到响应；凭据更换使旧执行确认失效，不泄露 key。
- 启动按保存的 enabled 恢复监听；区分恢复中、已监听、停止与失败，端口占用等失败有就近诊断和显式重试。
- 新的 HTTP/连接失败录制带失败 llm.call，复用既有 `error.message/status`。响应占位明确非实测消耗，详情概览可读可定位；历史文件保持原样。
- 明确已封存的失败代理 run 在保留完整自有请求时，可修改 messages 并独立确认重发，使用当前会话凭据并产生新子 run；未修改仍拒绝，不提供原样一键重试。
- 对编辑器塌缩建立可见宿主复现与恢复契约；修复只针对已定位原因，并保留草稿、模型及阅读位置。

## Capabilities

### New Capabilities

无新 capability 目录。

### Modified Capabilities

- `llm-proxy`：修改失败请求录制与单请求分叉规则，显式允许合法失败父本编辑重发，增加代理变化通知、启动恢复与诊断约束。
- `desktop-ui`：增加被动录制自动刷新、当前代理事实门禁、顶栏/录制页恢复结果呈现、失败概览及可见编辑器恢复要求。

## Impact

影响 `packages/llm-proxy/src/{handler,types}`、desktop 的 ProxyManager/ProxyRunRecorder、main/preload/shared IPC、store 与 messages/录制/失败概览消费。复用已有诊断脱敏规则及 trace-sdk 的 LlmCallErrorSchema，不增加第三方依赖或 trace 版本，不改历史 JSONL。main 空闲时的被动录制通知独立于主动 operations 轮询，不扩大执行槽语义。

## Non-goals

- 不做折叠按钮、说明去重、专注编辑、一般编辑区空间及模态视觉改版；这些归 `improve-workspace-reading-and-editing`。
- 不增加代理协议支持、任意外部 CLI 适配、取消/队列、跨 main 重启任务恢复或持久凭据。
- 不补写历史错误详情、不用模型设置 key 替代代理 key，不让刷新/恢复触发测试模型请求。
- 不把比较页旁白、问号字体猜测、最近目录、容量角标、中断 run 重新发起或缓存计数异常一起实现。
- 不在起草阶段修改实现、归档、打包或发布。

## 保真度与执行边界

被动录制仍是一外部请求一 run，响应状态/允许转发头/body 沿既有透明转发规则原样送给客户端；诊断只是脱敏摘要，不改客户端错误体。messages 重发仍是修改 messages 后发一个真实模型请求，沿用原 model/tools/params，使用当前会话最近捕获凭据，不执行外部工具、不恢复消息前缀或文件世界。通知、回读、重试读取和编辑器恢复均不消费授权、不产生模型/工具调用。父本、兄弟 trace 与文件快照不变。

## 验收口径

外部受控请求成功后无需手动刷新即可看到 run 并读取当前 hasKey；空闲 main、页面往返、并发录制、迟到回读均覆盖。重启成功/端口占用分别有真实监听证据，key 重启失效。HTTP 401/503 和网络失败有可读受控诊断，客户端字节保真、已知凭据不落盘；老失败文件诚实降级。失败父本修改后重发成功/再次失败、未修改拒绝、历史无调用/未封存拒绝及父本指纹均覆盖。编辑器以真实窗口切换验证可见宿主几何、可输入及草稿保留，CDP 仿真异常单独归因。详见 tasks 与 evidence-index，草案不代表通过。
