# A3-A：隔离文件执行内核

## Why

现有重跑在分叉点之后已经会真实执行工具，但桌面 `write_file` 的落点是应用数据目录，没有历史文件状态，也没有分支间的文件隔离。A3 要让用户从已录制的文件检查点继续执行真实读写，比较不同分支的结果，同时保证原工作目录、父分支和兄弟分支不被本次写入改变。

## Goal

通过包 API 创建带文件检查点的父运行，并从整轮历史状态隔离续跑，以集成测试证明文件状态恢复和分支不变性。

## Dependencies

本 change 是 A3 的 A 段，无 B/C 前置依赖。后续按 `add-sandboxed-rerun` → `add-sandboxed-rerun-desktop` → `add-sandboxed-rerun-file-view` 实施并归档。A 不包含桌面新入口或文件视图；已完成的版本兼容修正保留。

## What Changes

- **首期限定受控文件世界**：提供固定版本的 `read_file` / `write_file` 工具组，操作应用管理的文件快照和分支写时复制映射。采用 Node 标准库实现的内容寻址 blob 存储，不依赖 Docker、系统 overlayfs、管理员权限或新增第三方依赖。它是应用层文件隔离，不是任意代码的操作系统沙箱。
- **提供能产出检查点的父 run**：由 `replay` 包导出 `createIsolatedRun`，调用方显式传入源目录、dataDir 和本次副本写入授权；导入全部受支持普通文件后，模型与工具均基于副本执行。隔离编排不接受自定义 handler。
- **检查点对应整轮工具完成后的状态**：录制初始文件清单和每个 `agent.step` 完成后的文件快照。编辑某工具结果后，复用已有 messages 派生，从该工具所在轮次全部工具完成后的快照开始下一次模型调用；同轮其他工具不再执行。编辑的是模型观察到的结果，不撤销或重做被选中工具的历史文件写入。
- **分支文件写时复制**：父快照和文件内容不可变，子分支只创建新内容 blob 并更新自己的路径映射；读取先取本分支当前映射。任何写入都不会落到源目录，也不会调用现有桌面普通文件 handler。再次分叉使用直接父 run 自有步骤的检查点。
- **保留可核对的结果**：JSONL 内记录文件清单、内容哈希、检查点时点及父检查点来源；文件字节作为内容寻址附件存于同一便携数据目录。包层提供按清单引用读取及校验附件的能力，区分文本、二进制、路径不存在、附件缺失和损坏；通过重新打开数据目录恢复解析与合法执行，不自动合并回原目录。文件视图由 C 交付。
- **明确兼容和拒绝路径**：没有检查点的旧 trace 不支持历史文件恢复，不能用当前磁盘目录冒充历史状态。隔离 run 不能经普通 `replayRun`、prompt fork 或模型 A/B 降级到普通 handler；这些入口明确拒绝，`allowSideEffects` 不能绕过。旧 run 的既有操作保持原契约。
- **BREAKING（仅新隔离产物）**：隔离 run 使用 trace `format_version: 2`，新读取器支持 v1/v2，普通 run 继续写 v1。旧应用必须拒绝 v2，而不能剔除隔离字段后把它当普通运行重跑。新增 `fork.resume_after_step` 区分编辑位置和整轮续跑边界，完整保留同轮兄弟工具的前缀。
- **校准文档**：实现时修订 README 中“默认不复执行任何工具”的旧描述，明确普通重跑、隔离文件重跑和 Trace-as-Test 卡带的不同保真度。

## Capabilities

### New Capabilities

- `workspace-isolation`：源目录导入、受控文件工具、不可变内容附件、轮次检查点、分支文件隔离、配额与损坏拒绝、只读附件读取与状态区分。

### Modified Capabilities

- `trace-format`：v1/v2 共存、隔离元数据、JSONL 内嵌快照清单、整轮续跑边界和附件缺失时的读取行为。
- `replay`：新增隔离根运行和隔离工具结果重跑编排，保持前缀零调用并将上下文与文件检查点对齐；普通入口拒绝隔离父本。
- `prompt-replay`：首期拒绝隔离父本，防止丢失隔离约束后真实执行。
- `model-experiments`：首期拒绝隔离父本，包括 dry-run 和显式 `allowSideEffects`；多臂文件世界隔离留待独立扩展。

## 源码依据与验收

源码依据：`replay-run.ts` 已复用前缀并真实执行后续工具；`derive.ts` 重建整轮 assistant/tool 消息；`fork-runner.ts` 当前 handler 真实读写 `exec.cwd`，`main/index.ts` 将该值设为数据目录。`ToolRegistry` 会捕获工具异常，`sideEffect` 只是声明，不是权限系统；`resolveBranch` 当前只截到所选工具，不能完整表达同轮后续工具已执行的事实。上述结论来自源码核查，未对 OS 原生 COW 或容器能力作实测承诺。

验收主线：导入 `a.txt=before` → 隔离父 run 的某轮写入 `middle`、下一轮写入 `after` → 编辑前一轮工具结果并分叉 → 子 run 首次读取必须是 `middle`，而非源目录当前值或父 run 最终的 `after`；子分支写入 `child` 后，源目录、父快照及兄弟分支的字节哈希不变。多工具同轮和二次分叉必须覆盖，前缀 LLM 与工具调用数均为零，只有续跑段真实执行。验收直接驱动包 API；桌面可操作见 B，文件结果查看见 C。

## Non-goals

- `apps/desktop` 修改仅限因共享包版本兼容而必需的既有版本/测试断言与常量引用修正，须保留既有行为及拒绝门禁，并记录原因和回归证据。禁止新增或扩展 IPC handler、preload/store 暴露、渲染层组件和 main 侧流程；不交付目录选择器、创建表单或文件查看 UI。隔离桌面工作归 B/C，可用性工作归独立 U 变更，白名单外先调整受影响分工及 OpenSpec；公共全仓回归及桌面构建仍需运行。此白名单于 2026-09-17 随方向规划审阅同步，已完成的兼容修正不重复列为待办。

- 不运行 shell、子进程、任意插件/自定义 handler，不隔离外部 API、数据库、RAG、记忆和网络副作用。
- 不宣称操作系统级恶意代码防护；同用户的恶意进程篡改数据目录不在威胁模型内。
- 不给历史 run 补造快照，不把“现在复制一个目录”称为回到过去。
- 不重跑被编辑工具本身、不编辑工具参数、不恢复半轮状态；不改变既有 result 编辑的语义。
- 不支持隔离父本的 prompt fork / 模型 A/B 真执行；Trace-as-Test 继续是桩工具卡带，不访问文件世界。
- 不做自动回写、合并、导出执行目录、附件垃圾回收或删除 UI；保留原有分支删除保护，禁止单独删共享 blob。
- 不做任意工具定义编辑器、整个项目构建环境、跨平台发行或版本发布。

## 保真度边界

本期确定采用受控文件工具范围。`sideEffect: false` 只描述 `read_file` 不写入；只有固定快照下相同参数的读取才具备 pure 的确定性。`write_file` 必须经显式副本写入授权，其真实副作用仅更新本分支文件映射；文件内容在检查点边界可精确恢复，但权限、时间戳、链接、设备、空目录和外部状态不在快照契约内。模型继续真实调用 provider，响应和费用不是确定性回放，也不保证缓存命中。

源目录导入是用户启动时的文件采集，不承诺对并发修改中的目录取得操作系统原子快照；检测到采集期间变化时拒绝。所有历史恢复只使用已经录制的不可变清单与附件。原始文件内容可能含敏感信息，工具读出的文本会按现有模型请求流程发送给用户配置的 provider，文件隔离不等于网络离线。
