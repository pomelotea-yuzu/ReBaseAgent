# 面向第二轮社区试用的 UI 整理

## Why

现有界面已提供运行阅读、编辑、实验、比较和结果导出，但维护者仍感到内容难找、部分操作不顺手。10/12 实机走查发现当前对象与侧栏选择混淆、导航术语重叠、未修改会话被近似标为草稿、初始表单和执行说明重复；本轮先整理这些日常路径，完成验收后再打包，用于第二轮社区宣发。

## What Changes

- 为应用入口、当前对象、局部操作和会话活动明确分工；运行查看、编辑、比较、新建各自显示真实目标，侧栏选择不冒充当前任务对象。
- 将应用级“运行记录／分支关系”与运行内“概览／步骤／文件”、步骤目录和执行活动明确区分；列表优先呈现任务、结局和必要身份，详细指标仍可访问。
- 统一任务标题、来源路径和具体返回目的地；编辑、比较保持主工作区阅读空间，导航可以按任务临时收起，手动偏好和返回位置保持。
- 将有未提交修改的草稿与未修改的编辑会话分开呈现，保持已有精确身份、正文、修订及退出保护。
- 处理初始引导、校验与确认的层次，同一阻塞原因不重复铺陈；正式提交前仍显示目标、费用、执行范围和必要异常。
- 通过同任务原型、真实 Electron 操作、窄窗／200% 缩放／键盘及跨页状态回归选择并验收方案；形成后续实包验收清单。

## Capabilities

### New Capabilities

无新增 capability 目录。

### Modified Capabilities

- `desktop-ui`：工作区导航术语、全局／对象／活动分工、任务身份和返回路径、布局覆盖、清洁编辑会话与修改草稿的表达、初始校验及确认层次。

## Impact

主要影响 renderer 的 `App`、`GlobalBar`、运行列表、运行／辅助／比较工作区、草稿列表、创建和实验表单、操作入口及相关布局状态。复用现有 React、Tailwind、zustand、Monaco 和派生事实，不新增依赖、IPC 执行通道或 trace 格式；已交付 R2.1 导出作为本次回归路径。

本 change 与前述 U1–U8 及三个 UI 衍生归档保持历史分离。先交付 UI 整理，再安排包含 R2.1 的候选包和第二轮社区材料；R2.2 为此轮之后的下一项新增能力。

## Non-goals

- 不实现 R2.2／R2.3、真实 Shell／测试、跨运行文件 diff、外部会话导入、全局正文搜索或自动评分。
- 不新增通用停靠、多窗口、无限标签或另一份草稿／操作状态仓库。
- 不默认把设置改成独立页面；本轮保持现行设置模态与未保存配置保护，若后续选择改变，先另行修订设计和 delta。
- 不修改执行、费用授权、单槽去重、来源完整性、记录格式、文件恢复、R2.1 导出或副作用语义。
- 不在本 change 内提升版本、打包、上传 Release、推送或发布社区帖子；相关交付在 UI 验收后单独执行，不提前宣称已发布或已验证竞争优势。

## 保真度与执行边界

页面组织、查看、返回、折叠和草稿恢复不调用模型或工具，不修改 trace、附件、源目录或父／兄弟运行，不恢复旧许可。普通 result 重跑复用分叉前消息，后续真实执行且不恢复外部世界；隔离续跑从编辑轮末文件副本继续，不撤销同轮写入；prompt 从头运行，messages 只重发单请求。UI 必须准确表达这些既有区别，不能以更简洁的展示扩大恢复承诺。

## 依据与验收

- [实机走查](../../../docs/reviews/2026-10-12-ui-live-walkthrough-and-refinement.md)提供具体问题和已可用路径。
- [UI 组织调研](../../../docs/research/2026-10-12-ui-organization-patterns-and-rebaseagent.md)提供候选结构，未证明可用性收益。
- 会话中的两个交互草图仅用于讨论；选中或点击草图不构成全部布局和行为获批。
- 核心任务：指出当前对象、找错误／文件、修改后跨页恢复、比较两条并返回、找到操作结果、导出选定检查点。记录错误入口、对象判断、返回目标及实际完成情况；维护者自测不冒充外部用户研究。
- 最终按 delta 场景提供测试／实机证据，完成全仓既有质量门禁和规范差集复核，再归档；开发版验收不代替后续 portable 包验收。
