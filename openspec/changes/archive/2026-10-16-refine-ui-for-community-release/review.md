# 评审：refine-ui-for-community-release（面向第二轮社区试用的 UI 整理）

- 评审日期：2026-10-12
- 评审对象：proposal.md、design.md、tasks.md、specs/desktop-ui/spec.md（delta）、.openspec.yaml
- 方法：制品互证 + delta 与主 spec（`openspec/specs/desktop-ui/spec.md`）逐条对照 + 场景→任务覆盖矩阵 + `openspec validate --strict`（通过："Change 'refine-ui-for-community-release' is valid"）
- 结论：**方向与结构通过，可进入实现；但有 4 项建议在实现前销账的问题（A 组），其中 A1（会话活动入口与既有入口的关系）涉及归档后规范一致性，建议先定清。**

## 一、总体评价

这是一份质量较高的 change 制品：

1. **四份制品相互一致**。design D1–D6 与 delta 的 5 个 ADDED requirement 一一对应；proposal「保真度与执行边界」与既有 result 重跑／隔离续跑／prompt／messages 语义吻合，明确"UI 不得以更简洁的展示扩大恢复承诺"，边界意识清晰。
2. **范围控制得当**。Non-goals 明确排除 R2.2/R2.3、打包发布与版本提升，tasks 6.4 只交接候选包与社区材料验收清单——与"宣发执行等用户明确指令"的既定决策一致，未越权宣称已发布。
3. **验收纪律延续既有约定**。D6 禁止为截图改 store／伪造 operation；任务按 ≤2h 单元拆分、先原型后实现；6.1–6.3 覆盖门禁、证据索引、归档合入核对；引用的两份依据（实机走查、UI 组织调研）均存在于 `docs/`。
4. **MODIFIED 场景零丢失**。两个 MODIFIED requirement 的 8 个基线场景全部同名保留，正文改动（术语、分工、录制入口表述）均有对应落点。

## 二、A 组：建议实现前销账

### A1. 「会话活动入口」与既有三个入口的关系未在 delta 中定清（优先）

ADDED3 新增"系统 SHALL 提供在所有工作区和窄窗中可达的会话活动入口"，但主 spec 已分别存在三个相关契约：

- [草稿可定位且来源失效不丢输入](file:///D:/ReBaseAgent/openspec/specs/desktop-ui/spec.md#L1094-L1115)："提供可访问创建及其他运行草稿的会话入口"；
- [跨页操作反馈展示真实等待与分层状态](file:///D:/ReBaseAgent/openspec/specs/desktop-ui/spec.md#L1519-L1540)："全局操作入口 SHALL 在创建、运行阅读和设置往返期间可达"；
- [结果导航尊重用户当前阅读意图](file:///D:/ReBaseAgent/openspec/specs/desktop-ui/spec.md#L1636-L1662)："面板关闭时仍可通过全局未读标记和可访问的 polite live 区域感知结果"。

delta 未说明会话活动入口是这三者的**统一演进**还是**第四个并存入口**。若归档后四条 requirement 各说各话，容易出现入口重复或语义分叉，也与 Non-goals"不新增另一份草稿／操作状态仓库"的精神相悖（入口虽非仓库，但重复入口同样制造第二套状态表达）。

**建议**：在 ADDED3（或 design D1）中明确一句——会话活动入口即既有草稿会话入口与全局操作入口的同一入口演进，承载分组计数；并考虑对 1095 的"会话入口"条款做对应 MODIFIED 或在 ADDED3 内引用其定位／失效语义，避免双重维护。

### A2. MODIFIED2 中"录制接入"表述变化未被任务显式覆盖

基线 795 行为"录制接入定位现有代理设置"，delta 改为"录制接入进入独立录制工作区"。这与既有 [录制工作区提供真实接入提示和只读记录入口](file:///D:/ReBaseAgent/openspec/specs/desktop-ui/spec.md#L2116-L2144) 一致，推测是修正基线陈旧表述；但相对 delta 合入机制而言这是规范行为变化，不能默认"无事发生"。tasks 2.1–2.4 均未点名核对，5.1 的"设置／录制往返"偏输入保持。

**建议**：tasks 2.1 或 2.3 增加一条核对（"录制接入进入既有录制工作区，不新开第二入口"），并在 6.2 证据索引中写明该场景属于"文字对齐既有实现"还是"行为变化"，二选一标注。

### A3. MODIFIED 的 4 个既有场景缺少任务锚点

场景→任务覆盖矩阵显示，ADDED 的 14 个场景全部被 tasks 显式引用，但 MODIFIED 的 8 个基线场景中：

| 场景 | 任务锚点 |
|---|---|
| 切到分支树 / 切换不重载 / 既有四条指标对照仍可使用 | 2.1 显式 ✓ |
| 阅读过程不修改已有数据 | 5.4 显式 ✓ |
| **选中状态跨视图保持** | 无显式引用 |
| **首次打开与无运行入口** | 无显式引用 |
| **文件承载区不附带步骤目录** | 无显式引用 |
| **旧创建设置及执行入口保持可达** | 仅部分（5.1 覆盖设置／录制往返，入口可达未点名） |

1.4／6.2 只以"完整保留场景""受影响既有场景"笼统兜底。按项目验收纪律（逐场景证据、未过场景明确标记、不冒充通过），页面外壳与导航改动恰好直接触碰这四个场景的行为面（入口重组、文件页布局、首次进入路径）。

**建议**：在 2.x／5.x／6.2 中把这 8 个场景名（至少上述 4 个）显式列入证据索引条目，指明证据去向。

### A4. ADDED1"完整 ID SHALL 可访问和复制"无对应核对点

tasks 2.2 覆盖对象头、2.3 覆盖来源摘要与返回文案，但"完整 ID 可复制"未被任何任务点名。建议并入 2.2 的验证句。

## 三、B 组：建议确认（不阻塞实现）

### B1. 同一规则多处重述，存在分叉维护风险

- "侧栏选择不冒充当前对象"：MODIFIED2 新增句、ADDED1 正文、既有 [双运行工作区保留比较对象和返回位置](file:///D:/ReBaseAgent/openspec/specs/desktop-ui/spec.md#L1925-L1951)"比较对象 SHALL 独立于侧栏选中 run"三处表述。建议以 ADDED1 为唯一规范源，另两处引用之。
- ADDED4"相同阻塞原因 SHALL 有一个主要说明位置"与既有 [工作区说明分层去重且异常不隐藏](file:///D:/ReBaseAgent/openspec/specs/desktop-ui/spec.md#L2279-L2296)"同屏同一说明只呈现一份完整内容"基本同义。建议引用而非重述，ADDED4 只写新增的"初始引导／touched 时机"分层。
- ADDED1"返回来源失效可辨"与既有场景（1943 返回恢复来源、1102 源记录失效）高度重合，真正新增的是"返回入口显示实际目的地文案"。可收窄条款聚焦新增，回归部分留给既有 requirement。

以上不影响校验与合入，但会提高归档后的维护成本；若保留重述，建议至少在 design 中记下"重述系有意冗余"。

### B2. 术语漂移：design D1"运行配置" vs spec"设置入口"

D1 写"全局栏保留品牌、运行记录／分支关系切换、新建、录制和运行配置"，而 delta 与既有条款用"设置"，且主 spec 另有 [运行配置（LLM 接入）经 safeStorage 持久化](file:///D:/ReBaseAgent/openspec/specs/desktop-ui/spec.md#L278)（"运行配置"指 LLM 接入）。两词并存易误读。建议 design 统一措辞（如"设置（含运行配置）"）。

### B3. requirement 标题保留"轨迹"属正确做法，建议留痕

delta 标题"界面提供分支树与轨迹两种视图"保留基线用词（MODIFIED 须按标题锚定），正文要求不再用"轨迹"命名。这是对的，但建议在 design 或 tasks 1.4 注明"标题保留仅为锚定基线，不随文案改名"，防止后续整理术语时误改标题导致 delta 无法合入。

## 四、一致性通过项

- proposal ↔ design ↔ tasks ↔ delta 无互相矛盾；tasks 6.4 与 Non-goals 的"不打包不发布"口径一致。
- ADDED3 的 dirty 判据、改回基线、清空保护、录制未应用修改与既有 [编辑核对与明确放弃区分于收起](file:///D:/ReBaseAgent/openspec/specs/desktop-ui/spec.md#L1117)／[主进程核对草稿后决定常规退出](file:///D:/ReBaseAgent/openspec/specs/desktop-ui/spec.md#L1229) 的事实口径一致（"清空仍保护""改回基线恢复 clean"是既有契约的正确延伸）。
- ADDED2 与既有"自动适配 SHALL NOT 覆盖手动偏好"（2262）及专注模式条款（2343）方向一致，新增的是任务级临时覆盖的进入／退出规则。
- ADDED5 的"保持既有契约"回归句覆盖完整搜索、来源过滤、短 ID、未知语义（对应 27／406／475 诸条），未丢事实。
- 布局约束（窄窗、200% 缩放、键盘、主体高度、Monaco 离线挂载）在 D6 与 5.5／5.6 中均有落点，与主 spec 窄窗条款呼应。
- `.openspec.yaml` 存在；`openspec validate --strict` 通过。
