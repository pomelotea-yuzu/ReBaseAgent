# U5 设计：创建、执行反馈与结果收尾

## Context

硬前置 U1/U3/U4 均已归档，U2 的文件阅读用于回归。权威范围为拆分计划 U5；U4 [证据索引](../archive/2026-09-27-add-desktop-operation-tracking/evidence-index.md) 的未交付声明用于识别边界，不将取消、并发、跨进程恢复自动纳入本次。

当前实现提供的基础与本次衔接点：

| 位置 | 已有事实 | U5 所需变化 |
|---|---|---|
| `shared/operations.ts`、main registry | epoch、版本、槽、可信 runIds/arms、受控诊断 | 原样消费，不增加执行阶段 |
| `operation-session.ts` / `operation-polling.ts` | 握手、乱序守卫、有界单路轮询、未知门禁 | 统一触发结果核实，禁止组件各自轮询 |
| `store.ts` 执行方法 | 多个单运行路径收到 ok 后直接 selectRun；A/B 只刷新 | 收尾独立于局部 busy/组件生命期，导航受意图约束 |
| `draft-submission.ts` | 原子提交快照、修订、token、epoch/operationId；解冻删除待定关联 | 解冻前保留最小清理关联，读取结果后再按修订清理 |
| `CreateRunDialog` | U3 草稿、隔离目录/授权、执行期间模态锁 | 改为创建工作区，执行时可离开阅读 |
| `SettingsDialog` | 单向 key、保存/清除、代理区和 U4 门禁 | 增加未保存修改保护、可靠反馈和返回流程 |
| `RunRepository.getRun`、shared 派生 | 受校验详情、叶子事件、自有 span 身份、结局分类 | 按可信 ID 独立读取，不借选中运行或列表状态推断结果 |

U4 注释/记忆中个别“取消归 U5”表述与拆分计划不一致；实现时清理本次触及代码中的过渡注释，以本 proposal 的 Non-goals 为准。U4 归档记录保留历史原文。

## Goals / Non-Goals

目标是让一次创建或修改可以连续经过编辑、检查、确认、执行、读取和返回；页面离开不影响事实核对；正常结束才按原提交修订清理，任何不确定性都保留输入。验证范围包括七类主动入口和所有已有草稿类型。

非目标见 proposal。特别是结果读取状态只表示 renderer 看到了什么，不给 main 增加第二套 running/settled 状态，也不改变 U4 错误分类或执行锁。

## Decisions

### D1. 创建作为主工作区页面

复用 App 的工作区切换及 U1 阅读状态，增加明确的创建视图和来源位置引用。保留全局栏与运行导航；离开创建保留唯一会话创建草稿，再次新建恢复它。来源引用只含运行/页签/调用/文件阅读定位，失效时回退已有可用工作区，不伪造运行。

来源引用单独存于 renderer 会话导航状态，不进入创建草稿，不持久化。每次从非创建工作区进入创建时，以当时阅读位置重新建立来源；创建页内重复点击新建及设置往返沿用本次来源。草稿的恢复、放弃或正常结束清理不决定来源引用的生命周期；renderer 重载后引用失效，返回时使用已有可用工作区回退，不从草稿或 main 操作登记猜测旧位置。

正文单列、最大 800px，顺序为模式、任务、隔离目录、当前模型/接入摘要、高级系统指令、执行范围、操作区。两种模式共用摘要。执行相关字段与 sourceToken 使用已有独立数据结构；不把配置、目录引用、授权混入任务文本。空系统指令有效，空任务无效；没有采集预览 API 就不显示文件数量或“目录检查通过”。

提交后冻结对应草稿，允许切运行、阅读文件、去设置查看及收起操作详情；配置写入口仍受 main 门禁。原生目录选择期间遵守系统对话框行为并防重入，返回结果有流程代次守卫。更换目录、模式、内容或设置往返使确认失效；取消选择保留原有效引用。已消费/过期 token 必须重新选择，不能按路径重建。

### D2. 统一流程规则，保留入口语义

复用字段组件与既有编辑器，不建设通用表单引擎。检查结果绑定目标、草稿修订、设置快照和检查代次；任一改变后旧响应不可安装确认或授权。实际提交再次经过 main 原门禁。检查期间仅显示确实发生的本地检查/只读请求，不调用模型。

| 入口 | 确认信息与检查来源 |
|---|---|
| 普通创建 | 当前模型、任务、可空系统指令、纯对话；本地字段检查，提交时 main 校验 |
| 隔离创建 | 当前目录、隐藏普通文件采集范围、文本可能进入模型请求、副本写入；目录令牌与字段本地检查，导入条件由正式 main 请求校验 |
| 普通 result | 父运行、工具结果原/新值、后续工具可能有副作用，非隔离；保持原 replay 门禁和模型不一致提示 |
| 隔离 result | 现有 `forkCapability`，直接父、本地轮号、整轮结束检查点，不重做所选工具、不撤销原写入；每次副本授权 |
| prompt | 一次只改 system 或首 user，从头执行、无共享执行前缀；首次调用可重建检查 |
| messages | 完整有效 messages，当前代理会话凭据，单请求重发；不执行外部 Agent 工具 |
| A/B | 现有 dry-run 生效计划、独立计费、多臂从头执行；修改使计划失效，原副作用门禁不变 |

创建表单末尾可就地进入确认态，避免新增阻断阅读的大模态。result/prompt/messages/A-B 暂留既有编辑区，但提交前必须可核对本次目标与值。进入设置或返回编辑都撤销许可。已知但不具备资格的入口提供就近原因，不能只靠 hover。

### D3. 执行事实、读取状态和草稿关联分开

保留 `operations` 作为 main 快照的唯一镜像；全局可执行性仍从 U4 `deriveGate` 派生。renderer 可新增两类会话内数据，不写磁盘/URL/日志/操作 IPC：

- 结果读取项：以 `(epoch, operationId, runId)` 为键，记录未读/读取中/已核实/不可读、读取代次及经校验结果的展示投影。重复快照不重复拉取；手动重试递增代次，旧响应不能覆盖新读取。
- 提交收尾关联：以 `(epoch, operationId)` 为键，保留目标键、submittedRevision、token、批次预期臂及导航意图。解冻待定提交前转存这些最小元数据，正文仍只在 U3 草稿/原提交快照内；终止清理完成可释放关联，待读取则保留到 renderer 会话结束或显式放弃相关草稿。此关联不能授予执行资格。

收尾入口由有效 status 采纳、有效执行回执后的状态刷新、reconcile 后的状态刷新共同触发。同一操作的解冻、列表刷新和成功清理均幂等；不可只在组件 `.then()` 中处理。有效 `settled/notAccepted` 可以按 U4 规则解冻，结果核实可稍后完成；仍未知则继续冻结。`notAccepted` 没有结果核实的成功路径。

保留 U4 恢复语义：通信 unknown 只能由有效 status 清除，reconcile 只补单条事实；新 epoch 不把整个新会话锁成未知，也不证明旧操作结局。旧 epoch 的关联不能自动清理/重发；没有原修订关联的 renderer 重载只能恢复登记和读取结果，不能推测恢复草稿。

### D4. 按可信身份读取运行结局

main 记录为 settled 后，对其可信 runIds 经既有 API 独立读取 `RunDetail` 并校验。不能为了后台核实调用会修改当前选择的 `selectRun/reopenRun`。列表刷新最多对该终态自动触发一次，列表失败与结果读取分别报错；二者都不能发起执行。

实现上拆为独立的“按 ID 核实结果”与“校验资格后导航”两个 store 动作。核实动作无论成功、失败还是重试，仅更新对应结果读取状态，不改变当前运行/页签/调用选择、滚动或焦点。自动导航由流程协调处在核实结束后另行调用 D6 的导航动作；该动作在实际切换前重验资格，不能用开始读取时的资格快照代替。集成测试直接调用核实动作断言零导航副作用，再单独验证允许/撤销导航的两条路径。

读取核对包括请求 runId 与 `meta.id` 一致、自有终止事件所属运行、详情 schema 与版本，错误定位只用 `leafSpanIds` 内的真实失败调用。复用 `deriveTerminalReason` / `classifyOutcome` 展示，但清理须严格核实自有事件为 `event=stopped` 且 `reason=completed`，不能只看文件 `status=completed`（仅说明封存）。`RunRepository` 的根/prompt/proxy 分支返回当前记录事件，`trace-sdk/branch.ts` 返回 `leaf.events`；用现有 reader/resolver fixture 固定该归属。缺祖先导致既有详情读取失败仍按不可读处理，U5 不放宽读取。

| main 与读取事实 | 展示及处理 |
|---|---|
| running | 执行中，草稿冻结，零“即将完成”推测 |
| notAccepted | 本次未接受，保留草稿，按现有规则解冻 |
| settled，尚在读取 | 执行已结束，正在读取结果；不因它占槽 |
| 自有正常终止 | 正常结束，不表述测试通过；进入修订清理判定 |
| error / 上限 / aborted | 展示具体原因，保留草稿；有真实失败调用才给定位入口 |
| 无终止事件 / 未识别 reason | 中断或原因未知，保留原始 reason 和草稿 |
| 无可信 ID / 文件缺失、损坏、未来版本等 | 执行已结束，结果未定位/不可读；核对登记或按已知 ID 重试读取 |

`requestOutcome=rejected` 是现有编排分类，并非一律“零调用未执行”；只有 notAccepted 或明确的本地未发送才能这样表述。保留请求诊断与持久运行结局各自一行，二者不互相覆盖。信封失败但记录正常仍按严格的自有终止判据决定是否清理，同时保留请求异常；信封 ok 但运行 error 则展示失败并保留输入。

A/B 以提交预期臂和 main `target.armCount/arms` 为集合基准，逐 index 对应真实 ID；全部预期臂身份唯一、完整且记录各自正常结束才算具备整批清理资格。不得按旧 `ids` 成功子集或 `arms.every()` 空集合判断。缺臂、null ID、失败臂、不可读臂和不一致的 experimentId/臂身份均保留整批；不显示胜出臂或臂间质量结论。

### D5. 只清理提交对应的修订

自动清理使用原子 compare-and-delete：当前草稿目标键与提交相同、revision 相同、没有更晚 token 的待定提交，且本操作满足 D4 的正常终止条件。内容相同也不能代替修订相同；删除后重建草稿沿用 U3 单调修订保证。创建清理整份创建草稿及该提交对应的目录引用；A/B 清理整批，不清某个成功臂。

执行终态解冻后用户可以修改，旧读取结果只更新对应操作，不清后来的修订。重新提交即使正文没改也会有新 token，旧操作不得移除其冻结或草稿。显式放弃和自动清理竞争时均须做目标/修订检查；重复 status、返回回执和手动读取重试不得重复产生导航或通知。

错误、限制、中止、中断、未知和不可读保留草稿；只读重试最终核实正常终止后仍可清理原修订，但不得再自动导航。重新执行需要新 operationId、重新检查和授权，不能由“重试读取”复用执行通道。

### D6. 全局反馈与导航意图

扩展既有 OperationsEntry，按操作列出类型/对象、等待时间、请求事实、结果状态、诊断和可信结果动作。等待计时从本地提交时间派生；重载后仅有 main `startedAt` 时标作“自接受起等待”。settledAt 后停止增长；无开始时间的 tombstone 不伪造时长；计时不是模型耗时。使用一个可见性受控时钟更新显示，不据此轮询执行或推测进度。

提交时保存来源位置与导航代次。只允许未离开本次流程、同一代次、无阻挡模态、首次自动读取所得的单运行可读结果进入概览，失败也可进入失败概览。任何主动切运行/页签/步骤、去设置、返回来源或关闭编辑都会撤销自动导航资格；离开后再回到同一 run 也不能复活旧资格。异步读取提交导航前再次核对代次，避免读取途中抢焦点。

所有主动核对、手动重试读取、重载恢复和 A/B 都只显示可查看结果；当前页面不变。通知用全局入口未读标记和 `aria-live="polite"` 区域，不强制聚焦或弹模态；区域位于可访问的全局外壳，操作面板关闭时仍存在。结果从待读取转为可查看或不可读时更新相应通知文本，同一结果状态的重复快照不重复通知，等待计时不进入 live 文本；关闭通知不删除 main 登记。明确“打开结果”进入概览，“查看失败调用”进入自有失败 span；不存在调用详情时给诚实说明，不找祖先补全。保留返回原草稿入口，草稿已清理或来源失效时提供有效回退，不复活旧内容/授权。

### D7. 设置返回与密钥边界

设置保留真正模态，约 640px 宽但受可用宽高约束；窄窗占可用工作区。打开时记录来源焦点/工作区，保存后显示“已保存”，提供返回原编辑流程；关闭也按来源恢复。返回刷新配置摘要并使预检/确认失效，输入与 U1/U2 阅读位置保留。

未保存模型字段/密钥或尚未应用的代理字段关闭时确认放弃/继续编辑；密钥只在设置组件内存中，成功保存或确认放弃后清除，不入调试草稿。已有配置空 key 表示保留，新配置缺 key 按现有校验拒绝。保存中/清除中防重入，失败保留输入；保存已写入但回读失败需单独提示“配置已保存，状态待读取”，不能标为连接成功或显示旧摘要为新事实。清除确认明确包含删除凭据，取消不调用清除 IPC。

settings/proxy 写入继续使用 main 槽、configurationBusy/closing 与通信门禁；查看和返回不受执行锁阻断。代理区保留可达，“录制接入”定位该区，独立录制工作区留给 U8。系统退出继续使用 U3/U4 的一次合并确认，本次不新增恢复承诺或取消接口。

### D8. 视觉与可达性

使用现有图标、模式分段控件、授权复选框和就近字段错误。正文保留足够阅读宽度，原/新值窄窗上下排；操作状态以文本加语义图标表示，不能只靠颜色。新工作区、操作详情和本次修改的设置/确认容器验证 1440/1210/1024/800 CSS px、独立 200% 缩放及有效窄容器，长路径/ID/模型不遮挡动作，不用缩小字体掩盖溢出。

创建是页面，不做焦点禁闭；进入聚焦标题或任务，允许浏览导航。保留模态仍限制 Tab/Shift+Tab 和背景交互，Esc 只处理最上层，Monaco 弹层优先。关闭操作详情只恢复入口焦点，不取消任务。不得展示 IPC 名、修订/token 等实现细节作为用户使用说明；执行范围和费用事实必须就近可读。

## Delta 策略与兼容性

仅提交 desktop-ui delta，不直接改主 spec。MODIFIED 按完整 requirement 替换并保留既有 scenario 名称；以下为有意变更，不可在归档时误认作场景遗漏：

| 既有 requirement | 有意替换的过渡行为 |
|---|---|
| 桌面端提供原生 run 创建入口 | 小对话框改工作区；无条件选中新运行改受导航意图限制 |
| 代理 run 的 llm.call 可编辑 messages 重发 | 成功后一律自动选中新运行改受导航意图限制 |
| 运行工作区按阅读任务组织 | 首次加载不能覆盖用户已打开的创建页；过渡入口说明更新为已交付能力 |
| 创建草稿和实验臂遵守同一保留规则 | 创建恢复到工作区；仅响应不清理，核实正常结束后允许清理 |
| 提交绑定草稿修订且响应不清除草稿 | 保留名称；“响应”仍不清理，新增独立核实后的严格清理 |
| 保留模态框约束焦点并正确恢复 | 创建不再是模态；执行冻结不再阻断离页，原生选择防重入保留 |
| 现有界面消费统一操作事实 | 承接完整结果流程；恢复/核对仍不自动导航 |

设置 safeStorage、IPC、执行槽、关闭保护和文件读取 requirements 继续生效；新增设置交互 requirement 只补用户流程。没有新依赖、迁移或 JSONL 改动。若实现发现现有详情不能证明自有终止事实，先修订本设计和 delta，再决定最小接口变更，不扫描列表推断或悄悄放宽校验。

## Risks / Trade-offs

- 结果读取与解冻有时间差，丢失提交关联会使自动清理永远不发生；反向风险是旧结果清除新输入。用真实 store 接线测试覆盖两侧，不能只有清理纯函数单测。
- 七类入口已有局部 success/busy 标记；迁移时逐条核对所有消费者，避免旧 `.then(selectRun)` 与新收尾并存。A/B 计划仍只读，不进入结果编排。
- 轮询返回全量快照，逐次读取所有历史结果会放大 IO；仅处理新增终态和明确重试，读取队列串行且按身份去重，面板关闭不影响待定提交收尾。
- 现有 API 缺目录采集预览与实时进度，因此只能显示真实的等待和已完成检查，无法提前承诺执行一定成功。
- U4 快照真实 IPC 满载成本、configurationBusy 合并关闭的实机覆盖、跨 epoch 在飞恢复实机前提、ProxyManager 被动录制交错反证仍是历史限制。本次接线涉及的场景新增证据单列，未补齐者如实留账。

## Migration Plan

先实现不导航的结果读取与修订收尾，再迁移七入口，随后迁创建页面/确认/设置，最后做真实 Electron 闭环。每阶段保留原入口可达，禁止只落逻辑不接消费点。全部实施任务保持待办；通过门禁和场景证据核对后再另行归档。

## Validation Strategy

单测固定终止事实、修订/token 竞争、预期臂完整性、读取代次和导航资格。store/组件集成用真实动作链确认响应/status/reconcile 三条路径均接到结果读取与清理，记录只读/执行通道调用次数。受控 Electron 验收覆盖七入口成功与失败、503、限制、不可读结果、离页/返回、设置和键盘；不调用付费 provider。每场景在实施阶段 evidence-index 对应具体用例/fixture/截图与未覆盖限制。

场景「普通结果与隔离结果确认边界不同」只有 tasks 4.4/4.5 两部分证据齐全才计为覆盖；一侧通过只能记录部分覆盖。通知验收除检查 live 区域存在和 polite 属性，还要在操作面板关闭时触发真实结果状态转换，断言文本更新、重复状态/计时不重复通知以及焦点不变；DOM 与可访问属性检查不冒充屏幕阅读器实际播报验证。
