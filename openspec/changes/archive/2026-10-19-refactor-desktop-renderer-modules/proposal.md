# 按职责拆分桌面渲染层大文件

## Why

R2.1 结果导出与本轮 UI 整理已进入 `0.5.0-rc.1` 构建，维护者于 2026-10-16 确认已完成打包上传。后续 R2.2 等能力接入前，桌面端的详情编辑、文件查看和应用状态仍集中在三个大文件中，改动容易同时触及阅读恢复、执行许可与异步收尾，审阅和定位成本较高。

本轮只编写重构方案，尚未实现。源码核对基线为 `ddcfd2a`（UI 归档 `00ecab6`，打包提交 `18ebb6f`）；上传状态采用维护者确认，本轮未联网核验发行链接。当前三个目标文件分别为 `store.ts` 3769 行、`DetailPanel.tsx` 2161 行、`WorkspaceFileView.tsx` 1866 行，包含空行和注释。这些数字说明职责集中，不作为性能问题或缺陷的证明。

## What Changes

- 将详情容器、prompt/result 编辑器与调用详情展示按职责拆开，保留组件身份、现有入口和草稿恢复。
- 将文件工作区的读取连接、页面布局和内容编辑器拆开，保持两侧读取状态、过期响应守卫、滚动与 Monaco 资源生命周期。
- 将应用状态类型、功能分片与副作用资源管理拆开，继续只创建一个 zustand store；统一提交、状态核对和按修订收尾仍各有唯一实现。
- 迁移依赖旧文件位置的测试，逐条保留原有保证；用模块依赖、资源生命周期、真实 action 竞态和 Electron 交互证据证明拆分后行为等价。
- 记录拆分前后职责与规模，形成稳定的模块入口和维护说明，为后续功能变更提供可审阅的边界。

## Capabilities

### New Capabilities

无新增产品 capability。

### Modified Capabilities

- `desktop-ui`：增加渲染层模块边界、单一状态与资源生命周期、拆分后行为等价及验证要求。采用 ADDED 内部维护约束，现有用户行为 requirement 不改写、不重命名、不删除。

## Impact

主要影响 `apps/desktop/src/renderer/src/{store.ts,components/DetailPanel.tsx,components/WorkspaceFileView.tsx}`，新增其内部模块，以及直接消费这些入口的测试。必要时调整直接调用方的导入，但原入口保留兼容导出。现有 `lib/` 纯判据继续复用，不复制进新目录。不新增依赖，不改 main、preload、IPC schema、包层执行逻辑或数据格式。

实施顺序为详情组件 → 文件工作区 → store 类型及资源接口 → store 功能分片 → 集成验收。每阶段独立回归，同一文件的开发顺序集成；不操作其他 agent 的会话，不覆盖无关工作区改动。该 change 属于已发行版本之后的维护工作，不追溯为 R2.1 打包前置条件，也不改变 R2.2 的产品优先级。

## Non-goals

- 不重新设计 UI、调整文案、功能、样式或导航行为，不顺带修复与搬迁无关的历史问题。
- 不拆 `shared/ipc.ts`，不整理所有超过某个行数的文件，不迁移状态库、引入事件总线或通用插件框架。
- 不新增持久化、第二份草稿/阅读/操作仓库、多 store 同步或跨 main 重启恢复。
- 不实现 R2.2、隔离 prompt/A-B、跨运行文件 diff、真实 Shell/测试、取消执行或实时步骤。
- 不提升版本、重新打包、上传、发布或推送；后续发行另按发布流程验收。
- 不以缩短文件、测试数量或旧版本截图作为行为等价的证明。

## 保真度与执行边界

普通 result 分叉仍复用分叉前消息，后续真实执行且不恢复外部世界；隔离 result 分叉仍从编辑轮末文件副本继续，不撤销同轮写入；prompt 仍从头执行，代理 messages 仍只重发单请求。隔离父本的 prompt/模型实验拒绝规则保持。阅读和模块初始化不触发执行、不修改历史 trace/附件或源目录；导出只写用户确认的合法空目标目录。授权、费用确认、单槽、来源完整性和未知状态核对沿用现行规范。

## 验收

场景、任务与待补证据见 [delta](specs/desktop-ui/spec.md)、[tasks](tasks.md) 与 [evidence-index](evidence-index.md)。实施前固定行为与测试基线，按阶段保留断言映射；结束时执行全仓 `pnpm check:ci`、单独 desktop build 和真实 Electron 关键路径验证。当前仅文档校验通过不代表重构或行为验收完成。
