# R3 桌面流程与状态

本文件描述待实现的交互，文案以用户任务为主。底层 digest、资源标识和执行阶段放到可展开详情；确认页仍保留足以决定是否执行的环境、网络、文件和资源范围。

## 入口与主要布局

```text
文件工作区：原 run · 所选步骤/初始 · 快照身份
  [比较文件]  [验证代码]  [导出文件]

验证代码
  输入：run / 初始或第 n 步 / 快照短标识 [查看文件]
  检查：固定 TypeScript 检查 / 固定测试
  环境：node-ts-v1 · Linux 容器 · 已准备/需准备
  本次范围：独立副本；测试无网络；不会请求模型
  限制：时间、内存、文件/输出容量 [查看详情]
  [核对并授权本次执行] [开始验证] [返回]

验证结果
  明确结局 + verificationId + 所测输入
  实际检查/环境/时间 [展开命令与环境]
  stdout | stderr [范围/截断/继续读取]
  [查看所测代码] [与另一验证比较] [导出所测代码]
```

未准备环境时显示“准备测试环境”，独立弹出固定下载来源、许可、网络、空间和准备范围确认；准备完成回到原计划重新核对，不自动开始测试。未通过后端验收显示不可用原因和说明，不提供宿主命令替代。

## 状态与操作

| 状态 | 主要信息 | 可用操作 |
|---|---|---|
| 未核对/不可用 | 缺项/支持范围/当前输入 | 阅读、返回、查看准备计划 |
| 准备中/物化中/检查中 | 当前真实阶段与可信 ID | 阅读；对当前 R3 停止 |
| 正在停止 | 停止尚未确认，保留锁 | 核对、重复幂等停止、阅读 |
| 检查通过 | 实际检查范围，代码/条件引用 | 日志、比较、R2.1 代码导出 |
| 检查失败 | typecheck/断言失败与真实退出码 | 日志、返回已有修复编辑、比较 |
| 环境/启动/进程故障 | 具体阶段与原因 | 阅读；用户明确新计划才能新执行 |
| 超时/输出超限/已取消 | 已确认停止及保留证据 | 阅读、返回；不自动重试 |
| 证据不完整/产物非法 | 命令事实与缺项同时显示 | 阅读，不显示完整通过 |
| 未知/启动核查阻断 | 停止事实未知/残留待清理 | 只读与可信核对，不放行新 R3 |

R3 按精确验证身份阅读。操作 settled 是请求收尾，不等于检查通过；command exit 是命令事实，不等于完整证据。重读日志不改变执行状态，不重新调用项目或模型。

## 修复与比较

原检查点验证失败后，用户回到已有 result/prompt 编辑入口，自行记录假设并确认新模型执行。生成分支后明确选检查点再次验证；R3 不自动改 prompt、触发模型或批量运行。

比较先固定两个 verificationId，上方始终显示两侧 run/step/snapshot 和干预证据；条件一致时并列“原检查失败/修复检查通过”，不自动称因果或整体正确。测试/依赖/镜像/命令不同则显示条件变化，字段缺失显示未知。代码 diff 继续用已交付跨运行检查点比较。

从结果“导出所测代码”必须传入原 selector/snapshotId，即使当前文件页已切到另一步。沿用 R2.1 原生目标选择、空目录与来源清单，不增加材料包或自动应用。

## 连续阅读与可访问性

验证是现有工作区的关联阅读页，不新增全局实验导航体系。进入时保存返回目的地，返回保留文件/比较两侧选择、滚动和草稿。异步响应按 selector/verificationId/请求代次隔离。

核对和按钮相邻，停止只对当前操作显示。模态框约束焦点；关闭后回原按钮。长 run/path/日志换行或局部滚动；约 800 CSS px 与 200% 下纵向排列条件和结果，不隐藏主要身份/结局。实施后必须以真实 Electron 的宽窄窗、缩放、键盘取证。
