# R3：在独立项目环境中验证修复

## Why

开发者现在能通过工具结果编辑或隔离 prompt 实验产生修复分支，也能比较和导出文件，但 Agent 声称“已修好”和文件发生变化都不能证明代码通过测试。现有 Trace-as-Test 使用录制响应验证运行时行为，不执行修复产物的真实项目测试。

本 change 承接[正式路线 §6、§11](../../../docs/product/evolution-roadmap.md)和[能力细化稿 §6](../../../docs/product/2026-10-12-capability-roadmap-from-r2-2.md)。复用 R1、R2.1、R2.2 和 U4，先交付一个明确环境中的“原检查点测试失败 → 已记录干预的修复分支 → 同条件测试通过 → 导出所测代码”。MCP0/1 已归档，MCP2 后续消费本阶段证据。本次仅设计提案，功能和执行后端均未验证。

## What Changes

- 在 Windows x64 技术验证一个可选隔离后端，首选本机 Docker Desktop Linux containers。验证安装与许可、镜像固定、文件/网络/资源限制、停止子进程及重启清理；未通过保持未开放，不回退宿主 Shell。
- 首版限定一个 `node-ts-v1` profile：明确 Node/TypeScript 模板、锁定依赖、可信测试和有限固定命令。环境准备与正式测试分开授权、记录；测试无网络，不执行项目自定义安装脚本或 package scripts。
- 新增包层 `project-verification`：校验一个已封存隔离 run 的自有检查点，物化独立副本，执行固定检查，保存命令、环境、日志、退出码、耗时、停止事实和产物清单。
- 新增独立版本化验证记录，用精确 run/step/snapshot 引用关联失败与修复。保留失败尝试，不改写已封存 run，不把测试作为新 Agent run、tool 或 trace v4。
- 桌面检查点/比较视图增加核对、测试结果和日志入口；准备/测试复用 main 登记、去重和唯一执行槽。新增仅针对 R3 owner 的定向停止接口，显式扩展桥接白名单；旧模型/代理操作不因此获得取消能力。
- 区分项目检查失败、环境故障、超时、真正停止后的取消、异常退出、证据不完整与未知。复用 R2.1 导出所测输入检查点；测试副本不覆盖源项目或替换 run 检查点。

## Capabilities

### New Capabilities

- `project-verification`：可选后端门槛、固定环境准备、独立物化、真实命令证据、停止/启动核查、验证记录读取与修复证据关联。

### Modified Capabilities

- `workspace-isolation`：将已核实的自有检查点物化到独立测试环境，保持现有文件工具与不可变性。
- `desktop-ui`：验证计划、执行与停止、可信验证身份、操作登记和证据/导出闭环。

不修改 trace-format、agent-loop 或既有 replay 的执行语义，不扩展 MCP 接口。

## Impact

新增 `packages/project-verification`，分离纯 schema、只读记录、准备/执行与 Docker 适配器；依赖已有 trace-sdk/replay/zod 和 Node 内置库，不新增 npm 第三方依赖。桌面影响 shared IPC/operations/channels、main registry/endpoints/启动核查、preload 白名单、store slices 与检查点/比较组件。质量检查纳入新包及测试类型检查。

Docker Desktop/本机 Linux 引擎是用户自行安装的可选外部依赖，不放入 portable exe 或发行 zip；安装要求、许可、体积和资源占用在阶段 1 记录。运行镜像的系统组件、Node、TypeScript 及依赖固定版本/摘要，附第三方许可。准确版本和 image digest 待实测冻结，不能预称支持。

增加后端验证记录、受控模板、用户指南和逐场景证据索引。R1/R2 的原便携使用不要求安装后端。具体设计、交互和实施验收见 [design.md](design.md)、[prototype.md](prototype.md)、[tasks.md](tasks.md) 和 [evidence-index.md](evidence-index.md)。

## Non-goals

- 任意宿主 Shell/终端、模型调用命令工具、自由命令、任意语言/构建系统或一般 npm 项目接管。
- R4 工具参数重做、R2.3 完整隔离实验、R5 外部服务恢复；数据库、网络、进程内存和完整操作系统历史恢复。
- MCP2/MCP3、CI 接入、批量评测、并发/队列、自动重试、自动评分或因果归因。
- R3-E2 完整证据材料包、R3-E3 回归管理平台、trace 分享包、自动应用/合并或覆盖源项目。
- 普通模型/代理执行的真正取消、main 重启后继续执行或恢复旧操作登记。启动核查只停止/记录残留。
- 本次实际安装 Docker、拉取镜像、执行项目、实现功能、打包或发布。

## 保真度边界

测试不重放/续跑模型消息，模型调用为零。读取选定 run 的一个自有初始/轮末检查点，核验全部普通文件路径、字节、大小和哈希后复制，不回读当前源目录。R1 只保真普通文件路径和字节，不恢复权限、可执行位、链接、空目录或外部状态；首版模板不得依赖这些状态。

Linux 容器与 Windows 宿主分别标明。依赖、可信测试和运行时来自本次固定环境，不声称恢复历史机器；代码、测试、依赖或环境变化均明确显示。真实模型修复仍走已有隔离 result/R2.2 路径，独立确认和计费；R3 不自动发起修复。

R1 文件副本隔离保持原边界；R3 额外进程/网络限制来自执行后端，不能从工具声明或授权字段推导。测试通过只证明本次固定检查；模板成功不代表所有已有项目接入或修复效率已获验证。

## 验收口径

先通过 Windows 上真实后端边界验证，再完成模板的一次已知失败与修复后通过；核对输入哈希、可信测试、环境、命令、日志、退出码、停止事实和导出字节。模板只允许 Agent 修改 profile 明列的源码，测试/runner/编译器由固定环境提供，防止删除测试被标成修复通过。

覆盖损坏附件、来源/计划漂移、并发与重复、越界/网络、子孙进程、超时/停止、输出/磁盘限额、daemon 断开、main 崩溃、残留清理、记录损坏和采集失败。源目录、父/兄弟 trace 与既有 blob 指纹不变。真实 Electron 的宽窄窗、200% 与键盘、全仓门禁独立执行；I（真实项目接入，见路线 §3.2）的真实项目任务单列验收，不用 fixture 代替。
