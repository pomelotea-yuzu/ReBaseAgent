## 2. 状态表逐行核对（prototype 22 行）

- 与现有同构、直接复用判据：仅打开未改动 / 预检中 / 可提交 / 核对后编辑变化 / 槽被占用 / 业务前置拒绝 / 执行中离开 / 响应丢失未知 / 模型预算存储失败 / 正常结束 / 文件一侧不可用 / 文件二进制超限 / 导出后返回。
- **需要新增判据**（现有实现没有、6.x 要接）：
  - 「草稿身份 = 执行模式 + 根 ID」：现有 `draft-source.ts` 的草稿身份只有 run 维度，隔离编辑要并入模式与根，否则同根普通/隔离草稿互相覆盖；
  - 「从中间分支进入 → 前往根运行」：现有 `isolatedParentExecutionNotice` 文案是「本期不支持，改用 result 分叉」，R2.2 要改写为「前往根运行查看启动指令」并配显式导航动作（文案改动在 6.1）；
  - 「修改或配置变化撤销旧许可」：现有只有 result 分叉的 atSpan/parent 同源核对，隔离要加计划指纹 + `expectedConfigRevision` 双核对（D2），**撤销发生在 main 侧，渲染层只显示「需重新核对」**。
- 原型修订（见 §4）：补「比较冻结期间出现新完成检查点」一行。

## 3. 文件双 selector 与导出方向（P0 重点）

- **包层缺省 = 初始快照**；**桌面首次打开 = 最近自有完成步骤，无则初始**。两个语义不同层，
  桌面必须先在已校验详情里把「最近完成步骤」解析成显式 `stepSpanId` 再发 IPC（仅选初始才省略）。
  现有 `WorkspaceFileView` 的检查点选择逻辑可参照，但比较文件页**不复用**其「自动定位最近」逻辑，
  避免把「最近一步」误传成包层缺省。
- 迟到防护：请求携带冻结的 `expectedSnapshotIds`；不匹配返回 `selection_changed`，UI 显示刷新入口，
  不自动重拉、不串用新正文。6.5 接守卫，7.2 实机。
- 导出方向复核结论：原型路径 6 的表述与 R2.1 语义一致（补丁基线 = 该 run 初始快照，不相对另一侧），
  无需修订；**「导出选定检查点」入口必须只在文件视图且该侧清单可用时出现**（清单不可用侧不给导出）。
