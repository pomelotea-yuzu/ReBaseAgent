# R2.2：隔离 prompt 修复实验

## Why

开发者发现 Agent 误解启动指令后，需要在相同初始文件状态下修改指令，检查新运行是否产生有用的结果。当前普通 prompt fork 会从头执行，却拒绝隔离父本；隔离 result 续跑使用轮末文件状态，不能替代启动指令实验。运行比较只能分别打开单运行文件页，尚不能核对两份检查点的文件差异。

本提案承接[正式路线](../../../docs/product/evolution-roadmap.md) R2.2 与[能力细化稿 §4](../../../docs/product/2026-10-12-capability-roadmap-from-r2-2.md)，源码核对基线为 `a833269`（2026-10-19）。R0/R1、U1–U8、R2.1、UI 整理及渲染层拆分作为已交付基础，不重开历史任务。本次只完成 change 设计，功能尚未实现。

## What Changes

- 提供只读隔离 prompt 预检：首版只接受已封存、来源完整、启动请求可还原且初始快照及全部附件可验证的 `file-tools-v1` 根运行。分支入口只定位对应根运行，不自动换基线或执行。
- 一次只替换首条字符串 system 或首条字符串 user 消息的 content，保留其余启动消息全部字段；拒绝空编辑、组合修改和无法无损重建的输入。保留空字符串与尾随空白的真实语义。
- 新增独立包层编排，从根初始快照建立文件世界，从第 1 步真实调用模型与固定文件工具；不复用父消息执行前缀、不回读当前源目录。
- 新增 trace v3 表达“隔离启动指令实验”，区分初始快照来源与 v2 的轮末来源；记录单项干预、执行配置与子运行身份。v1/v2 writer 保持原版本，新 reader 三版本兼容，旧 reader 明确拒绝 v3。
- 接入现有 prompt 工作区、草稿、费用确认、当前副本写入授权、main 操作登记/去重和单执行槽。新隔离路径不接普通宿主文件 handler，不把历史授权视为本次许可。
- 在既有双运行比较中新增两个自有检查点的文件清单/文本差异，逐侧保留 run/step/snapshot 身份；连接 R2.1 单运行导出。保留假设与人工判据，展示实际结局、输出、文件和新增消耗，不自动判定修复成功。

## Capabilities

### New Capabilities

无新增 capability 目录。

### Modified Capabilities

- `trace-format`：v3 初始快照来源、干预/执行记录、版本守卫与往返约束。
- `prompt-replay`：普通与隔离入口分流，根基线、单项编辑、真实身份和前置拒绝规则。
- `workspace-isolation`：初始快照重建新世界、只读跨运行检查点比较及状态区分。
- `replay`：v3 独立执行边界及其后续合法 result 续跑的读取/拼接规则。
- `desktop-ui`：隔离 prompt 核对、提交、结果/草稿、跨运行文件比较与单侧导出闭环。

## Impact

影响 trace-sdk 的 schema/版本守卫/reader/branch/事件流与包导出，replay 的隔离预检/编排/只读比较，desktop 的 shared IPC、main runner/operation endpoint/repository、preload 与拆分后的 store slices、详情 prompt 编辑器、比较和文件组件。trace-test 等版本消费方须覆盖兼容回归。保持 agent-loop 零 Electron/文件世界依赖，不新增第三方依赖，不迁移或重写历史 JSONL/blob，不新增独立实验数据库。

精确 API、版本与状态契约见 [design.md](design.md)，桌面入口与状态表见 [prototype.md](prototype.md)，实施验收见 [tasks.md](tasks.md) 和 [evidence-index.md](evidence-index.md)。本次不修改主 spec，不打包或发布。

## Non-goals

- 隔离模型/参数 A/B、多臂、重复采样、任意中间消息编辑、连续隔离 prompt 叠加实验，以及同时修改 prompt 和模型。
- Shell、真实测试/构建、工具参数重做、自动定位首次行为分歧、事件自动对齐、自动评分或因果结论。
- MCP 服务、外部会话接管、通用适配层、权限沙箱、外部网络/数据库/RAG/记忆恢复。
- 自动应用、合并、覆盖源项目、比较补丁导出或 trace 分享包；导出继续只针对一个选定 run 的一个自有检查点。
- 真正取消、队列、main 重启后的操作恢复、持久草稿或新的导航体系。

## 保真度边界

启动 messages 来自根运行自有首次真实 LLM 请求，仅目标 content 改变；这属于从头实验，不复用已执行 assistant/tool 消息或父 spans。文件起点只取同一根记录的 initial_snapshot，逐附件核验路径、字节数与 SHA-256 后建立新映射。保真范围仅普通文件路径与字节；不恢复权限、时间戳、空目录、链接身份、进程或任意外部服务状态。

分叉后模型和工具均真实执行并产生新消耗；相同模型名不能保证服务商后端版本、随机性或缓存一致。历史 provider、预算等若未录制须标未知；本次使用的端点/限制另行核对并冻结，不能声称所有运行条件只变了一项。源目录、父/兄弟 trace 与既有 blob 不变，新 blob 可按内容共享但不能覆盖。R3 前文件/输出变化不证明代码正确，正常结束不等于修复成功。

## 验收口径

以“保留 config.json 未知键，只修正指定配置”的固定文件任务作为首版受控案例：原指令可能覆盖未知键，用户只改 system 或首条 user，子运行首次读取须为根初始内容；人工判据为未知键保留且目标值正确。确定性 mock 验证消息/文件不变量，真实模型用于桌面流程证据；若实际输出未满足判据，如实保留，不重试挑选成功样本冒充首次结果。该 fixture 不宣称已完成 I 的真实项目接入或 R3 测试验证。

缺消息/附件、损坏、非根、未封存、profile/config 漂移、空编辑及提交前变更均须验证前置零调用/零子记录；执行后模型/存储失败保留真实身份与落盘事实。跨运行比较覆盖不同检查点、缺项、二进制和迟到响应，导出逐文件复核选中侧。实施完成后另行补全定向测试、Electron 真键盘/窄窗/200% 缩放证据及全仓门禁，文档校验不充当功能验收。
