# R2.2 桌面流程与状态草案

状态：2026-10-19 文档方案，尚未做交互原型验证或 Electron 验收。入口沿用当前工作区，P0/P1 核查安排在任务 1.2。

## 路径

1. 隔离根概览/启动输入 → “修改启动指令” → 现有 prompt 工作区。页头展示当前根任务与 ID，返回目的地为原概览/详情。
2. 选择 system 或首条 user，一次只编辑一项。原值/新值 diff，假设与人工判据为可选输入。字段切换保存各自会话草稿，不暗中合并提交。
3. “核对本次运行” → 根与初始文件来源、编辑差异、固定工具、模型/参数、当前端点、历史未知项、执行上限与费用提示 → 用户确认真实调用和仅副本写入 → 提交。
4. 全局活动区呈现真实操作状态；完成时就近显示“查看运行”“与基线比较”，遵守当前阅读意图，不抢导航。
5. 双运行比较沿用修改/输出/指标；新增“文件”视图，左右标题固定携带 run/检查点，文件路径并集居中选择，正文宽屏并排、窄屏上下。
6. “打开左/右文件”进入该 run 的明确自有检查点；“导出选定检查点”走已有 R2.1 目录确认。返回恢复比较原位置。

文件视图首次默认由桌面解析：有自有完成步骤就传入该步骤的实际 ID，无则显式选择“初始”。包 API 的省略 stepSpanId 只代表初始，不代表“最近一步”；已选步骤失效时显示该侧错误，不自动改成初始。

## 状态与恢复

| 状态 | 就近反馈与动作 | 输入/身份规则 |
|---|---|---|
| 仅打开编辑器、尚未改动 | 显示原值，提交不可用，无错误轰炸 | 活动区不计未提交修改 |
| 从中途分支进入 | 展示当前分支与可验证根，“前往根运行” | 只导航；根与分支草稿不同身份，无确认继承 |
| 根消息/初始附件缺失或损坏 | 显示具体缺项与重新采集入口 | 不给可执行计划；已输入文字保留 |
| 有修改、未核对 | 显示原值/新值与核对动作 | 费用/副本授权初始未选 |
| 预检中 | 显示核对中，允许阅读 | 迟到结果按根/字段/修订隔离，不建立 operation |
| 可提交 | 单份完整确认与提交相邻 | 计划、设置/凭据修订、正文一致才有效 |
| 核对后编辑/来源变化 | 就近提示需重新核对 | 保留正文，撤销确认和副本授权 |
| 槽被占用 | 显示实际活动及查看入口 | 不清草稿、不排队、不自动再提交 |
| 业务前置拒绝 | 原因及重新核对入口 | operation rejected 可以存在，子 run 身份为空 |
| 执行中/离开页面 | 活动入口显示真实状态 | 输入快照与提交修订绑定，不能重复执行 |
| 响应丢失/未知 | 显示“核对执行结果” | reconcile 只读，不能用执行重试替代 |
| 模型/预算/存储失败 | 显示实际结局与已核实运行入口 | 保留草稿和已落盘检查点，不伪造成功 |
| 正常结束 | 查看结果、比较、单侧文件/导出 | 依 U5 清理匹配修订，正常结束不自动判修复 |
| 文件一侧不可用 | 该侧显示缺失/损坏/I/O 原因，另一侧可读 | 不可用不等于空文件，不显示伪 diff |
| 文件二进制/超限 | 哈希/大小、未提供文本差异原因 | 保留明确单侧来源与导出路径 |
| 导出后返回 | 显示 R2.1 反馈，返回原比较对象 | 导出来源固定为选中侧，补丁基线为该 run 初始 |

## 可用性验收

真实 1440/1360/1024/800px 窗口与 200% 应用缩放，核对正文高度、长 ID/端点/诊断全文、横滚局限于代码区。真键盘完成根定位→单项编辑→核对→费用/副本确认→提交→查看→文件比较→单侧导出→返回；焦点可见，错误可读，返回不丢修订、选择、滚动与焦点。自动读取、折叠、视图恢复和比较不得发执行调用或恢复许可。

保持主工作区 overflow-hidden、各列 min-h-0、详情独立滚动和底部/正文同色。文件 diff 单独核对 CRLF/LF、空字符串、缺末尾换行、新增/删除方向，确保文本原样保留且差异可辨；fixture 字节检查与实机可读性证据分列。
