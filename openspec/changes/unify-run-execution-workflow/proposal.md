# U5：创建、重跑与执行结果闭环

## Why

U1–U4 已归档，主进程操作登记、执行槽、可信运行身份、未知状态核对和会话草稿均已交付。现在需要把这些基础能力接成连续的桌面流程：创建仍由模态框承载，执行时不能离开；普通创建缺少与隔离模式一致的模型摘要和就近配置入口；若干执行函数在响应返回后无条件选择新运行；草稿尚不按核实后的运行结局收尾。

本 change 对应 [U 拆分计划](../../../docs/engineering/plans/2026-09-21-ui-change-split-plan.md) U5、[UI 方案 V0.2](../../../docs/engineering/plans/2026-09-19-ui-layout-discussion.md) §9.6/§10/§12.1–12.2/§12.4/§16，以及 [实际走查](../../../docs/reviews/2026-09-21-ui-usability-walkthrough.md) R3/R4/R5/R10/R11。U1 的状态色与失败概览、U3 的草稿和模态保护、U4 的全局操作入口均为复用基线，不重新宣称为本次新增能力。

已核对 `store.ts` 的执行返回与导航、`CreateRunDialog`、`SettingsDialog`、`OperationsEntry` 和 `draft-submission.ts`。以 U4 归档提交 `9e82c91` 后的 `desktop-ui` 52 requirements / 236 scenarios 起草。本轮是设计文档，未重跑历史 GUI 走查。

## What Changes

- 将新建运行迁入主工作区，保留运行导航和返回位置。任务优先，系统指令放入高级区，两种模式均显示已保存的模型/接入摘要及配置入口；保留已有目录选择、采集边界与每次副本授权。
- 统一编辑、检查、确认和提交的交互规则，按普通 result、隔离 result、prompt、代理 messages、A/B 的真实执行语义呈现确认信息；没有预检接口的路径只声明已完成的本地检查。
- 扩展 U4 全局操作入口，展示等待时间、请求状态、结果读取状态和自有终止事实；跨页可查看，关闭详情不停止执行，不显示假进度。
- 把执行信封、main 登记终态、记录可读和正常终止分开处理。所有七类主动入口共用结果收尾；失败有可信 ID 即可打开并定位真实自有失败调用，列表失败不阻断按 ID 读取，重试读取不重执行。
- 只有已核实正常结束且仍匹配提交修订的草稿才自动清理。解冻与清理分开，解冻后保留最小提交关联供迟到读取核对；错误、上限、中止、中断、未知或不可读均保留草稿。A/B 必须全部预期臂均正常结束才可清理整批配置。
- 用明确的导航意图约束结果落点：仍在本次流程的单运行操作可进入结果概览；已经离开、主动核对或重载恢复仅通知，不抢选择、滚动和焦点。A/B 始终由用户选择结果臂。
- 补齐设置往返、未保存输入关闭确认、保存/清除反馈和密钥单向语义；继续使用 U4 配置门禁和 U3/U4 合并退出确认。录制入口仍定位已有代理设置区。

## Capabilities

### New Capabilities

无新增 capability 目录。

### Modified Capabilities

- `desktop-ui`：新增连续检查确认、跨页等待反馈、结果核实与只读重试、修订清理、导航意图和设置返回行为；完整修改原生创建、代理重发导航、工作区首屏、创建/实验草稿、提交关联、模态边界和统一操作事实 requirements，明确替换过渡条款并保留其他场景。

## Impact

主要影响 renderer 的 `App`、创建工作区、`DetailPanel` 内各编辑入口、`OperationsEntry`、`SettingsDialog`、store 和草稿/操作/导航派生逻辑。沿用 `operations:status`、`operations:reconcile`、现有详情读取、目录选择、隔离能力预检与 A/B dry-run；不新增 IPC 通道或 main 操作状态，不改变包层编排、持久 trace 格式或已有权限。

结果展示复用 `RunDetailSchema`、`deriveTerminalReason`、`classifyOutcome`、U1 概览/失败定位及 U2 文件阅读。新增 renderer 内存中的读取状态和提交修订关联仅服务展示与清理，不成为第二套执行真相源。使用现有 React、zustand、zod、Monaco 和 Lucide，不增加依赖。

## Non-goals

- 不提供真实取消、停止、实时步骤事件、预设执行阶段/百分比、运行队列、多主动并发或跨 main 重启任务恢复。U4 证据索引中“不宣称”的项目不是全部转入 U5 的待办，真实取消继续后置。
- 不扩展隔离 prompt/A-B、工具集、配额、每请求模型覆盖、文件权限或 provider 能力；不把正常结束称为任务质量验证或测试通过。
- 不实现 U6 缺父链读取、U7 双运行比较或 U8 独立录制/实验工作区；保留既有入口，不增加空按钮。
- 不持久化草稿、提交关联或操作登记，不回读密钥，不增加连接测试和自动付费探测，不自动重发失败/未知请求。
- 不修改 U4 `requestOutcome` 错误分类、隔离父本裸错误的包层形状或预检是否登记的契约；不把 U4 尚未补验的项目计为本次已通过。
- 不在起草阶段实施产品代码、打包、发布或归档；不借本次改造宣称已修复所有历史模态框的窄窗问题。

## 保真度边界

结果核实、刷新和核对只走现有读取/内存登记通道，零模型/工具调用、零 trace/blob/source 写入。普通 result replay 仍按既有 world-free/工具策略处理：pure 工具沿用原保证，真实副作用和外部状态仍为 best-effort，不宣称隔离。隔离创建/续跑仅在显式授权的文件副本中执行，整轮结束检查点、前缀零调用、不回写源目录保持不变。prompt/A-B 从头执行；代理 messages 仅重发单个模型请求，不恢复外部 Agent 的工具和工作区。退出应用或收起状态视图不等于上游取消或外部副作用回滚。
