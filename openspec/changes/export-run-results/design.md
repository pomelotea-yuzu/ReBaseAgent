# R2.1 设计：结果导出

## Context

能力基线为 U8 归档后的 `87a73b3`，本次修订 HEAD 为 `7f65acd`。源码依据：`packages/replay/src/workspace/read-api.ts` 的 `locateWorkspaceSnapshot` 只读当前 run 自有 JSONL，`readWorkspaceFile` 再验证附件；`apps/desktop/src/main/run-lineage-read.ts` 的 `readRunLineage` 承担桌面父链读取与完整性分类。前者不校验父链，不能把两层事实混为包层前置。`WorkspaceFile` 只记录逻辑路径、字节数和 SHA-256，没有权限、时间戳、链接身份或空目录信息。桌面文件页已有检查点选择但禁止导出入口，本 change 通过 MODIFIED 明确允许导出，并保持原阅读工具的资格。

## Goals / Non-goals

目标是把一个已校验的初始或本 run 自有完成检查点复制到新的空目录，并提供可审计清单和可选文本补丁。导出过程只读历史事实，不放宽隔离执行门禁，不建立第二份 workspace 真相源。Non-goals 以 proposal 为准，尤其不实现应用补丁、合并和 R3 测试。

## Decisions

### D1. 导出边界与 API

包层新增 `exportWorkspaceSnapshot`，输入为 `dataDir`、`runId`、可选 `stepSpanId` 和调用方已选定的 `targetDir`。缺省 step 表示本 run 初始快照；指定 step 必须是该 run 自有且带 `workspace_snapshot` 的 `agent.step`。API 先固定本次选定/初始清单，再逐条验证选定快照全部附件；其中任一缺失、损坏或真实 I/O 错误都使整次文件导出失败。固定快照后不得因逐文件重新解析而拼接不同读取时点的清单。

API 不接受物理 blob 路径、source 根、任意快照对象或单文件 path 选择；非法请求、普通无 workspace run、祖先步骤和损坏当前 trace 返回结构化失败。包层不读取父链、不识别桌面 ownOnly，不以父文件缺失否定自足的自有快照。桌面首期仍采取完整来源策略：main 在目录选择返回后、一切目标写入前，复用 `readRunLineage` 及既有稳定拒绝码，ownOnly 返回 `RUN_LINEAGE_INCOMPLETE`，其他读取错误返回 `RUN_DETAIL_UNREADABLE`。使用导出专用受控提示，不直接透传 `checkRunSource` 中“父本不能执行”的文案，不修改其原执行语义。目录对话框前的检查只用于早期反馈，不能替代写入前重验。

这是明确的桌面策略差异：ownOnly 自有文件仍可读，本轮桌面不允许导出；包层只保证自有快照字节正确，不证明父链完整。当前 run 无须正常完成或封存，只能使用已落盘检查点；读取器针对祖先封存的既有关系校验保持不变。

### D2. 目标目录和失败清理

main 通过原生目录选择能力让用户选择目标目录；renderer 请求只携带 run/step 身份，不能自行写路径。入口先确认本次检查点、空目录要求、`files/` 布局和未保留状态，再打开原生对话框；取消确认或目录选择均零写入。对话框标题明确这是导出材料的目标目录，最终选择视为本次目标写入意图，无二次隐式目标替换。

包层校验目标存在、为空且为普通目录（目标本身的 symlink/junction 拒绝），按解析后的路径排除与 dataDir 相同或互为祖先后代的目标。逻辑路径合法性不能替代 Windows 物化校验：不受宿主支持的名称/长度应在写入前明确拒绝，不静默改名。目录返回后、实际写入前重新检查为空，并排他创建 `files/`；同目标竞争者失败而不清理获胜者产物。普通文件和元信息均用排他创建，不覆盖碰巧出现的条目。不能仅凭“之前为空”信任后续路径。

写入采用“清单最后完成”顺序：物化 `files/` 文件树并复核目标字节，写适用补丁，最后完整写入/关闭清单后才返回成功。清单存在本身不证明成功，读取者仍需解析并核对清单及字节。每次登记自己创建的文件、临时文件和目录，失败时按逆序仅清理仍可确认属于本次请求的条目；空目录用非递归删除，不递归删除用户选定根。并发出现或替换的未知条目保留并报告清理不完整，禁止仅凭记录过同名路径就删除。

正常捕获到的写入故障应完成上述清理；清理失败保留原始诊断及残留相对路径。进程崩溃/断电无法承诺 finally 清理，重启不自动继续写入、补清单或递归清理目标；残留目录视为非空，用户选择新空目录重新导出。重复请求不登记主动 operation，但 main/renderer 各自需要导出在飞保护，不能重发已经开始的写操作来“重试读取”。

### D3. 导出清单

布局固定为 `target/files/<逻辑路径>`、`target/rebaseagent-export.json` 和适用的 `target/changes.patch`。项目原有的 `files`、`changes.patch`、`rebaseagent-export.json` 等路径全部进入 `target/files/`，不占用元信息命名空间。界面明确带回原项目的是 `files/` 中的文件树。清单 JSON 使用 `format_version:1`，至少包含：

- `source`: `run_id`、`step_span_id|null`、`snapshot_id`、`initial_snapshot_id`；
- `files_root:"files"` 与 `files`：每条成功物化文件的逻辑 `path`（相对 files_root）、`bytes`、`sha256`、`kind`（`text`/`binary`）和固定 `status:"exported"`；后者保留并由 schema 钉死。选定附件缺失/损坏整批失败，不生成假成功条目；
- `unpreserved`：权限、可执行位、时间戳、链接关系、空目录、外部服务六类，当前记录能力均标明“未保留（原状态未知）”，不凭当前源目录或操作系统默认值推断历史；
- `patch`：`status` 为 `written`、`no_text_changes` 或 `not_available`，`file` 仅 written 时为 `changes.patch`，记录补丁文件 bytes/sha256、覆盖路径与逐路径排除原因（binary/deletion/baseline_missing/baseline_corrupt/baseline_io）。补丁部分覆盖时明确清单说明，不称全部变化已覆盖；
- `created_at` 只表示导出动作时间，不被解释为源文件时间戳。

源目录绝对路径、凭据、messages、工具参数和未由快照记录的历史不得写入清单。文件和补丁路径按 UTF-16 代码单元序排列。除 `created_at` 外字段及序列化顺序确定；测试注入固定时钟核对完整 JSON，不同动作时间的真实导出只排除 `created_at` 后比较，不宣称跨次 JSON 全字节一致。空快照成功导出空 `files/` 和空 files 数组，patch 为 `no_text_changes`。

### D4. 文件物化与文本补丁

已校验的文件按逻辑路径映射到 `files/` 中，只复制普通文件字节、不创建链接。补丁始终以本 run 初始快照为基线；同路径双方附件验证成功且是严格 UTF-8 文本才生成修改，初始合法清单确认路径不存在且选定侧是已校验 text 才生成新增（旧文件头 `/dev/null`）。这是可证实的不存在，不能用 missing/corrupt/I/O 失败代替空侧。

R1 固定 file-tools-v1 无删除操作，首期补丁范围固定为文本修改和新增。若读取的两份合法清单显示删除，清单逐路径标为 deletion，补丁不覆盖该项；不声称 unified diff 不能表达删除，也不以“空侧无法验证 UTF-8”解释。选定快照所有附件必须可验证；仅为补丁需要的初始附件缺失/损坏/I/O 失败时，文件物化仍可成功，但整个 patch 为 not_available，列明路径与原因，不生成看似完整的部分补丁。二进制变化和合法删除可排除并生成其余可验证文本补丁，反馈覆盖范围。

补丁使用仓库内纯 TypeScript 实现，不新增 diff 依赖。采用 unified diff，固定三行上下文，文件头为 `a/<逻辑路径>` 和 `b/<逻辑路径>`，新增旧头为 `/dev/null`。控制行用 LF；内容行保留原文件 CRLF/LF 和末尾是否换行，缺少末尾换行使用标准说明行，不以换行规范化掩盖字节差异。路径含需要转义的字符时采用确定的引用/转义，完整文件树仍原样保留路径。生成工作量须有上限，超限将整个 patch 标为 not_available，完整文件导出仍可用；任务 3.3 固定具体限制并测试。

没有变化时 patch 为 no_text_changes；有变化但全部为二进制/删除等未覆盖项时为 not_available。只有 written 才写补丁文件并显示“补丁已生成”，同时提示其覆盖范围。补丁是审阅材料，不承诺自动应用；生成/落盘补丁遇到目标 I/O 错误仍使本次导出失败并清理。

### D5. IPC 与界面

新增 `workspaces:export`，沿用统一 IPC 信封和严格请求 schema，renderer 只传 `runId`、可选 `stepSpanId`，任何额外 dataDir/source/blob/targetDir 等键均拒绝。main 注入 dataDir，负责对话框和 D1 的完整来源检查，再调用包 API；取消结果独立于失败。成功返回实际目标目录、`files/` 位置、文件数/总文件字节数（不包含元信息）、补丁状态及未保留说明；不传回文件正文或凭据。失败用导出语境的受控诊断及残留相对路径。导出不登记主动 operation、不消费授权、不改变当前 run/检查点/路径/滚动/比较选择/草稿。

导出入口的资格取决于已核实当前 run/自有检查点及桌面完整来源，不取决于选中文件、Monaco 是否挂载、diff 有无变化或文本两侧是否可比较。合法二进制、无变化、初始快照、空快照都可以导出。当前已知选定附件不可用或检查点尚未读取时说明原因；main/包层提交时复验所有附件，UI 不宣称按钮可用就等于全部字节已核实。

同会话导出中冻结重复入口，保留其他阅读行为。反馈绑定提交 run/step 和请求代次，切对象后旧响应不得覆盖新页面 loading/结果或抢焦点；离开不取消 main 文件写入，后台响应保存在 renderer 对应提交目标的会话状态，返回时可查看，不新增回执查询 IPC。重载后失去反馈则明确结果未知、检查目标清单，不能自动重发。同一 main 中在飞保护不因 renderer 重载消失。完成显示目标目录、files/、数量/字节、补丁覆盖与未保留说明；成功只表示结果材料已导出，不表示项目可运行、测试通过或已应用。

### D6. 测试与证据

任务 1.1 先建立 evidence-index 骨架，按 delta 全部场景逐项标待实施，实施过程逐批回填。包层单测覆盖快照自身校验、缺父但自有快照可导出、空快照、文件名冲突、目标竞争、固定时钟、文本新增/修改与补丁排除、基线附件缺失、写入/清理失败和进程中断。main/IPC 测试覆盖 ownOnly、目录对话框期间父链变化、恶意额外字段、重载/重复请求、回执守卫、零 operation 和 dataDir 保护。Electron 验证目录选择、成功/失败反馈、阅读状态、窄窗/200%/真键盘及复制/查找/差异导航原场景回归；未知或不可实机诱发的情形如实分层。

## Risks / Trade-offs

- 目标目录的写入会被进程中断打断：只有完整且可验证的清单与文件才是可用材料，记录残留行为，不承诺断电自动回滚。
- 快照不含空目录、权限和链接信息：不尝试猜测或复制当前源目录，统一进入清单未保留状态。
- 大文件和大量文件会占用磁盘：复用既有快照配额，并在 API/界面反馈实际数量和字节；不在本 change 引入压缩或上传。
- 文本补丁算法不是项目构建验证：保持补丁只读、确定、可审阅，R3 才负责测试和构建证据。

## Migration Plan

无需迁移既有 JSONL、blob 或 workspace。新 IPC/清单格式只由本 change 新增；旧 run 继续按现有文件页读取。实施完成后先跑包层和桌面定向测试，再做 Electron 真实目录/键盘/窄窗验收，最后执行全仓门禁和 OpenSpec strict；未归档前不修改主 spec 或发行包。

## Open Questions

- 目录选择是否在 Windows 原生对话框中提供“新建文件夹”按钮由 Electron 平台行为决定；契约只要求最终目标是用户明确选择的空目录，若平台不能选择新建目录则 UI 给出创建后重试的明确提示。
- 无阻塞的范围问题；补丁的工作量上限作为任务 3.3 的实现常量需留证据，不能通过无限算法消耗阻塞完整文件导出。三行上下文、文件头、新增空侧和状态枚举已固定于 D3/D4。
