# R2.1：结果导出

## Why

U1–U8 已经让用户能够定位一次运行、查看自有文件检查点、比较修改前后结果并核实执行结局，但当前文件工作区仍然只能只读浏览。用户确认修复有效后，无法把选定检查点带回原项目或交给同事复核。路线规划将“结果带出”列为 R2.1，且明确先交付导出，不把自动应用或合并混入本阶段。

能力基线为 U8 归档提交 `87a73b3`；2026-10-05 修订时 HEAD 为 `7f65acd`，两条测试基础设施欠账已销账。现有 `packages/replay` 已有按 run、自有完成步骤和逻辑路径读取并校验 workspace 清单及 blob 的接口；现有桌面文件页已有检查点、文件状态和文本差异视图。本 change 在这些只读事实之上增加一个受控导出路径。

## What Changes

- 新增包层 workspace 检查点导出 API：按 run 与本 run 自有检查点定位快照，重新校验清单、附件长度和 SHA-256 后，将普通文件字节物化到用户选定的空目录。
- 固定导出布局为目标目录下的 `files/`（普通文件树）、`rebaseagent-export.json`（清单）和适用的 `changes.patch`（补丁）。项目即使有同名文件也原样存入 `files/`，不会与导出元信息冲突。清单记录导出版本、来源 run/step、初始基线、快照 ID、文件路径、字节数、哈希和未保留状态；不记录源目录绝对路径、凭据或消息正文。
- 相对本 run 初始快照生成确定性的 `changes.patch`：同路径双方经字节校验且为 UTF-8 文本时支持修改；初始清单确认不存在且选定侧是已校验 UTF-8 文本时支持新增。二进制和删除不生成文本补丁，逐路径列明未覆盖原因；缺失/损坏的基线附件使补丁整体不可用，但不阻止完整选定快照的文件导出。
- 桌面文件工作区提供“导出选定检查点”入口。main 先检查输入，再通过原生目录选择取得目标；选择返回后重新验证父链完整性并调用包层 API。包层只校验当前快照、附件和目标，不新增父链读取。桌面来源不完整时拒绝；合法二进制、空快照、无文本差异或 Monaco 未就绪都不阻止独立文件导出。
- 导出完成后反馈实际目标目录、文件数、字节数和补丁状态；失败只清理本次请求创建的内容，不改源目录、trace、blob、父/兄弟运行或阅读状态。

## Capabilities

### New Capabilities

无新增 capability 目录。

### Modified Capabilities

- `workspace-isolation`：增加从已校验初始/自有完成检查点生成独立导出材料的契约，明确状态保真边界和失败清理。
- `desktop-ui`：允许文件工作区导出选定检查点，补充目录选择、状态反馈和只读边界。

## Impact

主要影响 `packages/replay/src/workspace` 的导出与文本补丁逻辑、`apps/desktop/src/main` 的目录选择和导出编排、`apps/desktop/src/shared`/preload 的请求与结果 schema、`WorkspaceFileView` 和 store 的入口及结果反馈。复用现有 workspace 读取/校验、Electron 原生目录选择、统一 IPC 信封和草稿/阅读状态；不新增依赖，不改 JSONL、blob 布局或 trace 版本。

导出 API 接收由 main 选择并校验的目标目录；renderer 不获得 fs 权限，也不提交物理 blob 路径或数据根。目标不得与 dataDir 相同或互为祖先后代；包层不读取原源目录。桌面完整性策略复用 main 的 `readRunLineage` 分类，ownOnly 的自有文件仍可按既有规则阅读，本次桌面导出明确要求完整来源；包层 API 自身不承诺来源链可追溯。导出不占主动执行槽、消费 sourceToken、发起模型/工具调用或产生新的 run，但属于对用户所选目标的显式文件写入，需单独防止重复提交和输出冲突。

## Non-goals

- 不提供自动应用补丁、覆盖源目录、合并分支、删除文件或回写既有项目。
- 不导出或恢复权限、可执行位、时间戳、符号链接身份、空目录、外部服务、网络、数据库、RAG 或其他 R1 快照未记录的状态；这些状态必须在清单中标为“未保留”或“未保留（原状态未知）”。
- 不支持从普通无 workspace run、祖先步骤、清单外路径或缺失/损坏的选定附件猜测并导出内容。桌面不放行不完整父链；包层不重复读取父链或从父链补快照。
- 不把二进制、missing、corrupt 或未校验的空侧伪装成文本补丁；仅初始合法清单证明不存在的新增路径可以用 `/dev/null` 表示初始侧。不引入通用评分/项目测试执行能力。
- 不修改 workspace 快照、共享 blob、JSONL 或源目录，不新增隔离 prompt/模型实验、Shell/真实测试（R3）、取消、队列或跨运行文件导出。
- 不在本 change 中打包、发布或宣称 R2.1 已进入发行物；实施前只完成方案和可验证任务拆分。

## 保真度边界

导出只复制已校验 workspace 快照引用的普通文件字节，在 `files/` 下保留逻辑路径、字节、大小和 SHA-256；不复现 Agent 消息、工具副作用、运行时环境或快照之外的文件系统状态。文本补丁表达初始快照与所选检查点的可验证文本修改和新增，清单逐路径列出二进制、删除等未覆盖变化；基线附件不可用时仅文件导出完成，补丁不生成。导出不证明项目可构建、测试通过或完整恢复。

导出只读取历史事实，不执行 replay：不重放消息、不调用模型、不执行工具、不读取当前源目录、不使用外部服务。导出材料写入是唯一副作用，必须限定为本次请求选定的空目录且排除 dataDir；不自动回写原项目。父本、兄弟运行、JSONL 和共享附件保持不变。

## 验收口径

以 R1/C 已有隔离 fixture 验证根 run 与分支 run 的初始/自有完成检查点、文本/二进制/新增文件、失败运行已落盘快照、缺失或损坏附件、非空目标目录和路径越权。每个成功导出逐项比较清单、文件字节、大小和哈希，并对源目录、父/兄弟运行、trace/blob 做指纹核对；失败场景验证无半成品残留。桌面验收覆盖真实目录选择、取消、窄窗、200% 缩放、纯键盘、导出后反馈和阅读位置保持。规划材料完成不等于功能交付，实施后还须补测试、实机证据、OpenSpec strict 和归档记录。
