# ReBaseAgent 参赛视频完整分镜草案 v0.1

> 日期：2026-09-26
> 用途：供用户一次审阅整条视频，再集中讨论修改。
> 状态：纯内容与分镜设计，没有制作网页、录屏、动画或视频，没有调用模型。
> 依据：[讨论记录](2026-09-26-remotion-video-discussion.md)。不参考旧参赛视频方案。
> 已确认的主题与表现形式沿用讨论结论；本文新增的精确时长、字幕、镜头和转场均为提案，不视为已获确认。

## 1. 全片主线

从“反复说不对，再改”，走到“看清过程、验证改动、保留测试”。

开场提出问题，三个案例分别回答：

1. **为什么会改错？** 查看 Agent 的输入和工具调用，修正规则，隔离续跑。
2. **换一种方案会怎样？** 用同一份资料比较模型，再固定模型修改提示词。
3. **以后改了运行配置，流程还能走通吗？** 用录制卡带检查当前运行时，展示配置不兼容。

全片以参赛的核心功能和使用流程为主，保留 B 站观众熟悉的番剧情境。无配音，依靠音乐、短字幕、真实操作和少量原理动画讲清楚。

## 2. 参考时间轴

草案约 **8 分 50 秒**。这是为了检查结构是否完整给出的节奏样本，不是最终时长承诺；等待模型生成的时间不等于成片长度。

| 时间 | 段落 | 观众要理解的内容 |
|---|---|---|
| 00:00–00:22 | 问题开场 | 不断要求重改，却不清楚 Agent 哪一步出了问题 |
| 00:22–00:54 | 产品亮相与能力概览 | ReBaseAgent 是什么，四组核心能力有哪些 |
| 00:54–01:12 | 先看案例一的错误结果 | 追平连载不等于看完整部作品 |
| 01:12–01:35 | 简短交代任务如何启动 | 内置引擎、模型配置、隔离文件运行 |
| 01:35–03:55 | 案例一：排查与隔离续跑 | 输入规则影响输出，修改上下文后可以开分支验证 |
| 03:55–06:25 | 案例二：模型和提示词实验 | 同条件比较模型，再固定模型改变提示词 |
| 06:25–07:50 | 案例三：卡带回归 | 不调用模型，也能检验录制流程与当前运行配置是否兼容 |

入门操作放在第一个错误结果之后，用一句“这次任务是这样开始的”短暂回顾，避免一开场就进入设置教学。手册承担未来的详细教程。

## 3. 画面与声音的统一约定

### 三种画面各自承担什么

- **真实界面与操作**：ReBaseAgent、独立番剧演示页、命令行，作为功能证据。
- **单独设计的示意**：隔离文件分支原理、卡带响应来源，短暂解释运行方式，标注“原理示意”。
- **编辑包装**：开场重复文字、倾斜上滑、放大标注、章节名称、片尾。不得伪装成软件已有功能。

### 视觉建议

- 横屏 16:9 作为本稿构图假设，最终分辨率与帧率尚未确定。
- 主体沿用 ReBaseAgent 现有界面基调，正文演示保持正视角。
- 只有开场能力概览使用整组轻微倾斜上滑，画面与说明一起运动。
- 案例一前后对比固定同样的页面尺寸、排序和卡片位置，方便观察是否被过滤。
- 普通操作以界面为主，只对关键区域放大；不长期展示文字无法阅读的全桌面。
- 每次只突出一个判断点。完整句子的字幕通常留 4～7 秒，长文对比给更长停留。
- 原分支、新分支使用稳定标记与文字标签，不只靠颜色区分。
- Logo 配色调整是后续任务；本稿不指定新色值，最终品牌画面采用确认后的版本。

### 声音建议

- 无人声、无配音，也不添加合成旁白。
- 开场音乐逐渐加紧，在问题出现时短暂停顿或收弱。
- 操作演示采用稳定、低干扰的音乐，读文案时降低密度。
- 可少量加入切换、停顿、确认的轻音效，具体试听后决定；不使用持续打字声抢注意力。
- 转场与节奏服务于阅读，不要求所有镜头都卡音乐节拍。

## 5. 案例一：追平了，怎么就算看完了

### 先展示错误，再短暂回顾启动路径

| 镜头 | 时间 | 画面与动作 | 屏幕文字草案 |
|---|---|---|---|
| B01 | 00:54–01:03 | AniBox 风格的独立番剧页，卡片上可见总集数、更新集数与观看进度；点击“未看完”，目标卡片消失 | 只想找一部没看完的番。 |
| B02 | 01:03–01:12 | 局部放大消失前的卡片信息，以回看或前后定格呈现，不虚构网页有此特效 | 全 12 集，更新 6 集，已看 6 集。／追平了，怎么就算看完了？ |
| B03 | 01:12–01:24 | 简短回顾打开 ReBaseAgent、进入模型配置；显示服务与模型，密钥不出现 | 这次任务，使用内置 Agent 引擎。 |

AniBox 与 AniPedia 仅作参考，不对它们的工程或数据作修改。本例使用单独准备的演示目录。

### 观察与定位

| 镜头 | 时间 | 画面与动作 | 屏幕文字草案 |
|---|---|---|---|
| B05 | 01:35–01:52 | 回到已有错误运行的轨迹，按读文件、模型调用、写文件顺序突出真实节点 | 先看过程：读了什么，随后改了什么。 |
| B06 | 01:52–02:12 | 打开规则文件的读取结果，框选错误规则，再短暂关联到生成的筛选代码 | “已看集数达到已更新集数，就算看完。”／这条规则，把追平当成了看完。 |
| B07 | 02:12–02:24 | 打开实际的 Token 预算分布，突出本次上下文中的主要占用 | 这次调用，Token 用在了哪里？ |

不把“理解规则”画成产品不存在的独立 span，也不宣称观察到了模型内部思考。原因归纳必须能由实际输入、输出支持。

### 单独设计的隔离续跑示意

| 镜头 | 时间 | 画面与动作 | 屏幕文字草案 |
|---|---|---|---|

示意不画出虚构的“任意时间点撤销”。沿轨迹的节点应是轮次检查点，不是任意工具操作。末尾新分支的视觉标记与随后真实界面的新运行对应。

### 修改、续跑、验证

| 镜头 | 时间 | 画面与动作 | 屏幕文字草案 |
|---|---|---|---|
| B09 | 02:44–03:02 | 切回真实界面，修改选中步骤的工具结果，突出规则变化 | 追平不等于看完。／尚未完结或仍有未看集数，都保留。 |
| B10 | 03:02–03:18 | 展示只读预检、核对父运行与轮末检查点、确认副本写入并续跑；等待区间可明确标注加速 | 修正这次输入，创建新的续跑分支。 |
| B11 | 03:18–03:30 | 查看实际续跑调用的 Token 与缓存统计；若无缓存命中，如实展示当前结果 | 新分支实际调用与用量。／缓存命中以本次返回为准。 |
| B12 | 03:30–03:43 | 查看检查点、选择修改的文件、放大筛选条件的 diff；必要时用两个真实视图剪辑对照 | 检查文件到底改了哪里。 |
| B13 | 03:43–03:55 | 在浏览器展示修正结果，同样点击“未看完”，目标卡片保留；已看完的作品被过滤 | 追平的留下，看完的过滤。 |

镜头 B09 编辑的是模型本次接收的工具返回内容，不自动修改原始规则文件。真实功能操作和说明不能让观众误认为两者等价。

镜头 B12 按实际 UI 能力选择拍法：若文件视图只提供相对初始检查点的差异，就分别展示各分支视图再剪辑对照，不伪造原生“任意两分支文件直接 diff”功能。

页面效果由演示者打开检查。内置文件 Agent 没有替观众自动打开浏览器、执行测试的镜头。结果必须由实际演示生成；若链路不稳定，回到案例设计调整，不用后期伪造成功。

## 6. 案例二：同一份资料，两种模型，再改一次提示词

过渡文案：**“问题找到以后，还可以比较不同方案。”**

### 任务与比较条件

- 作品：《无职转生》。先选定明确的作品或季度范围，避免混合不同季的内容。
- 观众：没看过这部作品的普通观众。
- 资料：一份固定、简短的作品资料，两个模型完全一致。
- 提示词草案：150 字以内、不剧透、少用术语、说明前提与看点、不编造资料外信息。
- 模型：用户选择的 DeepSeek V4.1 Flash 与 V4 Pro，经 DeepSeek 官方接口调用。官方可用名称与 API 标识待核实，不为补齐镜头擅自替换型号。
- 不宣布赢家，不使用“最佳模型”或自动评分式包装。
- 此处是单独的普通运行，不从案例一的隔离父本直接进行模型 A/B 或 prompt fork。

| 镜头 | 时间 | 画面与动作 | 屏幕文字草案 |
|---|---|---|---|
| C01 | 03:55–04:10 | 简单的任务画面：《无职转生》名称、精简资料和三项要求依次出现，再切回软件 | 同一份资料。／写给没看过它的人。／不剧透，不编造。 |
| C02 | 04:10–04:27 | 新建普通运行，展示同一资料与提示词，建立实验父本；不重复完整配置教学 | 固定资料与任务，建立比较起点。 |
| C03 | 04:27–04:46 | 真实 A/B 编辑器中展示两个模型，保留计划预览与调用确认，再执行；实际等待可加速 | 这一次，只改变模型。 |
| C04 | 04:46–05:12 | 并排展示两个真实输出，使用可读字号和固定栏宽；不同时铺上复杂数据图 | 两个模型，两份推荐文案。 |
| C05 | 05:12–05:34 | 从真实结果中选择两三处差异，依次放大，不把全文和所有批注同时塞满屏幕 | 它怎样介绍故事？／看点是否具体？／是否使用了资料之外的信息？ |
| C06 | 05:34–05:46 | 展示两次运行的 Token、耗时等真实数据，数字单位清楚 | 输出之外，也看看这次运行的用量与耗时。 |
| C07 | 05:46–06:02 | 选定其中一个普通运行，固定模型，修改启动提示词，创建从头运行的新分支 | 模型不变。／增加一条要求：少用抽象赞美，多给具体看点。 |
| C08 | 06:02–06:25 | 展示提示词改动，再并排看同一模型修改前后的文案；若未达到要求，也如实指出 | 同一模型，新的提示词。／这次，结果发生了什么变化？ |

完整文案并排时，若阅读仍然吃力，应增加停留或减少非核心包装，不靠缩小字号硬塞。第一次看全貌，第二次放大差异，两次各有目的。

模型名称用实际服务名称，数据只代表本次实验，不外推成稳定性能排名。不同模型 Token 计数口径可能不同，不能仅凭 Token 数判断质量或费用；本稿不规划未经核实的金额比较。

提示词分支从头执行。画面与文字应与案例一的“从检查点隔离续跑”明确区分。字幕对文案的观察由演示者完成，不伪装成 ReBaseAgent 内置自动评审。

## 7. 案例三：把一次运行留下，检查后续流程

过渡文案：**“运行结束以后，这份记录还能做什么？”**

本例使用独立演示配置与兼容的已封存 trace，镜头中的记录必须与实际输入对应。能否沿用前面某个案例的记录需验证；不预先承诺它们无需准备即可直接作为基线。

| 镜头 | 时间 | 画面与动作 | 屏幕文字草案 |
|---|---|---|---|
| D01 | 06:25–06:37 | 从一份真实运行记录切到简单原理示意：录制的模型响应与工具结果进入当前运行时，产出测试报告 | 复用录制响应，检查当前运行流程。／本次回归不调用模型。 |
| D02 | 06:37–06:55 | 显示实际测试定义的关键要求、运行配置与一条命令，执行后放大通过结果 | 原配置下，流程完成。 |
| D03 | 06:55–07:07 | 仅展示独立配置中 maxIterations 的变更，例值按基线轮数确定，不修改产品源码 | 如果把运行轮数上限调低…… |
| D04 | 07:07–07:28 | 执行相同命令，突出真实的卡带剩余报告；短示意显示流程停住而记录还有后续 | 提前停止，录制内容尚未消费完。／配置与录制不兼容。 |
| D05 | 07:28–07:40 | 恢复配置，执行后再次通过 | 恢复配置，再次通过。 |
| D06 | 07:40–07:50 | 三次结果并列回看，用文字标记通过、不兼容、通过；命令行入口旁短标可接 CI | 留下运行记录，持续检查运行流程。 |

命令在准备好实际 fixture 与 config 后填写，不在镜头中使用未运行过的假输出。测试定义文件、trace 和配置模块要在说明上区分清楚。

这里的中间结果是配置错误，当前 CLI 对应 exit 2，不是断言失败的 exit 1。屏幕采用“配置不兼容”标签，避免用一个笼统红色 FAIL 模糊语义。

卡带冻结模型响应，工具使用录制结果。本段不宣称检查新模型质量、验证真实工具实现或保证番剧业务逻辑正确。可以展示命令可接入 CI，但不虚构尚未运行的远端流水线成功截图。
