## 1. 视频用途与优先级

- 主要用途：参加上海开源软件应用创新大赛，赛道为开源 AI 工具中的调试与可观测工具方向。名称按用户口述记录，正式提交时再核对官方写法。
- 参赛视频需要展示作品的核心功能和使用流程，通过视频链接提交。
- 发布平台：B 站，同时作为 ReBaseAgent 的初期宣传视频，一条视频兼顾参赛与宣传。
- 用户目前未获知比赛有明确的视频时长要求。
- 展示完整性以参赛需求为主，兼顾首次接触产品的 B 站观众。

## 2. 产品定位与表达

允许参考 `docs/` 中的产品定位、架构和使用说明，但不参考此前的视频规划。

现有产品文档将 ReBaseAgent 定位为“本地优先的 Agent 调试、实验与测试平台”。用户说明，产品之初就面向类似方向，因此看到比赛的调试与可观测工具赛道后报名。

本轮讨论形成的表达方向：

- 以“Agent 调试与可观测工具”为视频主线，与产品方向和参赛赛道一致。
- 先让观众看清 Agent 的运行过程，再展示如何定位问题、修改上下文、重跑和比较结果。
- 实验与测试能力纳入整体展示范围，分别由第二个文案实验案例和第三个卡带回归案例承担。
- 候选价值表达：“让 Agent 的运行过程看得清，出了问题能调试，做了修改能验证。”这仍是讨论稿，不是最终宣传文案。
- 功能和边界应按当前实现核实，历史产品文档中的路线图不能直接当作现有能力。

## 3. 制作流程与当前阶段

Remotion 用 React 组织画面，以时间轴控制动画，并把文字、产品画面、录屏、图片和声音组合、渲染成视频。

本轮讨论采用的制作流程：

1. 明确目标、观众、发布渠道和展示范围。
2. 确定核心信息与叙事结构。
3. 编写脚本和分镜，安排画面、文字、操作与时长。
4. 准备产品素材、示例数据、音乐，确定关键画面的视觉设计。
5. 用 Remotion 制作动态初稿。
6. 预览并调整内容、节奏、可读性、动画和音画配合。
7. 经后续确认后渲染、验收和交付视频。

当前处于前期讨论阶段。此前按用户要求逐题讨论；最新要求是加快讨论，先整理完整方案供整体审阅，再继续调整，不再逐个询问细节。最新完整草案见 [完整分镜草案 v0.1](2026-09-26-remotion-video-storyboard-v01.md)。

## 4. 已确认的表现形式

- 不录音、不加配音，采用背景音乐与画面文字讲解。
- 风格以简洁清晰的产品演示为主，加入少量轻松表达。
- 可用局部放大、重点标注、步骤文字、修改前后对比辅助理解。
- 轻松文案示例：“追平了，但没看完啊。”仅为候选，不是定稿。
- 关键操作需要留出阅读和观察时间，不能用过快的切换代替解释。
- 精确分辨率、画幅、帧率、音乐、字体和最终视觉规范尚未确定。

## 5. 视频结构与时长

### 用户明确提出的调整

最初建议的 2～3 分钟被用户认为过短：ReBaseAgent 的功能不止一个案例所覆盖的部分，参赛展示需要更完整，B 站也能容纳长视频。

因此不以短宣传片为前提压缩内容，应先确定功能和案例，再决定总时长。

### 用户提供的结构示例

用户强调“举例，不一定要这样”，以下作为候选结构保留：

1. 开场用快速切换的画面介绍软件有哪些核心功能。
2. 中段通过几个具体案例展示使用过程。
3. 结尾简要列出未在案例中出现的小功能。

讨论中补充的建议：

- 开场快切使用真实产品界面与简短标题，负责建立整体印象。
- 不同案例承担不同功能的讲解，避免多个案例重复展示同一过程。
- 结尾可补充开源信息、项目地址及相关项目链接。

“6～10 分钟”仅是后续提出的体量建议，用户尚未确认，不能视为目标时长或上限。最终长度取决于功能范围、案例数量和无配音情况下的阅读时间。

### 后续讨论形成的内容顺序

1. 问题开场：反复出现“不对，再改”，引出 Agent 执行过程为什么需要调试。
2. ReBaseAgent 名称与真实界面出现，快切展示核心能力。
3. 简短交代打开软件、配置模型、新建运行的必要路径。
4. 案例一：番剧筛选错误的观察、定位、上下文修改与隔离续跑。
5. 案例二：《无职转生》推荐文案的不同模型对比，以及同一模型的提示词分支实验。
6. 案例三：Trace-as-Test 卡带回归的通过、不兼容和恢复通过对照。
7. 补充未在案例中自然出现的辅助功能。
8. 展示开源仓库，邀请观众前往了解、下载和反馈。

用户明确：入门步骤简单带过，详细使用教程留给未来手册；本视频不逐项讲解所有设置。

### 问题开场的方向

用户希望问题足够吸引注意。讨论后放弃“某一步错了，为什么从头再来”的提问方向，采用反复反馈却仍改不对的情境。

画面反复多次出现“不对，再改”，逐渐叠加，随后停住，出现：

> Agent 一直改不对。
>
> 它读到了什么？执行了什么？究竟哪一步出了问题？

随后切入 ReBaseAgent 的名称与运行轨迹，进入能力快切。具体次数、排版、停顿与衔接在完整分镜草案中给出建议，仍可修改。

后续确认的开场画面：

- 使用文字叠加与代码修改画面，不使用聊天界面。
- 代码取自后续番剧筛选演示页，让开场与案例产生关联。
- “不对，再改”反复出现并逐渐叠加，代码修改逐渐加快，最后停住。
- 这一段属于情境化表现，不冒充真实录制的多次模型失败。
- 可将“究竟哪一步出了问题？”留作停顿时的主问题，让“它读到了什么、执行了什么”与随后真实节点对应。

### 已确认的能力快切动效

- 软件画面与简短描述作为一组，整体保持轻微倾斜。
- 从下方向上滑入，到中央时减速并短暂停留，再继续向上离场。
- 下一项顺势进入，形成连续运动，不做完全静止的功能幻灯片。
- 暂按运行观察、修改续跑、模型与提示词对比、卡带回归四项设计。
- 用户确认画面与描述统一倾斜；具体角度、速度、停留时间等到实现预览时调整。
- 进入正式案例后恢复正视角，以便阅读界面内容。

用户专门提出了开场与产品能力是否匹配的问题，后续表达须保留以下边界：

- ReBaseAgent 帮助观察和干预 Agent 的执行过程，不是自动判断和修复所有错误代码的通用纠错器。
- 番剧案例展示的是“错误规则进入上下文后影响 Agent 修改代码”，由开发者发现并修正规则。
- 不保证修改上下文后必然成功，实际效果需要验证。
- 本次使用内置引擎，不暗示可以直接接管任意 Vibe Coding 软件、回退其操作。

## 6. 演示 Agent 的来源与能力范围

用户已确认先使用 ReBaseAgent 内置引擎。寻找、接入外部 Agent 属于后续规划，本次聚焦现有能力。

本轮查阅文档和源码后确认的方案基础：

- 项目已有 `agent-loop` 执行引擎。
- 桌面端“隔离文件运行”可使用配置的模型，并提供 `read_file`、`write_file` 工具。
- 可以选择示例目录，让 Agent 读取、修改副本中的文件，并记录运行过程。
- 演示所需准备包括示例文件、任务提示词、规则与数据，以及模型配置。

- 网页效果由演示者在浏览器中查看，不描述成 Agent 自动完成的浏览器验证。

本轮未运行模型或验证完整演示链路；可拍摄版本、实际界面入口与发行包能力仍需制作前核实。

## 10. 第一个案例：追平不等于看完

用户已认可这个案例方向，作为暂定主线。它不是整条视频的全部内容。

### 视频叙事顺序

用户确认采用“先展示错误结果，再回看执行过程”：

> 点击“未看完” → 已追平的连载番消失 → “只是追平，怎么就算看完了？” → 回到 ReBaseAgent 排查。

先让观众理解问题，再展示 Agent 接到任务、读取规则、修改文件的相关记录。以下小节描述任务与调试逻辑，不要求视频从下达任务开始按时间顺序播放。

后续确认的排查顺序：

1. 简短展示“读取文件 → 模型调用 → 写入文件”的轨迹；“理解规则”只作叙事概括，不虚构独立执行节点或模型内部思考。
2. 打开读取规则文件的工具结果，放大错误规则。
3. 用短字幕解释：代码按这条规则写了，但规则把“追平”当成了“看完”。
4. 编辑工具结果并隔离续跑。

### 已确认的独立分支示意画面

在真实隔离续跑操作之前，加入用 Remotion 单独设计的原理动画，不使用软件界面伪装这个示意：

1. 原运行画成一条轨迹，选中一个轮末文件检查点。
2. 从该检查点的文件副本分出新路径，标注“修正规则后续跑”。
3. 原分支保持不动，新分支继续执行并出现修改后的文件。
4. 短说明：“在检查点的文件副本中继续，保留原来的运行。”

画面应区分源目录、原运行与新分支，表达源目录和已有分支保持不变。动画按真实的轮末检查点语义设计，不表示能回退到任意一次文件操作。动画结束后接真实续跑界面。

### 任务

向内置 Agent 提出：

> 给番剧库添加“未看完”筛选，让我能找到还没看完的番剧。

Agent 读取页面代码、番剧数据和规则说明，然后修改页面文件。

### 首次结果中的问题

某部作品全季共 12 集，目前更新 6 集，用户已看 6 集。点击“未看完”后，它被错误隐藏。

观众应能从卡片上的数字理解：用户只是追平当前更新，并没有看完整部作品。

### 可追溯的错误来源

演示样例预设一条不完整的规则：

> 已看集数达到已更新集数，就算看完。

通过 ReBaseAgent 查看文件读取、工具返回内容与文件写入过程，展示 Agent 接收到的规则如何影响修改结果。

这属于预先设计的调试样例，应如实说明，不包装成未经干预、随机遇到的真实故障。

### 调整上下文并续跑

在相应文件读取步骤的工具结果中，将规则澄清为：

> 追平更新不等于看完。尚未完结，或仍有未看集数的作品，都应保留在“未看完”列表中。

利用已有工具结果编辑和隔离续跑能力，让 Agent 根据修正后的信息继续修改代码。

需要准确表达：这里编辑的是该次续跑中模型接收的工具结果，不会自动修改原始规则文件。实际续跑边界、检查点和操作顺序需验证。

### 结果对比

- 在 ReBaseAgent 中查看两个分支的文件差异。
- 演示者分别打开生成的页面，展示实际筛选效果。
- 第一版错误隐藏已追平的连载番；修正版保留它，并过滤真正看完的作品。

案例承担的能力展示：观察过程 → 找到错误上下文 → 修改并隔离续跑 → 对比文件与结果。

### 待验证事项

- 模型能否稳定完成页面修改，并在给定规则下呈现预期的首次错误。
- 修正工具结果后，能否沿当前实现支持的续跑路径产生正确修改。
- 文件差异与网页结果能否清楚对应，便于无配音讲解。
- 文件规模与素材组织是否适合现有隔离文件运行限制。

以上仅为讨论方案，尚未制作页面、调用模型、生成运行记录或录制画面。

## 11. 第二个案例：推荐文案的模型与提示词实验

### 已确认的任务方向

- 作品：《无职转生》，由用户指定。
- 文案面向没看过作品的普通观众，少用圈内术语。
- 根据同一份作品资料生成不剧透的推荐卡片文案。
- 不预设哪个模型获胜，只展示差异，交由观众判断。

讨论中的任务草案：

> 根据提供的作品资料，为没看过《无职转生》的普通观众写一段 150 字以内的推荐文案。说明故事前提、主要看点和适合人群，不剧透关键情节，不堆砌圈内术语，不编造资料之外的信息。

具体资料内容、作品覆盖范围和最终提示词仍需后续细化。

### 模型与调用渠道

- 用户选择的模型名称为 **DeepSeek V4.1 Flash** 和 **V4 Pro**。
- 用户明确使用 **DeepSeek 官方接口**。
- 上述名称按用户选择记录，尚未查询官方当前可用型号、账号权限或 API 模型标识；不代表已验证这些名称可直接用于请求。
- 曾讨论本地 Ollama 的 OpenAI 兼容接入方式，但用户随后选择官方 DeepSeek 接口，因此 Ollama 不作为本案例当前方案。
- 第一例文件 Agent 使用的具体模型尚未单独确定，不自动沿用本节选择。
- 当前没有调用接口或验证输出。

### 第一段：不同模型对比

1. 在普通运行路径中准备相同的作品资料与任务提示词。
2. 为两个模型创建 A/B 实验，展示必要的计划预览与执行操作。
3. 先并排展示完整文案，再放大两三处具体差异。
4. 展示 Token 用量与耗时，说明这些是本次运行的观察结果。

对比关注点：资料是否被准确使用、是否遵守要求、表达是否易懂、看点是否具体。不是自动评分或模型排名；差异根据真实输出选择，不预先安排哪个模型更好。

该案例单独创建普通运行。现有隔离文件运行不支持直接进行模型 A/B 或 prompt fork，因此不把第一个案例的隔离分支直接作为本案例父本。

### 第二段：同一模型修改提示词

用户确认加入提示词分支对比：

1. 选其中一个模型，保持模型不变。
2. 在提示词中增加“少用抽象赞美，多给具体看点”的要求。
3. 创建 prompt fork，**从头运行**，不描述成从中间步骤续跑。
4. 并排比较修改提示词前后的推荐文案。

两个阶段分别改变模型和提示词，便于观众理解差异来源。最终以实际输出为准，不承诺新提示词一定更优。

## 12. 第三个案例：卡带回归的成功与失败对照

用户确认保留一小段命令行操作，配合关键输出放大与文字说明，并加入失败对照。

### 演示流程

1. 用一份已完成、适合卡带回归的运行记录执行测试，正常通过。
2. 在独立演示配置中调低运行轮数上限，使执行提前停止。
3. 再执行相同卡带，展示提前终止、卡带仍有未消费内容的报告。
4. 恢复轮数配置，再次执行并通过。

可概括为“正常通过 → 误调轮数上限后不兼容 → 恢复配置后通过”。无需为演示修改 ReBaseAgent 本身的代码。

### 必须准确表达的能力边界

- 回放使用录制的模型响应和工具结果，不重新调用模型，也不执行真实工具。
- 目标是检查 Agent 运行时对录制流程的处理，不是检测新模型回答是否正确，也不验证工具 handler 内部实现的正确性。
- 这里的负例在当前实现中属于**配置与录制不兼容**：卡带有剩余，命令行对应配置错误，而不是断言失败或模型回答错误。
- “通过”不表示原始文案或业务逻辑必然正确；本案例突出运行流程验证。
- 不通过更改提示词来制造这个负例，因为卡带冻结模型回答，提示词变化不等于真实模型行为变化。
- 具体基线记录与命令尚未准备，流程需在制作阶段验证。

核对依据：`packages/trace-test/README.md` 及 `test/rerun.test.ts` 中轮数上限收紧后报告卡带剩余的用例。本轮只读核对，没有执行测试或修改配置。
