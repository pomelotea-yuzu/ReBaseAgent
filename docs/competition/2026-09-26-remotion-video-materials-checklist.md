# ReBaseAgent 视频素材收集清单

> 日期：2026-09-26
> 依据：[讨论记录](2026-09-26-remotion-video-discussion.md)与[完整分镜草案 v0.1](2026-09-26-remotion-video-storyboard-v01.md)。
> 当前只建立清单，不开始收集、下载、录屏、调用模型或制作视频。
> AniBox、AniPedia 只作参考，不修改两个项目。正式软件镜头在 U8 完成、拍摄版本验收后采集。

## 1. 如何使用

- 勾选表示材料已经找到、检查并记录存放位置，不表示仅讨论过这项内容。
- “AI 可整理”指后续可以交由 AI 查找、整理或制作，不表示本轮已经执行。
- 用户主要负责提供只有自己能访问的素材或配置、确认偏好、审阅结果；本方案没有必须由用户亲自拍摄的视频。
- 已有文档、界面和数据可以作为来源线索，但尚未统一整理成素材包，因此下面暂不勾选。
- 实际采集时给材料记录来源、用途和版本；不用一开始就把全部材料准备齐。

## 2. 第一批：U8 前优先准备

### A. 番剧筛选案例的作品与数据

用途：独立制作 AniBox 风格的精简演示页，以及开场代码画面、案例一的前后对比。

- [ ] **A01｜番剧名单**：选 6～10 部作品，注明具体季度或版本，避免同名作品和不同季混用。AI 可给候选，用户可指定偏好。
- [ ] **A02｜封面图片**：每部一张清晰的竖版封面，保留原始图片、来源页面和使用条件。建议宽度至少 600px；没有合适封面时先保留占位，不阻塞案例设计。
- [ ] **A03｜作品基础资料**：每部的名称、总集数、简介等必要信息，以及可核对的来源。优先选择总集数明确的作品。
- [ ] **A04｜独立演示进度**：另建演示数据，包含已更新集数、已看集数、是否完结，覆盖未看、看到一半、追平但未完结、全部看完。明确是演示状态，不冒充用户真实记录或作品当前播出情况。
- [ ] **A05｜关键错误样例**：确定一条“总集数 12、已更新 6、已看 6、尚未完结”或等价的有效样例，以及正确筛选时应保留哪些作品。
- [ ] **A06｜任务与规则文本**：保存筛选任务、错误规则、修正规则三段文本，并说明修改的是工具返回内容还是文件本身。AI 可整理。
- [ ] **A07｜AniBox 视觉参考**：只读参考海报墙、卡片、观看进度、筛选区，选少量代表性截图或组件说明。注明仅作设计参考，不把原软件截图充当独立演示页。
- [ ] **A08｜来源标注文案**：整理“基于 AniBox 界面设计的精简演示版”及对应项目链接，供视频角标与简介使用。

建议字段：`id`、`title`、`season`、`totalEpisodes`、`releasedEpisodes`、`watchedEpisodes`、`isFinished`、`cover`。作品事实与演示进度分开保存。字段名是建议，尚未建立数据文件。

AniPedia 的作品资料不包含用户个人观看进度，收藏统计不能代替已看集数；封面也需要单独准备。

### B. 《无职转生》文案实验资料

- [ ] **B01｜作品范围**：明确本次介绍哪一季或哪一部分，不混合不同季的剧情与集数。用户可决定，也可由 AI 提出建议。
- [ ] **B02｜固定资料包**：整理故事前提、主要看点、适合人群及来源，删去关键剧透。两模型使用同一份资料，不各自临时搜索。
- [ ] **B03｜基础提示词**：面向普通观众，150 字以内，少用圈内术语，不剧透，不编造资料外信息。保存可重复使用的完整文本。
- [ ] **B04｜修改版提示词**：在基础版上增加“少用抽象赞美，多给具体看点”，保留准确的前后差异。
- [ ] **B05｜官方模型信息**：核对用户指定的 DeepSeek V4.1 Flash、V4 Pro 是否为官方当前可用型号，记录实际 API 标识与文档链接。未验证前不制作模型选项或结果画面，也不擅自替换型号。
- [ ] **B06｜调用条件**：确认官方账号可用、调用配置就绪，以及后续实验允许的费用范围。用户处理账号与访问条件；密钥只进入本地配置，不放入素材包、文档或录屏。

本案例的关键材料是文字资料，不需要收集番剧正片、剪辑片段或角色配音。

## 3. 第二批：U8 前可同步整理

### C. 视觉、音乐与片尾信息

- [ ] **C01｜Logo 原文件**：定位现有可编辑源文件或最高质量的透明底版本，记录当前使用位置。此项只收集，不启动调色。
- [ ] **C02｜界面风格参考**：选取当前软件的主背景、正文、强调色与状态色作为视觉参考；U8 后复核，避免提前冻结会变化的细节。
- [ ] **C03｜字体候选**：准备 1 套中文正文/标题字体，代码需要时另配等宽字体，保留字体文件、来源与使用条件。优先控制字体数量。
- [ ] **C04｜音乐候选**：选 2～3 首无人声背景音乐，能够覆盖开场推动感与正文低干扰节奏，保留试听、原文件和使用条件。AI 可给候选，用户确认偏好。
- [ ] **C05｜轻音效，可选**：准备少量滑动、停顿、确认音效；不是必需项，可在动画预览后决定。
- [ ] **C06｜仓库入口**：核对 ReBaseAgent 的 Gitee、GitHub 地址，确认下载与文档入口可达。片尾和简介均为 Gitee 在上、GitHub 在下。
- [ ] **C07｜赛事准确名称**：核对赛事、赛道名称及视频提交要求，留存官方来源，供片尾或简介使用。
- [ ] **C08｜发布文字**：整理一句话介绍、标题候选、简介、章节名称和 AniBox 参考说明。已有分镜中的草稿可作为起点。

### D. 真实运行材料的候选

以下现在可以筛选或规划；新运行、调用费用与正式采集留待后续执行阶段。

- [ ] **D01｜案例一候选记录**：寻找或规划有明确文件读取、工具结果、写入与终止事件的运行；保留完整父链与文件附件，不能只有截图。
- [ ] **D02｜错误详情候选记录**：挑选已记录原因或状态码、适合公开展示的失败调用。没有合适记录就列为待补，不伪造错误输出。
- [ ] **D03｜卡带基线候选**：选择需要多轮才能完成、工具声明与配置可匹配的已封存记录。不能默认任意代理记录或纯对话记录都适合此负例。
- [ ] **D04｜卡带配置与测试定义**：准备正常轮数配置、调低轮数的配置、预期完成状态及实际执行命令；预期中间结果为“卡带剩余、配置不兼容”。AI 可在后续准备，不修改产品源码。
- [ ] **D05｜记录索引**：标明每份候选的用途、运行 ID、父运行、源版本、配置来源、附件位置与尚未验证事项。只记录脱敏配置。

已有记录是候选，不等于最终镜头。U8 后须确认能在拍摄版本中正常读取，必要时重新录制基线或运行实验。

## 4. 第三批：U8 与拍摄版本验收后采集

### E. 正式软件画面

- [ ] **E01｜拍摄版本信息**：记录版本号、提交标识、使用的安装包或启动方式、拍摄日期，统一全片的软件基线。
- [ ] **E02｜能力概览画面**：采集轨迹与上下文、工具结果编辑、实验对比、测试报告四组清晰画面，用于倾斜上滑段。
- [ ] **E03｜简短入门操作**：打开软件、模型配置、新建运行、选择独立演示目录与任务；密钥和无关个人信息不出现。
- [ ] **E04｜案例一完整操作**：错误页面、读文件到写文件的轨迹、错误规则、Token 分布、编辑工具结果、隔离预检与确认、续跑、文件检查点与差异、正确页面。
- [ ] **E05｜案例一原始产物**：保存原运行与新分支的完整 trace、父链、附件、页面文件和实际用量；缓存命中如实记录，没有命中也不填假数字。
- [ ] **E06｜案例二完整操作**：普通父本、A/B 配置与计划、调用确认、两份完整文案、差异放大所需内容、固定模型后的 prompt fork 及修改后输出。
- [ ] **E07｜案例二实验数据**：保存准确模型 ID、两版提示词、固定资料、可公开的参数、完整输出、Token、耗时与运行 ID。不要只保存挑选出的高光句子。
- [ ] **E08｜案例三命令行**：采集正常通过、降低轮数后的配置不兼容、恢复后通过三个结果，并保存完整命令、配置与日志；不调用模型的事实应能核对。
- [ ] **E09｜辅助功能镜头**：实际错误详情、录制代理入口与地址、本地记录位置。按最终脚本选择，不必为每个小功能额外制作长演示。
- [ ] **E10｜最终品牌与链接素材**：使用确认后的 Logo 配色，核对片尾地址并生成二维码；不是现在提前定稿 Logo 或二维码布局。

录屏可以由 AI 尝试自动采集；若某些桌面操作无法稳定自动化，再由用户补录具体片段。保留清晰的原始视频与操作前后静态截图，转场、文字、放大和倾斜效果交给 Remotion，避免直接烙进唯一原片。

画面尽量使用统一窗口尺寸、缩放与主题。实际等待可以后期加速并注明，原始日志和真实耗时仍保留。

## 5. 由 Remotion 制作，不需要外部收集的视频

以下属于后续制作工作，不应误列为“用户需要找来的视频素材”：

- “不对，再改”的重复文字与代码修改开场；代码来自独立演示页，反复失败为情境演绎。
- 软件画面和简短描述整体倾斜、上滑、停留、离场的能力概览。
- 原运行、轮末检查点、文件副本与新分支的独立原理动画。
- 卡带响应与当前运行时的原理示意。
- 文案重点放大、字幕、章节过渡、片尾与封面排版。

原理动画不冒充软件界面，模型输出与命令行结果使用实际采集内容。

## 6. 用户需要参与的最小范围

| 事项 | 用户参与方式 |
|---|---|
| 番剧和视觉偏好 | 可指定喜欢的作品、音乐或参考；没有偏好可由 AI 提候选 |
| 非公开素材 | 说明素材位置或提供访问方式；已有本地参考项目不需要重新上传 |
| 模型账号与调用条件 | 在本地配置可用访问条件，确定实验费用范围，不把密钥当素材交付 |
| 自动采集无法覆盖的操作 | 后续仅补录实际缺失的片段，不预先要求整条视频手动录制 |
| 审阅 | 核对案例、品牌表达、动画可读性和最终成片 |

不需要真人出镜、自己录旁白、收集番剧正片，也不需要先手动完成剪辑。

## 7. 素材记录模板与准备顺序

每项材料可以用以下最小模板登记；素材目录可在正式开始收集时再创建：

| 字段 | 示例或说明 |
|---|---|
| 编号 | A02、E06 等，对应本清单 |
| 名称与用途 | 某作品封面；用于案例一番剧卡片 |
| 存放位置 | 实际文件路径或来源链接 |
| 来源与使用条件 | 原页面、作者、许可或署名要求 |
| 状态 | 待收集、候选、已核对、正式采用 |
| 版本信息 | 软件素材记版本和运行 ID；模型结果记模型 ID 与采集日期 |

优先顺序：

1. 番剧名单、基础资料、封面和独立演示进度。
2. 《无职转生》固定资料与两版提示词，核对官方模型信息。
3. 音乐、字体、Logo 源文件和风格参考。
4. 运行记录与卡带基线候选。
5. U8 后用验收版本统一采集正式界面与真实结果。

先凑齐可验证的案例，再补充装饰性素材。音乐、音效或某张封面未定，不阻塞文字资料与任务规则的整理。
