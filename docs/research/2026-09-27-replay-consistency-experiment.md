# 重跑一致性实验方案

制定日期：2026-09-27。状态：**待执行**。本文件定义方法和验收判据，不填充实验结果。已有测试文件仅作为用例来源；本轮未启动模型调用、桌面实例或完整回归测试。

## 问题与假设

目标场景是开发者调试一个多轮读写文件的 Agent。以下属于可运行的仿真任务设计，尚不代表访谈结果或真实用户需求统计。

- H1：相同消息边界下，历史文件快照能防止续跑误读当前源目录或父运行终态。
- H2：分支写入及失败不会改变源目录、父分支和兄弟分支的文件字节。
- H3：复用前缀能省去分叉点之前的模型/工具调用，但总时延收益依赖快照和载入成本。
- H4：在真实开发任务中，明确的分叉与文件证据能改善原因定位；尚无用户实验数据。

任何核心不变量失败都应记录为失败，不以最终文本“看起来正确”抵消。H3 若只减少调用但没有减少总耗时，应分别报告。H4 必须经后续使用研究，不能从单元测试推出。

## 第一阶段：受控机制实验

先使用固定响应的模型替身和临时数据目录验证 H1/H2。每个用例独立创建源文件、父轨迹和分支，文件使用固定 UTF-8 内容。保存文件清单、大小、SHA-256 与模型/工具调用日志。

采用三种内部配置，**不把它们命名为其他产品或代表其能力**：

| 配置 | 消息起点 | 文件起点 | 用途 |
|---|---|---|---|
| A：当前目录对照 | 相同的派生消息 | 特意改变后的临时源目录 | 检验消息恢复与文件恢复分离的影响；写入仍限制在临时目录 |
| B：父终态对照 | 相同的派生消息 | 父运行最后的文件快照 | 检验选择了错误时间点的文件世界会造成什么 |
| C：轮末快照 | 相同的派生消息 | 编辑工具所属整轮末快照 | 验证当前隔离语义 |

A/B 仅存在于实验夹具，不修改生产入口、不关闭真实路径守卫。三组使用同一派生消息、固定下一步 `read_file` 请求和相同结果判定，变化项只保留文件起点；由此检验状态影响，不推论产品速度或易用性。

### 用例与预期

| ID | 输入与干预 | 核查项 |
|---|---|---|
| E1 历史状态选择 | 初始 `a.txt=before`，分叉轮末为 `middle`，父终态为 `after`，源目录另改为 `outside` | C 读到 `middle`；A/B 分别读到 `outside` / `after`，确认对照确实改变了变量 |
| E2 同轮多工具 | T1 写 `a.txt`、T2 写 `b.txt`；只编辑 T1 观察 | 派生消息保留两条结果且仅 T1 改变；分支初态包含两次原写入；T1/T2 不重执行 |
| E3 多代和兄弟 | 从同一轮末派生 L/R，再从 L 自有合法点派生孙分支 | 路径映射独立，parent/fork 可追溯；源、父、兄弟哈希保持不变 |
| E4 附件与授权失败 | 分别移走附件、篡改字节、删除当前请求授权 | 各例执行前拒绝；零新运行、零模型和工具调用；不读取源目录补洞 |
| E5 执行失败 | 合法分支完成一次写入后，下一次模型调用失败 | 保留已有文件事实与错误记录；源、父、兄弟不变；不伪造成功 |
| E6 数据目录迁移 | 完整复制测试 dataDir 到新临时目录，重新创建读取器 | 无需原源路径仍能读取、验证和合法续跑；缺附件变体必须拒绝 |
| E7 前缀调用计数 | 构造 1、5、20 轮历史，在每个固定边界各创建 3 个分支 | C 分叉之前新增模型调用=0、工具调用=0；只统计本次新调用，排除父 trace 的历史记录 |

E1–E7 建议各做 10 次独立重置，以暴露偶发 I/O 问题。并发兄弟作为单独用例运行，不与其他包测试混跑。先以所有目标断言成立为正确性门槛，再报告运行次数；重复通过次数不等于真实任务成功率。

既有用例入口：[隔离重跑](../../packages/replay/test/workspace-isolated-replay.test.ts)、[跨模块集成](../../packages/replay/test/workspace-isolated-integration.test.ts)、[迁移恢复](../../packages/replay/test/workspace-package-recovery.test.ts)。新增实验夹具应在独立工作区实施，使用独立 dataDir，不占用桌面验收实例或修改其数据。

## 第二阶段：资源与真实模型实验

受控断言通过后再测 H3。对文件数 10 / 100 / 1000、单文件 1 KiB / 64 KiB 的配额内组合分别测量，固定修改比例并报告唯一 blob 字节增量。若某组合超过当前配额，标记拒绝，不调整配额凑出结果。

比较完整重跑与隔离续跑时，固定父记录、目标边界、任务、模型配置和停止条件，并明确干预如何对齐。完整重跑的历史执行有模型随机性，应同时提供确定性模型对照；无法对齐时不得把两组直接解释为因果性能差异。

| 指标 | 定义 |
|---|---|
| 一致性 | E1–E7 各自的布尔断言与失败原因，不只给总分 |
| 未授权写入 | 对源目录、父/兄弟世界清单逐文件比较，预期差异数为 0 |
| 模型与工具调用 | 前缀和后缀分别计数；文件工具与外部请求分列 |
| 时间 | 导入、预检/快照载入、首个后续模型响应、续跑总时间分别计时 |
| 存储 | 逻辑快照字节数、实际新增唯一内容字节、JSONL 大小分别记录 |
| Token 与费用 | 记录 provider usage；未知项留空，缓存 token 单列；按日期固定单价计算估计费用 |
| 任务效果 | 对预先定义的输出文件/状态断言判定成功，文本质量另行人工判断 |

性能测量建议每组合 3 次预热、30 次记录，冷启动单列，不混入预热统计；保留原始样本，报告样本数、中位数、P95 和失败数。失败样本仍计入失败率，耗时应单列，不能只保留成功执行。

真实模型阶段至少选择 3 个不同任务模板，每配置每任务计划 20 次独立执行，随机交错顺序。这个数量只是初步预算，不能自动保证统计把握度。记录服务商、精确模型标识、参数、日期、缓存命中与限流；不声称温度为 0 即完全确定。发生失败按预先定义的重试策略记录全部尝试。

## 第三阶段：实际开发任务

在参与者知情同意后，选用已脱敏的实际文件任务，与仿真任务分开报告。记录任务来源、预期目标、真实工具范围和环境，不使用第三方凭据或未授权数据。

先比较当前工作流与隔离分支工作流，交错任务顺序以减少熟悉效应，观察定位耗时、错误诊断次数、完成情况和遇到的阻碍。个人开发者自测只能称为自测；少量访谈不能称为广泛采用。跨产品比较需要另行固定版本、配置和适配代码，参见 [方案调研](2026-09-27-agent-debugging-landscape.md)。
