# AI 与 Agent 的真实用途：产品探索的现实依据

调研日期：2026-10-17。范围：公开使用数据、调查与真实使用者自述，覆盖中国大众 AI 使用、海外消费端和 agent 使用。状态：完成首轮公开资料调查，未做目标用户访谈、产品实测或付费意愿验证。本文不改变正式路线，不替用户选定新产品。

## 1. 先回答“人们在做什么”

现有证据支持：**大众 AI 使用覆盖问答、学习、写作、图片与视频、办公材料和生活安排；具有工具执行能力的 agent 则已被用于研究、工作流、编程和业务处理。** 不同产品与人群的用途差异很大，不能把开发者社区等同于整个用户市场。

产品探索应先落到具体用户任务：输入是什么、想拿到什么、过程中怎样修改、在哪里仍需人工处理。已有资产能否帮助这些任务，需下一步验证；不能从“我们会回放”直接推导用户需要回放产品。

## 3. 中国用户：编程是现实用途之一，并非多数人的用途

S1 报告正文第 8 页（PDF 第 16 页）给出如下使用目的：

| 用户表示使用 AI 做什么 | 比例 |
|---|---:|
| 回答问题 | 76.0% |
| 生成／处理图片、视频 | 47.8% |
| 生成／处理文本 | 37.6% |
| 工作总结、会议纪要、PPT | 32.5% |
| 生活助手 | 30.6% |
| 娱乐 | 30.1% |
| 生成／处理代码 | 10.8% |

这些是调查中用户使用目的的比例，类别可重叠，不能相加，也不是各类任务占全部请求的份额。不能据此断言 10.8% 的用户是程序员，或其他用户不需要复杂任务。

**入口也影响“普通人快速上手”的判断。** 正文第 7 页（PDF 第 15 页）中，网民使用方式包括手机内置助手 36.1%、移动端 AI App 35.5%、App 内 AI 插件 29.2%、电脑网页版 15.6%、电脑 AI 客户端 6.5%。分母与用途表不同，且允许多种方式并存。它提示大众已有入口明显偏向移动和既有 App；不能因为我们已有 Electron 桌面壳，就默认桌面应用是所有普通人的最佳入口。反过来，这些数据也没有否定桌面文件工作者这一具体人群。

报告对 2026-07 应用次数的分析称，综合助手、搜索引擎、生活助手最常用。这里能看出问答与生活使用确有规模，但不能把请求次数当作去重人数或付费意愿。

## 4. 消费端 AI：日常决策、理解信息和写作有明确使用基础

S2 研究摘要显示，实用建议、寻找信息、写作三类合计接近 **80%**；非工作相关使用已超过 **70%**，编程所占份额相对较小。这是截至 2025-07 的消费端样本，不能作为 2026-10 的即时份额。

较新的 S3 从实际产出观察，chat 与 Cowork 的最常见输出为：解释 **17%**、文档与报告 **15%**、指导建议 **11%**。对话型输出和文字交付物各约三分之一，代码与技术工作约六分之一。报告将聊天解释也定义为 artifact，**93%“有产物”不能理解为 93% 都生成了可下载文件**。

S3 直接观察到的具体用途包括：

- 工作：商业邮件、营销文案、演示材料、报告、分析与摘要。
- 学习：概念解释、教材、课程相关材料、学术文稿。
- 个人：旅行行程、健身安排、食谱、创作、媒体推荐及生活建议。
- 表格和数据：财务建模、仪表盘，以及结构化提取与标注；不同入口的任务结构不同。

其中，在被分类为工作的会话里，文档／报告占 **20%**，邮件草稿 **7%**，分析／摘要 **6%**。这些任务真实存在，但统计没有进一步证明用户需要“可分叉的报告”或愿意换一个工具。

## 5. Agent：用途随执行入口而变化

### 5.1 浏览器 agent：工作流、研究、课程和购物

S5 论文摘要基于 Comet 与 Assistant 的交互，报告：

- 生产力／工作流和学习／研究两个主题合计占 agent 查询的 **57%**。
- 课程与商品购物两个子主题合计占 **22%**，不是各占 22%。
- 个人场景约 **55%**，职业 **30%**，教育 **16%**；四舍五入后合计可超过 100%。
- 数字技术、学术、金融、营销、创业等知识密集人群更容易采用或积极使用 agent。

这说明消费型 agent 确实覆盖编程之外的任务。但“查询”不等于完整执行成功，购物查询也不等于完成付款。摘要不足以支持某个更具体的动作频率，因此本轮不编造“多少人自动下单、报名或订票”。

### 5.2 模型 API 与编码 agent：软件工程活动突出

S4 的 API 工具调用样本中，软件工程接近 **50%**；商业智能、客服、销售、金融、电商等各占较小比例。编码任务可能需要更多连续工具调用，因此该份额不能理解为“一半 agent 用户在写代码”，也不能与 CNNIC 的用户比例直接比较。

S4 的 Claude Code 中，用户仍会补充上下文、纠正执行、手动测试和调整要求。人工中断原因中，补充技术背景或纠正约 **32%**；agent 自己停止的原因包含收集诊断／测试结果 **21%**、澄清不完整需求 **13%**。这些数字的分母是特定中断／停止样本，不能当作所有任务的失败率。

### 5.3 专业团队：客服、研究分析与内部自动化

S6 受访者报告的主要 agent 用途为：客服 **26.5%**，研究与数据分析 **24.4%**，内部工作流自动化 **18%**。日常使用的自由回答则经常提到编码助手、深度研究，以及知识库、SQL、测试和客服等自建 agent。

这是现实团队用途的线索，尤其适合理解部署者。但样本科创色彩很强，不能据其“57.3% 已生产部署”宣称普通大众或全部企业已普遍使用 agent。

## 6. 使用者自述：普通人的价值还包括做以前做不了的事

S7 记录了具体使用者：客服人员基于既有回复生成新回复；送货司机尝试创建电商业务；园林工作者制作音乐应用；会计构建帮助处理融资任务的工具。其效率数字属于自述，本轮没有独立验证。

在明确提及生产力影响的受访者中，**48%** 谈到能力范围扩大，**40%** 谈到速度提升。这不是全部 80,508 人的统一答题结果，也不意味着所有普通人都能轻松上手。

这些案例提示：调查不能只问“你每天做什么重复工作”，也要问“你用 AI 做成了哪些过去不会做的事”。同时也存在多次修复才有效、精确指令难以遵守的负面自述，不能只选成功故事。

## 7. 对本轮产品探索的修正

以下为基于资料的**推断与待验证安排**，不属于已经发现的市场空位：

1. **场景池应扩大。** 至少保留资料研究、文档／表格办公、应用制作三类，图片视频和生活任务也需纳入需求观察。不能仅因播放器经历或已有文件引擎就选定编程为主线。
2. **高频用途不自动等于适合现有资产。** 简短问答虽然常见，未必需要检查点和分支；多来源资料、多文件处理、持续修改与可验收交付可能更有适配空间，但要看真实工作过程。
3. **“普通人”要按任务细分。** 学生、行政、财务、内容作者、小商家、非技术创作者的输入、验收能力和日常入口不同，不能以“非开发者”一词代替用户画像。
4. **入口需要验证。** 优先观察用户是否已有网页、Office、手机或本地目录工作流。现有桌面资产是成本优势，不是用户必须换入口的理由。
5. **实际使用与需求缺口分别调查。** 这些报告能证明人们在做哪些事；还不能证明版本恢复、干预或可复用执行过程是他们的主要痛点，也不能证明候选产品原创或有人愿意购买。

对既有讨论的校准：端用户 agent 已有 Cowork、Comet 等实际产品与使用研究，“端用户无人做”的泛化判断不能沿用。具体能力是否相同仍需用户另行安排的竞品对照；本轮不推断这些产品已解决全部恢复、一致性或调试问题。

## 8. 下一步应该调查真实任务的过程

公开统计之后，建议按研究／资料处理、办公文档／表格、非技术创作／应用制作分别收集若干近期真实任务。先不规定必须出现失败，也不使用已经修好的播放器旧问题作为待修任务。

每个任务记录：

| 需要知道什么 | 记录内容 |
|---|---|
| 用户与任务 | 最近实际做过什么、发生频率、为自己还是为工作做 |
| 输入和工具 | 原始素材、文件和网站；使用的 AI、账号、入口及前置配置 |
| 真实过程 | 首次要求、补充背景、改要求、检查与返工；区分使用者叙述和可核对记录 |
| 人工负担 | 查证、复制粘贴、整理格式、处理环境、恢复修改、搬运成果等哪些实际发生 |
| 完成判据 | 用户怎么知道结果可用，谁最终验收，有没有真正使用产物 |
| 上手与复用 | 是否自己完成首次任务、谁帮过忙、遇错后怎么办、后来是否再次主动使用 |

本次未招募、联系或采访任何人，不将上述研究设计写成已完成证据。后续每个产品候选应引用真实任务，再解释资产复用、独创性、实际价值和上手门槛，避免继续只围绕技术能力想象需求。
