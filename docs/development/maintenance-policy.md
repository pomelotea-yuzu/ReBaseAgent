# 版本与维护政策

修订日期：2026-09-27。本文说明单维护者阶段的版本、依赖和兼容性维护规则，不新增长期支持周期或固定发布日期。当前安全报告受理范围以根 [安全策略](../../SECURITY.md) 为准；具体版本是否公开发布以对应 Release 与验收记录为准。

## 维护范围

| 对象 | 当前范围 | 不代表的承诺 |
|---|---|---|
| 桌面发行物 | Windows x64 portable；按具体发行说明列明已验收环境和能力 | 不代表所有 Windows 版本均已测试，也未提供 macOS/Linux 发行支持 |
| 已发布版本 | 接收问题、核查影响，修复优先进入当前开发线，并说明所在版本 | 不默认对每个历史版本单独回补，不承诺 LTS |
| 预览版与候选包 | 按版本、提交和哈希定位反馈；公开预览包与仅本地构建分别记录 | 预览不等于稳定性保证，候选构建不等于已发布 |
| `main` 与源码运行 | 接收附提交、环境和复现步骤的问题；活动 change 状态单列 | 不保证随时可发行，不把部分实现写成整项完成 |
| workspace 库 | API、CLI 和数据格式按规范及对应版本说明维护 | 桌面包版本不代表所有库已同版本发布到 npm |
| 模型与外部服务 | 在已声明的协议、工具和配置范围内处理兼容问题 | 不保证任意服务商、模型、第三方 Agent 或自定义工具均可运行 |

发行说明应注明正式版或预览版、准确提交、平台、包含范围和限制。产品版本、库版本和 trace 格式版本是不同标识，不依赖版本名推断数据兼容性。

## 修复与依赖更新

优先评估数据完整性、安全、执行或阅读阻断和兼容性问题，再处理高频体验问题与新功能。维护者在关联 Issue/PR 中说明采用、暂缓或不采纳的理由；确认问题不等于承诺完成时间。回补旧版本时单独记录必要性、目标版本和验证结果。

依赖更新按安全修复、已知缺陷、兼容要求或明确功能需要提出，不为追求版本新而夹带无关升级。普通更新保留较小范围；需要成组升级的依赖说明关联原因。更新包声明与锁文件，并记录上游变更、许可变化、对应用和数据的影响。

涉及 Node、pnpm、Electron 或构建工具时同步检查运行要求、CI 和打包流程。`engines` 的最低版本不是完整支持矩阵；构建报告记录实际使用版本。当前不承诺定期自动扫描、自动升级或固定更新频率。

代码与构建变更按[开发工作流](workflow.md)验证；运行时、资源裁剪或打包变更还需对应实包检查。依赖或捆绑内容改变后，按[第三方声明说明](third-party-notices.md)重新核查受影响项。检查未完成时保持待验证状态，不沿用旧提交结果。

## 数据兼容与升级

数据读取、分叉和隔离执行的真实边界以 [trace-format](../../openspec/specs/trace-format/spec.md)、[workspace-isolation](../../openspec/specs/workspace-isolation/spec.md) 等主规范和实现为准。可读取一份记录不等于可以用它续跑；旧包能否读取新格式必须单独核查。

改变格式、必需字段、路径布局或旧记录行为时，先按 OpenSpec 说明影响范围、拒绝方式、迁移需要及验收条件。迁移工具没有实现并验证前，不在升级说明中承诺自动迁移；不通过删除隔离字段或改低格式版本绕过守卫。

升级前在应用停止写入后备份完整数据目录，保留 trace 父链及文件附件；只复制单个 trace 不一定能恢复隔离运行。先用数据副本检查目标版本。退回旧包不等于数据也已回退，必要时使用升级前备份；不得为降级直接改写原始记录。

## 放缓、停止与恢复维护

维护能力下降时在 README、版本说明或置顶公开记录中注明日期、受理范围、未完成问题和是否继续处理安全报告，并同步根安全策略；不使用未兑现的计划日期代替状态说明。

停止某条版本线或整个项目的维护时，说明停止范围、最后可用版本、已知风险、数据保留办法，以及可用时的迁移或 fork 入口。停止维护不等于删除既有许可证或撤销已经授予的开源许可。当前未设固定停止日期或提前通知期限。

新增维护者或恢复维护时记录负责人、权限范围、接手结果和新的支持范围，按[发布与交接指南](release-and-handoff.md)核对，不能仅修改文档就宣称已完成交接。
