# 第三方声明与发行说明

修订日期：2026-09-27。本文件定义第三方内容核查和声明交付要求，**不是最终发行包的第三方许可证汇编，也不是合规验收结论**。本轮未重新扫描依赖、解包 exe 或改动打包配置；已有输入见[依赖核查记录](audits/2026-09-27-dependency-licenses.md)。

## 核查范围

项目原创贡献按根 [MIT 许可证](../../LICENSE) 分发。第三方内容依其自身许可保留版权、许可文本、NOTICE、署名以及适用的其他义务，不能用项目 MIT 声明统一替代。

| 内容 | 核查依据 |
|---|---|
| 运行依赖和传递依赖 | 锁定名称/版本、上游代码和声明、实际发行物中的位置 |
| 前端 bundle 中的代码 | 构建输入与实际输出；排除原始 node_modules 目录不消除已打包代码的义务 |
| Electron/Chromium 等运行时 | 实际携带版本、运行时许可与其第三方声明，不因位于 devDependencies 而排除 |
| 开发或构建依赖 | 是否将代码、资源或运行时复制进发行物；未分发也需给出判断依据 |
| 图标、字体、图片、文档、示例和数据 | 来源、许可、改动情况、署名或再分发要求；仓库和对外材料中的内容均需考虑 |

包的 `license` 字段是查找线索，不能代替完整文本。没有找到顶层 LICENSE、不在生产依赖图、或上游标记双许可证，都需要按实际内容判断，不能直接记为通过。

## 组件记录

每次候选发布建立“实际携带组件 → 版本 → 来源与许可 → 声明交付位置”的映射，并关联源码提交、锁文件及发行物 SHA-256。建议字段如下；以下只是记录格式，没有虚构已核查的组件结果。

| 字段 | 内容 |
|---|---|
| 组件与版本 | 包名、运行时或素材名称，精确版本/提交 |
| 来源与改动 | 上游 URL、本地输入位置、是否修改及修改说明 |
| 发行范围 | bundle、asar、独立文件或未分发；附判断依据 |
| 许可与义务 | 适用许可或选用路径、版权/署名、NOTICE、源码提供等具体要求 |
| 声明文件 | 实际许可全文与相关声明的来源、哈希和交付位置 |
| 结论 | 已核查 / 待核查 / 不分发及依据，负责人和日期 |

双许可证按原文判断是可择一还是须同时满足；选用的路径和处理方式要留记录。涉及修改声明、源码提供或其他条件时逐项处理；有疑问时保持待核查，不凭许可名称推断已满足全部义务。

## 声明如何交付

实际发行应提供用户可以取得的声明索引，以及适用的许可全文、版权与 NOTICE。可以使用包内文档或随发行资产提供的声明文件，具体方式必须符合每项许可和分发形式的要求；仅提供一条上游网页链接不自动满足义务。

可采用以下文档组织方式，**这是建议布局，目前未生成或接入打包流程**：

```text
THIRD_PARTY_NOTICES.md       组件、版本、许可和声明位置索引
third-party-licenses/       按组件保留的许可全文、版权和 NOTICE
```

不要覆盖 Electron 自带的 `LICENSE` 或 `LICENSES.chromium.html`。若声明置于单独下载资产，需要与可执行文件明确关联版本、哈希和下载入口，并逐项确认这种交付方式满足许可；不能假设一个独立压缩包总能替代应随软件附带的声明。

更改打包包含规则、生成通知文件或新增查看入口属于后续实现，不由本文直接完成。实际文件位置应在[发布记录](release-and-handoff.md)注明，不能仅写“随包提供”。
