# 从 R2.2 开始的能力增强路线（讨论稿存档）

日期：2026-10-12。状态：路线细化讨论稿已归档，主线排序与 UI 整理方向已同步正式路线；详细任务与技术方案仍待设计、立项，未建立新的 OpenSpec change，未开始实现。

## 1. 规划起点与不变的大方向

本稿按本轮讨论，从 **R2.2 开始安排新增能力与增强**。R0、R1、U1–U8 与 R2.1 已有成果只作为复用基线，不把新调研中的候选能力追溯成已完成阶段的待办。

产品目标继续沿用[正式演进路线](evolution-roadmap.md)：

**找到 Agent 出错的步骤 → 修改输入或操作 → 在独立状态中执行 → 判断结果 → 将有用结果带回项目。**

主要服务维护多步文件／代码 Agent 的开发者，先支持一种真实技术栈；免费开源、数据本地保存、来源可核查、源项目与父／兄弟分支不变。真实项目接入 I 持续推进，可用性核查随新增能力实施。

本稿依据[竞品与社区需求调研](../research/2026-10-12-agent-differentiation-and-community-needs.md)细化工作。该调研 §6 是能力来源的讨论映射；**本文是后续新增任务的规划草稿，以 R2.2 及之后阶段承接增强**。调研中的独创性候选仍需验证，不因进入路线而变成已证明的竞争优势。

正式路线的能力边界与 OpenSpec 继续约束当前实现；本稿补充各阶段的候选任务，经具体设计后再创建对应提案。状态校准：R2.1 已于 2026-10-12 归档（提交 `ac8729e`），依据[归档任务](../../openspec/changes/archive/2026-10-12-export-run-results/tasks.md)；正式路线已回填完成状态与 R2.2 优先的顺序，详细任务不因同步主线而自动获批，不据此宣称已经打包或发布。

## 2. 依赖基线

| 基线 | 后续直接复用的内容 | 本稿的处理 |
|---|---|---|
| R0／R1 | 轨迹、启动消息、工具结果编辑、固定文件工具、不可变附件、初始／轮末检查点、隔离续跑与文件查看 | 不重新立项，不增加“重做 R1”任务；新实验语义通过后续 change 定义 |
| U1–U8 | 工作区导航、阅读／草稿、主动操作登记、运行身份与结果核对、运行比较、实验工作区 | 新能力接入时复用；只对新增流程补交互与验证 |
| R2.1（已归档） | 选定检查点文件导出、来源清单、适用的文本补丁 | 复用[归档提案](../../openspec/changes/archive/2026-10-12-export-run-results/proposal.md)与任务所定义的能力；本稿不增加分享包、自动应用或合并范围 |

原生隔离文件恢复、普通 prompt fork、普通模型 A/B 是不同入口。已有普通 prompt／模型实验不能直接当作隔离实验已经完成，也不能只取消隔离父本拒绝就获得新能力。

## 3. 阶段与推荐顺序

| 阶段 | 用户得到的能力 | 主要新增增强 | 交付重点 |
|---|---|---|---|
| **R2.2：隔离 prompt 修复实验** | 改一项启动指令，在同一初始文件起点重新运行 | 实验起点的一致性说明、干预记录、修改前后结果核对 | 一次合法干预、一个独立分支的完整流程 |
| **R2.3：隔离模型／参数实验** | 同一任务与文件起点，比较不同模型或参数 | 可比较条件说明、所有尝试记录、失败分类、重复采样与费用 | 首版双臂；完整多臂与重复实验分开交付 |
| **R3：真实测试与修复证据** | 在受支持项目环境中验证失败与修复 | 代码／测试／干预关联、可核查修复材料、项目回归案例 | 一个明确环境中的“失败 → 修复 → 通过 → 导出” |
| **R4：工具操作级修复** | 回到操作前，改参数真正重做 | 调用级状态配对、执行范围预览、操作与文件差异定位 | 固定文件工具、串行调用的准确恢复与执行 |
| **R5：更多工具与外部状态** | 在更多真实项目中复用上述流程 | 适配能力与数据质量说明、录制／真实执行来源区分 | 每种新增对象单独证明支持范围 |

**已有 R2.1 已归档，推荐新增主线：R2.2 首版 → R3 首个受支持环境 → R2.3 完整扩展 → R4 → 按需求推进 R5。** R3 的独立技术验证可以在 R2.2 规划／实施期间开展。

如果真实案例明确需要两个模型，R2.3 的最小双臂可插在 R2.2 与 R3 之间；它不成为 R3 的进入条件。完整多臂管理与自动化重复采样仍后置。R4 的固定文件工具技术验证不依赖 Shell，R5 的非进程适配也不必等待所有 R4 工作。

原编号保持不变。本文按能力分别细化，表格排列不表示必须逐项串行等待。

## 4. R2.2：隔离 prompt 修复实验

### 用户任务与阶段成果

用户发现 Agent 对配置的理解有误，修改 system prompt 或首条用户指令，从对应根运行的初始文件状态重新执行。用户能说明改了哪里、用了哪个文件起点、执行产生什么差异，再导出选定结果。

首版成果是一条桌面可完成的单分支流程。**本阶段新增的一致性说明只服务新隔离实验，不先建设面向全部旧运行的诊断平台。**

### 必须做的事情

| 任务 | 要完成的事 | 可检查的交付物／结果 |
|---|---|---|
| R22-01 实验起点 | 首版只接受有完整启动消息与初始文件快照的根基线；对中途续跑分支提供回到对应根基线的操作，验证后仍由用户确认实验目标 | 明确根 run、启动消息来源、初始快照与工具版本；缺失时在创建子记录和模型调用前拒绝 |
| R22-02 单项编辑 | 一次编辑 system prompt 或首条 user message；拒绝空编辑、组合修改与无法还原的启动输入 | 编辑 diff；其余启动消息保持原样；实际请求与配置指纹一致 |
| R22-03 独立执行 | 从初始文件快照建立新文件世界，从第 1 步真实执行；历史父运行只作溯源 | 子 run 独立轨迹、快照与运行身份；不混入父前缀，不回读当前源目录作为历史起点 |
| R22-04 干预记录 | 记录基线、修改字段、原值／新值、执行配置与实际子 run；敏感正文保持原有存储边界，公开材料另行处理 | 用户与后续比较逻辑能核对“这次到底改变了什么” |
| R22-05 执行流程 | 接入已有授权、费用确认、操作登记／去重、执行槽、失败草稿与结果定位 | 提交前显示真实调用范围与费用边界；前置拒绝无假 run 身份，运行失败保留真实记录 |
| R22-06 结果核对 | 使用现有输出／指标比较；新增两个运行的选定文件检查点比较，明确各自来源与基线 | 输出、文件清单／文本差异与新增消耗可查看；缺失或二进制状态分别显示 |
| R22-07 产物带出 | 结果页连接已交付的 R2.1 检查点导出能力 | 导出材料对应用户选中的子 run 与检查点，不把比较页中的另一侧误当来源 |

跨运行文件比较是新增工作：现有文件页与运行比较作为组件／事实读取基础，不能把它们记成已经提供完整跨运行文件 diff。比较接口、检查点选择与缺项行为须在本阶段设计。

### 本阶段的增强

| 增强 | 具体内容 | 首版控制范围 |
|---|---|---|
| R22-E1 实验条件说明 | 提交前列出配对的启动消息、初始文件、固定工具组、模型配置和本次修改；拒绝原因连接具体缺项与补采集方式 | 复用已有校验事实，不添加“可信度评分”，不改旧运行读取模式 |
| R22-E2 指令变化与结果证据 | 将指令 diff、子运行结局、文件结果与消耗放到同一结果流程；保留用户填写的修复假设／人工判据 | 不自动断言指令修改导致成功；R3 前只展示实际结果、确定性文件规则或用户判断 |

“首次可确认差异”的自动定位先记录设计问题：同一步数不等于同一动作，跨分支工具序列可能变化。本阶段先交付可靠的文件与输出比较，自动事件对齐另在真实案例验证后补。

### 验收与首版边界

- 同一初始文件状态下完成原指令与新指令任务；新分支的首次读取内容等于选定基线，而非父最终内容或当前源目录。
- 能从记录核对单项编辑、完整启动请求、新 run 和文件结果；源目录、父与兄弟分支指纹不变。
- 缺少启动消息、初始附件损坏、来源不完整、空编辑与中途分支起点均有明确行为；前置拒绝零模型调用、零子记录。
- 失败子运行仍可定位、查看落盘结果和保留草稿；用户可以导出符合 R2.1 条件的自有检查点。

首版不支持任意中间消息实验、模型与 prompt 同时变化、Shell、工具参数重做、自动评分、批量重复运行或导入会话接管执行。

## 5. R2.3：隔离模型／参数实验

### 用户任务与阶段成果

用户固定任务和初始文件，比较模型 A 与 B，或在同一模型上比较一项采样参数，查看输出、文件和消耗。**实验条件、执行失败和任务判断分开呈现，不能只给一个“最佳模型”。**

R2.3 复用 R2.2 的起点校验、独立文件执行、干预记录和文件比较能力。已有普通模型 A/B 的 UI 与身份管理可以复用，但需要新的隔离编排与每臂授权契约。

### 首版双臂必须做的事情

| 任务 | 要完成的事 | 可检查的交付物／结果 |
|---|---|---|
| R23-01 控制变量 | 两臂共享输入、初始文件和工具版本；选择模型比较或单项参数比较；记录 provider／模型标识与无法固定的版本限制 | 请求预览明确相同项与变化项；模型标识不同是一个实验因素，不声称其内部实现只变了单一属性 |
| R23-02 独立世界 | 两臂分别从初始快照开始，顺序执行；禁止后一臂继承前一臂写入 | 每臂首次读取一致、文件世界独立，源与各臂状态不互相污染 |
| R23-03 每臂身份与收尾 | 保存全部已启动臂的真实 run ID、执行结局和诊断；明确第一臂失败后是否继续第二臂 | 费用授权中预先说明继续策略；成功、失败、未知状态不丢臂，不按成功臂重编号 |
| R23-04 结果比较 | 复用 R2.2 文件比较，显示输出、文件、耗时、token、缓存与费用 | 未提供 usage／价格时标未知；费用估算注明来源，不把未知记为 0 |
| R23-05 失败分类 | 区分前置拒绝、provider／网络错误、工具执行错误、预算终止、正常完成与用户任务判据 | 执行失败不自动算作模型任务失败；不使用总体成功率掩盖未完成臂 |
| R23-06 选择与导出 | 用户按明确判据选择一个结果，再调用 R2.1 导出 | 导出与选中臂、run、检查点对应，未经测试不显示“测试通过” |

### 后续增强与拆分

| 增强 | 要完成的事 | 进入条件 |
|---|---|---|
| R23-E1 按案例重复采样 | 用户选择重复次数、费用／调用上限；每次从相同基线运行；保留每个尝试 | 双臂已验收且有重复实验需求；不隐式触发额外计费 |
| R23-E2 可解释的结果统计 | 分别报告有效完成、任务通过、基础设施失败、未知与总费用；给出明确分母 | 人工判据或确定性规则可用；重复数不足时只描述本次结果 |
| R23-E3 更细差异定位 | 对固定工具及明确文件读写定位首次可确认差异，给出匹配依据与不确定项 | 真实案例证明比手动比较有价值；不按步骤序号强行匹配 |
| R23-E4 多臂配置与运行组织 | 扩展臂数、配置复用、结果筛选与预算管理 | R3 首个真实任务通过后，按需求独立立项；并行执行／队列另定义 |

重试与重复采样不同：重试针对一次执行错误，重复采样是新实验。首版不自动重试；以后增加重试时记录原尝试、原因、额外费用与副作用边界，不覆盖失败记录。

### 验收与首版边界

两个臂使用同一基线、独立写入；原项目与各臂不变性可核对。覆盖一臂失败、两臂失败、usage 缺失、参数无效、预算中断及导出来源选择。用户能说明比较条件和选择依据。

首版固定双臂、顺序执行；不包含通用排名、自动评审模型、多因素组合搜索、无限重试、并发调度或全部模型版本可复现承诺。

## 6. R3：真实测试与修复证据

### 用户任务与阶段成果

用户在受支持的 Node/TypeScript 项目中得到一次测试失败，通过已有工具结果干预或 R2.2 指令实验修复，再在同一明确环境中测试并导出代码。R3 仍是下一项核心执行能力，不等待完整 R2.3。

### 必须做的事情

| 任务 | 要完成的事 | 可检查的交付物／结果 |
|---|---|---|
| R3-01 执行后端验证 | 在 Windows 验证一个维护中的进程隔离方案；核对安装、文件／网络限制、子进程停止与环境类型 | 技术验证记录；未通过则保持未开放，不退回未约束宿主 Shell |
| R3-02 项目与环境基线 | 固定一个 Node/TypeScript 模板、依赖锁文件、运行时／镜像版本、测试命令与受控配置；保留已有源码接入路径 | 可核查环境清单；依赖准备与正式实验分开记录，安装脚本在同一隔离边界内 |
| R3-03 文件物化与回收 | 将历史文件状态物化到独立项目环境；执行全部停止后采集产物，排除依赖／缓存／临时目录 | 输入与输出清单、路径／链接／配额检查；必要文件状态超出 R1 时先扩契约 |
| R3-04 命令记录 | 记录命令、参数、工作目录、stdout／stderr、退出码、实际执行耗时与输出限制 | 每次测试关联实际 run／检查点／环境；凭据不进入 trace |
| R3-05 中止与失败 | 明确正常测试失败、启动失败、超时、取消、崩溃、环境准备失败；停止子进程后收尾 | 已取消必须真的停止；重启后核查／清理残留，不能把旧未知操作显示为仍可恢复执行 |
| R3-06 修复闭环 | 关联原失败、人工干预、新分支、测试记录与导出检查点 | 失败与通过证据使用明确可比较条件，用户能从代码差异追到测试和产物 |

### 本阶段的增强

| 增强 | 要完成的事 | 交付边界 |
|---|---|---|
| R3-E1 修复证据说明 | 显示哪些判断来自 Agent 文本、退出码、项目断言或用户确认 | 测试只证明实际运行的用例；环境故障不作为代码不正确的证据 |
| R3-E2 可核查材料 | 导出所选代码、测试日志、环境清单、干预与来源引用；提供范围选择、脱敏预览及缺项说明 | 与 R2.1 文件导出分开立项；不默认打包整个历史会话、全部依赖或凭据；只读复核与可重执行分别标注 |
| R3-E3 项目回归案例 | 固定输入基线、命令与确定性断言，形成该修复的再次验证入口 | 区分 Trace-as-Test、文件不变性、真实项目测试与重新计费的模型质量实验；CI 接入为后续独立交付 |

材料包和回归不是 R3 技术验证的前置条件。先交付一条真实测试路径，再按实际复核需求增加 E2／E3，避免将 R3 扩成评估平台。

### 验收与首版边界

同一环境得到已知失败与修复后通过，能核对代码、命令、日志、退出码与导出来源。越界访问、网络、输出容量、超时、子进程与中断恢复有证据；源目录与兄弟分支不变。

首版支持一个明确环境、有限固定命令；不支持任意宿主 Shell、全部语言、任意构建系统或完整数据库恢复。工程 fixture 通过后，另完成 I 接入的真实项目任务才主张已有项目支持。

## 7. R4：工具操作级修复

### 用户任务与阶段成果

Agent 写错了文件路径。用户回到该工具调用之前，修改路径并真实重做，后续模型看到的新参数、新结果与新文件一致；父运行保留原错误。

### 必须做的事情

| 任务 | 要完成的事 | 可检查的交付物／结果 |
|---|---|---|
| R4-01 调用级采集 | 为新运行记录固定文件工具调用前／后检查点、实际顺序、输入与工具版本 | 明确新能力版本；旧轮末快照只读兼容，不补造调用前状态 |
| R4-02 调用选择与恢复 | 首版限定串行固定文件工具；验证调用归属与前置检查点 | 选中调用前的文件世界可恢复，缺项在模型／工具执行前拒绝 |
| R4-03 参数干预 | 编辑选中工具的合法参数，保留原值、新值、调用 ID 与父来源 | 父记录不变，子记录能说明改了哪次操作 |
| R4-04 重执行范围 | 保留前置工具结果，重新执行选中及后续同轮工具，随后继续模型 | 后续旧结果不复用；被重做的工具与先前未重做的工具有实际证据 |
| R4-05 上下文一致性 | 同步后续 assistant 工具调用参数、调用 ID、新结果与文件状态 | 模型上下文不再声称执行旧参数；修改后的失败结果同样真实记录 |
| R4-06 桌面操作与收尾 | 显示恢复点、参数 diff、重做范围、授权与费用；接入草稿、操作登记和失败定位 | “修改返回结果后继续”与“修改参数并重做”两个入口语义清楚 |

### 本阶段的增强

R4-E1 将首次可确认的操作差异与对应文件变化连接，帮助用户看到“改路径后，哪次写入和后续读取改变了”。仅对有明确版本和执行记录的工具建立关系，不把观察到的相关性显示为自动根因判断。

R4-E2 预览会再次执行哪些工具、涉及哪些受支持文件路径。预览基于已知历史顺序和新参数，后续模型产生的新调用仍可能变化；不能承诺提前知道全部未来副作用。

### 验收与首版边界

新分支旧错误写入不存在，新内容落在修改后的路径；前置工具未重做，后续同轮与模型执行范围正确。验证多工具同轮、参数无效、工具失败及中止；仅在执行链路实际停止后显示已取消。

并行工具单调用回退、任意 handler、外部业务写入、任意工具代码替换均后置。扩大格式／能力版本前独立评审旧 trace 行为，不改变已有 result 编辑含义。

## 8. R5：更多工具与外部状态

### 用户任务与阶段成果

第二个真实 Agent 项目能复用已验证流程；根据它的具体需要增加一种工具或状态。每个适配有明确状态来源、恢复方法、执行模式和失败边界。

### 必须做的事情

| 任务 | 要完成的事 | 可检查的交付物／结果 |
|---|---|---|
| R5-01 选择具体对象 | 用第二个真实项目决定重复接口和首个新增工具／状态 | 原工作方式、失败任务、正确性判据与适配成本记录 |
| R5-02 版本与执行契约 | 声明工具定义／实现版本、状态归属、权限、恢复方法和执行入口 | 明确支持查看、录制响应、真实请求、隔离续跑或参数重做中的哪些模式 |
| R5-03 状态适配 | 为每种对象实现快照／版本／测试实例或受控模拟 | 缺少可恢复状态时保持只读或录制模式，不声称文件快照恢复外部世界 |
| R5-04 数据质量说明 | 对新增源记录字段缺失、推导时间、请求截断、usage 未知、合成父关系与侧链处理 | 原始／推导／未知可辨；导入成功不等于执行资格成立 |
| R5-05 接入与真实修复 | 提供文档、固定测试数据、一个真实失败修复与状态不变性案例 | 原 Agent 主体保留，另一位开发者可复现支持路径 |

优先评估纯计算、不可变文件搜索，再按需求考虑 HTTP 录制／实时读取。数据库、RAG、记忆依赖独立测试实例或版本数据；业务写 API 使用测试端点／模拟路径，不能自动真实外发。

### 本阶段的增强与独立工作

跨工具会话导入可作为 **I 的独立只读接入工作**，按真实需求提前，不必等待 R5。它复用已有查看能力，并在新适配流程增加数据质量说明；不追溯改写 R0／R1 的交付任务，也不作为 R2.2／R3 前置条件。

跨源完整上下文诊断先要求源提供真实请求或明确压缩事件；只能取到会话日志时，展示可确认片段与缺项，不还原未记录内容。跨源查看已有竞争方案，其价值以适配保真与排障效果验证。

首版逐适配交付，不建设全框架插件市场、任意数据库恢复或多 Agent 调度平台。

## 9. 研究储备：失败案例缩减

调研中的“将长失败运行缩减为可复现实验”保留为独立研究方向。**不作为任何阶段首版的完成条件，也不新建 R6。**

R3 或已有确定性文件规则提供可重复失败判据后，先用固定文件工具研究减少初始文件／任务输入；需要修改调用参数时再消费 R4。若接触 R5 外部状态，必须先有对应恢复能力。

研究任务：

1. 定义失败判据、可修改对象、输入／文件配对约束、实验次数与费用上限。
2. 在独立分支尝试缩减，保存每次干预、结果与成本，不改原任务记录。
3. 输出一个再次确认仍失败的更小案例；不宣称全局最小。
4. 对随机失败重复确认，分别报告基础设施错误和未能复现的尝试。
5. 与人工整理比较耗时、材料大小与复现成功情况；收益不成立时保留人工材料选择。

未经重新执行的内容裁剪只叫诊断摘录。自动缩减涉及新的输入变更语义和模型费用，须独立设计、授权与验收，不借 R2.2 的 prompt 编辑入口隐式执行。

## 10. 每个阶段共同要交付的内容

这些是新能力接入时的工作要求，不是新增一个 U 阶段，也不重新打开已归档 U change。

| 方面 | 本阶段要做的事 |
|---|---|
| 提案与设计 | 明确用户任务、输入／状态契约、与旧数据的关系、拒绝条件、真实执行／费用边界与非目标 |
| 包层和接口 | 先形成可校验事实与结果结构，再接桌面；IPC、记录格式与版本变化分别设计 |
| 桌面流程 | 配置 → 条件／费用确认 → 执行状态 → 失败处理 → 结果定位 → 对比／导出；解释新增入口与恢复点 |
| 质量与证据 | 对新增契约做相关测试、OpenSpec 校验与桌面实机流程；窄窗、200% 缩放、键盘、草稿与来源不完整场景按新增流程覆盖 |
| 真实案例 | 工程 fixture 与真实接入案例分别记录；需要特定工具／环境的阶段必须满足其支持范围 |
| 独创性验证 | 允许对照产品使用合理扩展，比较同类任务的接入、排障、验证时间与成本，保留不支持与失败结果 |
| 发行 | 按实际完成范围触发相应 K4 体验包；构建、实包验收与发布分别核对，不提前承诺版本日期 |

超时、取消、队列和跨重启执行恢复都需要真实执行契约。仅接入现有操作状态不等于这些能力已经支持；R3 中实际停止进程的要求必须落到实现和验证。

## 11. 建议的实施单元与下一步

以下是提案拆分建议，不是已创建 change，也不是精确工期估算。任务编号用于后续映射，正式 tasks 可按设计重新拆分。

| 单元 | 拟覆盖范围 | 优先级／依赖 |
|---|---|---|
| A：R2.2 首版 | R22-01–07、E1–E2；起点诊断、隔离 prompt 单分支、文件比较、结果／导出闭环 | 首先设计与交付，复用已归档 R2.1 |
| B：R3 技术验证 | R3-01–03 的后端／环境可行性试验 | 可在 A 期间独立准备；不默认开用户命令入口 |
| C：R2.3 最小双臂 | R23-01–06，复用 A 的共同实验基础 | 案例需要时提前；首版不包含多臂平台与重复采样 |
| D：R3 用户交付 | 通过 B 后实现命令、停止、日志、产物与失败／修复闭环 | 下一项核心执行能力；不依赖 C 或完整模型实验 |
| E：证据与实验扩展 | R3-E1–E3、R23-E1–E4，按真实需求分别提案 | 核心闭环验收后逐项交付，避免合成一个过大 change |
| F：R4 | 调用级采集、参数干预、真实重执行及相应增强 | 先设计检查点粒度／兼容策略，再按固定工具实现 |
| G：I／R5 独立适配 | 首个真实接入与后续每种新增适配 | 首个 I 随主线推进；后续对象需求驱动 |

**下一份具体方案应聚焦 A：R2.2 首版。** 先选一个确实需要改启动指令的文件任务，核对根基线、单项干预、输出／文件判据；据此细化包层 API、记录格式、桌面交互与逐场景任务。R3 后端验证单独形成小方案，不把完整 A/B 或研究储备列为其前置条件。
