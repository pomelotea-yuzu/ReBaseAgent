# 软件 i18n 与用户文档英文化决策记录

创建日期：2026-10-09。最近修订：2026-10-28。

状态：**阶段范围已确认，仅更新规划；软件与翻译实施尚未开始，须另行明确放行。**

背景：本文原用于记录门面文件英文化决策。2026-10-28 经重新讨论，下一阶段收敛为**现有软件完整中英双语 + 必要用户文档**，不为宣发另造演示产品。本文记录范围、顺序与验收要求，不放实施产物。国内社区宣发与海外 PR 宣发继续暂缓，其决策另行记录。

修订关系：下文取代旧版“只做门面文件”“UI i18n 不急且排在文档之后”“README 逐句直译”“沿英文 README 所有链接递归翻译”等口径。2026-10-09 的文档数量、约 40 KB 翻译量和源码行数均为历史估计，不作为当前工作量依据。软件 i18n 的技术选型、精确任务清单与排期仍待提案审阅，不因本文更新视为已批准实施。

## 一、已定决策

### 1. 阶段目标与边界

**让非中文用户能够安装、配置、完成核心调试操作、理解结果与限制，并知道如何反馈问题。**

两条工作线属于同一阶段目标，但分别设计与验收：

1. **软件 i18n**：覆盖现有产品用户可见界面的完整中英双语，不止演示路径或几个核心名词。
2. **必要用户文档英文化**：覆盖主要使用任务，不全量翻译 `docs/`，不要求英文引用链全部有译本。

中文仍为默认 README；软件默认语言规则、语言检测、语言选择入口与技术框架在实施提案中另定，不从 README 默认语言自动推导。

### 2. 软件 i18n 范围

| 范围 | 决策 |
|---|---|
| 导航、标题、按钮、表单、空态、帮助提示 | 纳入，覆盖当前产品已有页面 |
| 创建运行、录制、重跑、实验、比较、文件、项目验证与设置工作区 | 纳入；按完整操作闭环分批迁移，不长期混用语言 |
| 预检、费用及副本写入确认、执行状态、失败说明 | 纳入；文案事实与授权语义中英一致，不削弱风险提示 |
| 主进程和共享层返回、最终显示给用户的产品提示 | 纳入盘点，不能只扫描 renderer；本地化展示与稳定错误码分离 |
| 语言切换、偏好保存、缺失翻译回退 | 纳入；默认语言、保存位置、切换生效与回退规则在设计中明确 |
| 用户输入、模型输出、历史 trace、文件正文 | 不自动翻译，不重写已有运行记录 |
| 路径、工具名、协议字段、错误码等稳定标识 | 保持原值；必要时另加本地化解释，不修改契约 |
| 源码注释、测试说明、内部诊断日志 | 不以英文化为目标；因接入 i18n 必需的测试适配另列任务 |
| 业务逻辑、授权流程、全局页面重设计 | 不借机调整；只处理本地化必需的接线和布局适配 |

实施纪律：

- 先统一术语，尤其区分 Step/Turn、Replay/Rerun、运行分支与 Git 分支；文件起点须准确表述为对应轮末状态。
- 同一工作区的入口、确认、执行中、错误和结果一起覆盖；不能只把按钮改成英文。
- 切换语言不得丢失草稿、错绑执行身份、扩大既有授权或绕过配置修订校验；语言切换与授权保留/失效的具体交互规则须在提案中明确，不能悄悄改变。
- 英文长度变化须验证布局、窄窗、缩放和键盘操作；不只检查翻译键是否齐全。
- 不因界面出现英文就宣称 macOS/Linux 已支持，也不翻译历史数据来伪装界面覆盖率。

### 3. README 与门面文件

| 文件 | 决策 |
|---|---|
| `README.md` / `README.en.md` | 保留中文默认页，新增英文版，顶部互链；事实、能力状态、支持平台、命令、费用和安全边界等价，允许用自然英文改写句式，不自行改变定位与重点 |
| `SECURITY.md` | 首批提供英文版，中文主文件保留 |
| `CONTRIBUTING.md` | 后续完善英文版，补项目现状与文档导航，不依赖内部 HANDOFF |
| `CODE_OF_CONDUCT.md` | 后续完善英文版；核对现有准则版本与官方对应文本，不随意改写规范含义 |
| `LICENSE` | 不动，保留 MIT 英文原文 |
| `CHANGELOG.md` | 不补翻全部历史；新增版本是否附双语发布摘要另定 |

先校准本批中文内容与能力边界，再翻译对应批次，不无限等待整份文档“永久定稿”。保持价值、案例、入口与关键范围清楚；不把此次工作扩展为营销定位重做，也不将决策级限制全部藏进折叠区。

### 4. 用户文档分层

判断标准：**保证英文用户完成主要任务所必需的文档有英文版；其他链接可以指向中文，但须明确标注语言，不递归扩大翻译范围。**

以下是主题优先级，不是已经核实的逐文件施工清单；实施前按现有文档映射文件，缺失主题另列补写任务，避免重复新建指南。

| 优先级 | 主题或现有文档 | 决策 |
|---|---|---|
| 首批必需 | README、上手指南、模型配置、首次运行 | 提供英文路径，覆盖安装、平台前提、实际入口与成功判据 |
| 首批必需 | 隔离文件运行、续跑操作及其边界 | 覆盖历史文件起点、观察编辑、预检、授权、费用与结果核对，不用架构说明代替操作指南 |
| 首批必需 | SECURITY 与问题反馈入口 | 英文用户可理解支持范围、隐私注意事项与报告方式 |
| 按实际入口补齐 | `guide/mcp-readonly-diagnostics.md` | README 或使用路径引导 MCP 接入时提供英文版，保留只读范围与客户端信任说明 |
| 按实际入口补齐 | `guide/isolated-project-verification.md` | 英文界面开放验证入口时补齐，明确 Docker、平台、固定模板及执行限制，不默认后置 |
| 后续完善 | CONTRIBUTING、CODE_OF_CONDUCT、`architecture/replay-state-consistency.md`、`architecture/overview.md` | 贡献与机制阅读材料，后续分批补齐 |
| 后续完善 | `development/governance-and-maintenance.md`、`maintenance-policy.md`、`third-party-notices.md` | 治理、维护与第三方许可说明；翻译后置不影响既有许可义务，分发所必需的原始声明不得删减 |
| 后置或中文标注链接 | `development/project-status.md`、`research/2026-09-27-agent-debugging-landscape.md` | 不作为首批阻塞；指南中必要的当前状态必须准确，不能因该页未翻译而缺失 |
| 不翻 | 历史评审、报告、比赛材料、工程证据、内部交接、旧讨论稿与历史构建记录 | 保持中文；英文入口确有引用时标注语言 |

- **存放与命名：同目录 `*.en.md`**，如 `docs/guide/getting-started.en.md`；不集中复制 `docs/en/` 目录结构。
- **互链：**英文版顶部回链中文原文；已有英文对应文件的中文原文顶部加 English 入口，不提前创建悬空链接。
- **同步：**能力变化时同步修订受影响的双语用户说明；允许句式与版式不同，不允许命令、平台、费用或边界事实漂移。
- **导航：**CONTRIBUTING 英文版提炼公开项目现状与用户/开发文档入口；指向中文材料时标注 Chinese，不搬运 HANDOFF。
- 文档数量与体量按实施前清单重新评估，不沿用“7 篇、约 40 KB”的旧估算。

### 5. 模板与配套文件

- **范围**：`.github/ISSUE_TEMPLATE/` issue 模板 + `.github/pull_request_template.md` PR 模板；先检查已有文件再增补，不预设尚不存在。
- **语言策略：混排。**中文为主、关键字段标签并列英文，不维护两套同义模板；影响填写的必要说明也应可由英文用户理解。
- **内容要求**：
  - bug 模板填写实际使用的发行版本或源码提交、运行环境、复现步骤、预期/实际；不能仅凭仓库 `package.json` 推断已安装版本；
  - 引导提供脱敏后的相关 run/trace 与最小必要日志，明确不要提交 API Key、私密提示词或未经确认的项目文件，不强求完整数据目录；
  - feature 模板先问真实使用场景、当前做法、预期结果；
  - PR 模板带 build / typecheck / test / lint / OpenSpec 校验提示，具体命令以当前工程门禁为准。

## 二、后续工作与验收（待实施放行）

### A. 软件 i18n 工作线

1. 盘点用户可见文本与现有 IPC/错误展示路径，确定术语、语言键、参数插值和稳定标识边界；核实现有测试约束，不沿用旧源码行数估计。
2. 单独提出软件 i18n 的 OpenSpec 方案，明确语言机制、默认与回退、持久化、切换行为、迁移批次和不改业务语义的边界；审阅通过后再 apply。
3. 按完整工作区迁移，优先完成首次使用与核心调试路径，再覆盖其他现有工作区，不以局部演示路径冒充全软件双语。
4. 验证缺失翻译、动态提示、错误展示、草稿和执行状态；做中英文布局、窄窗、缩放与键盘验收，复核授权与配置修订语义未回归。

### B. 用户文档工作线

1. 核定现有主题对应文件与首批清单，先校准本批中文事实，再产英文版及互链。
2. 首批完成 README、上手/配置/首次运行、隔离运行/续跑与 SECURITY；MCP、项目验证指南按实际开放入口同步补齐。
3. 调整或补充中英混排 Issue/PR 模板；后续完善贡献、机制、治理材料，不补翻全部历史。
4. 按英文指南实际走通：安装 → 配置 → 核心操作 → 结果核对 → 查限制/反馈；执行涉及真实费用、数据外发或副本写入时按既有规则授权，不能为验收绕过确认。

### 阶段完成标准

- 两种语言覆盖全部纳入范围的用户可见产品提示，不把原始模型输出或历史数据计入待翻文本。
- 英文用户无需理解中文即可完成声明支持的主要任务，并能读懂失败原因、授权范围和结果边界。
- 同一功能的 UI 与指南术语一致；中英文能力、平台、命令、费用与安全事实一致。
- 切换语言不损坏状态与执行关联，不扩大权限；必要的授权失效行为有设计与验收依据。
- 分别列明软件、用户文档与后续完善材料的完成情况；历史文档未翻译不计为缺陷，未完成用户入口不能靠中文兜底后宣称全程英文可用。

当前仅更新本决策记录；以上待办尚未执行，未创建实施 change、翻译文件或软件改动。

## 三、文档入库分流规则（2026-10-09 定）

**总则：过程可以入库，草稿不行；被引用的必须入库，没读者的不必。判断不了的默认入库**——"引用悬空"是硬错误，"多一篇过程文档"只是轻微噪音，两害相权取轻。

- **已入库的历史过程文档：不动。** 重写 git 历史成本高、无收益；且 `docs/` 成体系的 review / 调研 / 方案正是"开源治理 + 长期发展"评审维度的迭代记录证据。
- **新文档分流**：

| 类型 | 例子 | 入库？ |
|---|---|---|
| 引用链上的 | tasks.md / README 引用的 review、截图、机制说明 | **必须**（悬空引用是硬错误，先例 `181e11a`、`94725cd`） |
| 决策记录 / specs 设计 | `docs/product/` 本文件、未来设计稿 | 入库，供未来 agent 与协作者查阅 |
| 调研成果 | landscape、方案对比 | 入库，可被引用、可对外展示 |
| 内部交接 / 草稿 | `HANDOFF.md`、一次性试跑记录、中间态笔记 | 不入库（沿用 `.workbuddy/` 等既有惯例） |
| 宣发文章草稿 | 未发布的掘金/知乎稿 | **定稿发布后再入库**，草稿期不入库 |

- **草稿目录 = `docs/drafts/`**：个人工作过程文件与一切草稿一律放这里，已通过 `.gitignore` 规则 `docs/drafts/` 整目录排除（2026-10-09 已配置并验证）。
- 体量不构成问题：1.5 MB 纯文本摊进数百个 commit 增量可忽略；真正的成本是认知负担，因此**无读者的草稿一律进 `docs/drafts/`，不混入正式 `docs/` 分类**。

## 四、本阶段不做与暂缓事项（2026-10-28 校准）

- **npx Demo、静态交互 Demo、完整 Web 版或额外桌面演示模式**：均不作为本阶段交付，不为海外展示另造演示产品。
- **国内社区文章、HN/Reddit/X 等社区投放、Awesome PR**：继续暂缓；篇目、目标、渠道规则和实际发布授权另行讨论。
- **全量历史文档翻译**：不做；新增用户指南按实际任务需要判断，不递归追翻引用链。
- **macOS/Linux 打包**：不在 i18n 范围内，语言覆盖不等于平台支持。
- **业务功能扩展、授权改造及无关重构**：不做；若 i18n 暴露独立缺陷，单独记录和评审。

软件 i18n 已纳入阶段目标，不再列为“文档之后、不急”的外围事项；但本文范围确认不代替技术提案批准与实施放行。
