## 二、四张图的具体内容

### 图 1 · `hero.png` —— 首屏主图（最重要）

**要表达**：这是一个桌面工作台，左边是运行列表，中间是轨迹，右侧是详情。三栏一眼看懂。

- 停在「概览」tab
- 中间轨迹选中一个 **LLM 调用** 节点（不是工具节点）
- 右侧详情显示：模型名、tokens、延迟、缓存命中
- 侧栏 4–5 条记录，状态混合（已完成 2–3 条 + 出错终止 1 条），这样徽标颜色才好看
- **不要**打开任何弹窗

> 这张图在 README 里紧跟标题，是唯一决定"要不要点进去"的一张。

---

### 图 2 · `rerun.png` —— 改一步重跑（核心卖点）

**要表达**：改掉某一步的工具结果 → 从那一步重跑，重跑前有一道只读预检把关。

**踩过的坑（别重复）**：重跑编辑器显示的是 **`span.result` 字段**（`DetailPanel.tsx` 的 `toolMessageText`）。
- 选 `write_file` 的 span → 编辑器里只有一句 `已写入 README.md（298 字节）`，**没有可改的内容**
- 要选 **`read_file` 的 span** → result 是文件全文（130 字节 README），改起来才看得见

**推荐操作**：
1. 轨迹树点第 1 轮的 `read_file README.md`（那个 1ms 的工具 span）
2. 点「在此重跑」→ 编辑器打开，是 README 全文
3. **真的改一个字**（如把「这里原本只有一句话」改成「两句话」）。不改则底部提示"编辑值与原始结果相同"、确认按钮置灰
4. 滚到底 → 点「校验续跑条件」跑只读预检
5. 停在**预检通过、`确认重跑` 变亮**的状态截图 —— 这张图同时表达了"能改一步"和"重跑前有把关"
6. 顺手点「确认重跑」跑完，**分支树里会出现「改 tool_result」边和「分叉点 s_03」标注**，图 4 就有了

> 这条链路实测：`fork.at_span = s_03`、`resume_after_step = s_01`、只重跑 2 轮（不是从头 3 轮），
> 源目录 130 字节逐字节不变，新内容落 `workspace-blobs/sha256/354f5e4a…`（185 字节）。

### 图 3 · `files.png` —— 文件状态可回退（差异化最强）

**要表达**：这是 ReBaseAgent 和别的调试器不一样的地方——**文件也能退回去**。

- 「文件」tab
- 检查点选择器选中「第 2 轮结束」
- 左侧文件列表选中一个 **.md 或 .py 源文件**（不要 `a.txt` / `logo.png` / `gone.txt`）
- 右侧并排 diff，左侧「初始快照」、右侧「第 2 轮结束」，**两侧都有真实内容**且能看出改动
- 顶部文件树不要出现「不可用附件」这种状态

> 这张是三张里最能打的。别的工具改不了文件状态。

### 图 4 · `compare.png` —— 分支与对照

**推荐 `compare.png`**：分支树 + 底部「所选运行」详情，一图两信息。

- 「分支树」tab
- 树上有隔离分支，边标注 **「改 tool_result」**，节点旁有 **「分叉点 s_03」** 徽标
- 底部「所选运行」面板显示 `run_mur436u9_8zx5`、模型、**入口标注：改 tool_result · 分叉点 s_03**、**沿链累计（沿根累计）**：5 步 · 4.2k tokens，不等于从分叉点重跑一次的消耗
- 右侧「对照」栏勾选 2–4 条会显示指标表

> 侧栏混进纯对话 run（早期测试残留）不必刻意清理 —— 真实使用场景本来就有历史 run 混着，反而可信。
> 顶部「全部关系」可切换范围，嫌乱可只留隔离那一支。
