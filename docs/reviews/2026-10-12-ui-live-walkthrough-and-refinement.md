## 1. 范围与方法

通过现有开发启动器启动真实 Electron 窗口，使用本地 CDP 鼠标与键盘输入操作已渲染的入口；读取 DOM、尺寸并保存截图。没有注入虚构运行或直接修改 store 以跳过导航。少数树节点使用 DOM scrollIntoView 定位后点击，因此不能把此次操作步骤数或用时当作普通用户的寻找成本。

初始窗口受到遗留 200% 页面缩放影响，先记录该状态，再重启本次启动的进程，以 100% 页面缩放检查。主要 CSS 视口为 1210×713，后续窗口为 1220×723；系统 DPR 约 2.1。没有使用伪造视口的设备模拟。不同截图的尺寸有记录，本次不据此做严格布局收益比较。

现有列表有 581 次运行，包含大量历史验收标本和重复任务。代表样本：r_03 的工具错误恢复、export_e2e_root 的文件检查点、tree_r00/tree_r02 的分支比较，以及 run_mv20e7df_vlvn 的代理调用。

检查了概览、错误定位、步骤输入/结果入口、模型实验与返回、文件选择与差异、分支树搜索与对照选择、双运行比较和输出文本差异、messages 编辑工作区、会话草稿、录制接入与返回、操作空状态、新建运行初始表单。

没有提交模型请求、重跑、实验、创建或导出；没有修改输入内容或保存配置。打开实验与 messages 页面本身会创建会话内的基线草稿，这一行为也纳入观察。检查结束时软件保持打开，停留在比较页。操作登记仍为 0。

证据目录：[原始截图与 DOM 记录](../../output/ui-walkthrough-2026-10-12)。本稿已归入 `docs/reviews/`，选取的截图与 DOM 记录见[证据索引](2026-10-12-ui-live-walkthrough/README.md)。过程截图按仓库默认规则仅本地保存；全部原始输出继续留在 `output/`。本次不是发布验收。

## 2. 实际可用的结构

- 概览能区别运行结局与工具错误。r_03 显示“已结束”，同时说明工具错误不构成终止原因；点击“定位”能进入第 2 轮的 read_file 错误调用。该路径值得保留。
- 从工具详情进入模型实验，再返回，能回到原调用。messages → 录制接入 → 返回 messages → 返回调用的目标链也可用。本次未修改草稿，因此只证明目标与基线内容的返回，不证明已编辑长草稿或异步执行的完整回归。
- 文件页自动腾出运行导航空间，保留检查点、目录与正文关系；选择 a.txt 后能查看真实只读差异。文件 diff 主体在 1220×723 下实测约 950×372 CSS px，仍有主要阅读空间。
- 比较输出文本差异可直接切换，正文区域约 1204×549 CSS px。独立大工作区在这个任务上有价值。

分支树搜索会呈现命中入口，而图/关系列表仍保留关系上下文；搜索不等同于过滤列表。当前树、全部关系、搜索定位、所选运行与对照集合存在多个独立状态。本轮实际切换过这些状态，路径较绕；但自动化的定位方式和对功能的熟悉度会影响操作，暂不把它写成搜索失效或性能问题。

文件页的全局栏、运行头、标签、来源条、检查点和文件工具条形成多层横向信息。虽然正文高度满足已有约束，视觉层次仍可以收敛；没有证据要求把文件页改成另一种页面结构。

## 4. 方案修正：先表达清楚对象与状态

调研稿方案 A 继续优先，但范围应从“顶部、列表、命名”扩展到任务初始状态和提示去重。仅移动按钮或减少留白，难以解决本次最具体的混淆。

建议按以下顺序设计与验证，均为候选，未直接实现：

1. **明确当前对象。** 日常运行头显示该运行；编辑头显示来源运行和调用；比较头显示两侧对象；新建页显示新任务。顶栏旧选中 ID 的保留、移除或改为有明确含义的返回上下文，需要选择一种一致规则。返回按钮优先表达具体目的地。
2. **统一术语层级。** 为全局运行查看、分支关系视图、运行内容“步骤”、步骤目录与会话执行活动分别定名。候选词需在实际任务中验证，不能只把“轨迹”全部替换。
3. **处理初始状态与重复提示。** 必填与未修改采用适当的初始引导；必要校验在交互或准备提交时突出。费用、真实执行范围、副作用、缺失凭据等影响决策的事实仍可见。一个阻塞原因有主要呈现位置，其他区域避免重复整段解释；保持所有原有执行门禁。
4. **区分编辑会话与未提交修改。** 保留恢复能力；考虑清洁基线与修改草稿的标识、排序和计数规则。现有草稿生命周期是产品契约，不能只隐藏条目或删除 store 记录来获得清爽截图。
5. **整理全局与局部工具。** 根据应用、当前对象、当前任务和会话活动分工。先验证明确分组和摘要，再评估移位；录制异常、结果可达性和设置入口仍需满足现有规范。

方案 B 的统一任务外壳仍可做后续原型。当前观察支持保留大页面的编辑和比较空间，还不足以支持全面合并工作区、自由停靠或全部抽屉化。

## 5. 与 spec 和工程范围的关系

无需重新规划所有布局契约。第一轮可以建立一个边界清楚的 UI 整理变更，逐项对应主 spec：

| 候选调整 | 需核对的契约 |
|---|---|
| 文案、重复提示、初始校验层级 | 解释分层；异常可见性；创建、实验与重发的校验/核对规则 |
| 当前对象身份与返回文案 | 运行头；辅助来源；比较对象；返回和阅读状态 |
| 草稿计数与清洁基线表达 | 草稿登记、恢复、关闭协商、修订与目标绑定 |
| 全局入口或任务动作移动 | 全局栏、操作入口、并列内容标签及页头左右分工 |

需要改行为或明确位置条款的部分，通过新 delta 更新；历史归档证据保留。当前没有修改 spec，也没有以视觉整理为由放宽权限、收费确认或副作用边界。

后续同任务验证应以“指出当前对象、找到错误/文件、恢复已修改草稿、选定两条比较并返回”为核心，分别测当前界面与原型。此次为维护者工具辅助走查，无计时用户试验、竞品实测、窄窗矩阵或后台执行验证，因此不声称已证明可用性收益。
