## 一、复核通过的部分（实质可信）

### 2.x 会话状态与导航

- `reading-state.ts` 的 `files` 为**可选**子结构，`undefined`（未进过文件页）与
  `checkpoint: null`（进过、停在初始）语义可分 —— 抽查属实。
- `WorkspaceFileView` **确实删掉了**局部 `selection`/`pane`/`selectedPath` state，
  改读 store（`fileReadingOf` / `setFileReading`，见 107–108、295–330 行）。
  `useState` 残留的是**请求状态**（listState/initialState/selectedState）与重试计数，
  这些本就该是组件本地状态，不算回退。
- `pendingFileTarget` / `openFileAt` 接线存在，受 run 身份约束。
- 测试：file-reading-state 8 / file-checkpoint-resolve 13 / file-reading-target 12 /
  file-view-session-state 8，**全过**。

### 3.x 双侧读取与代次守卫

- `reading-request-guard.ts` 的 `RequestGuard`（`begin`/`accept` 单调代次）真实存在，
  组件三个请求面各持一个 `useRef` 守卫，**无 `cancelled` 布尔残留**。
- `sideResult` 只对 `ok` 给结果（failed/loading/idle 一律 `null`），**不再把 failed 折成 not_found**。
- 测试：file-two-side-read 52 条（含 3.1/3.2/3.3/3.4/3.5 能力断言与接线契约）。

### 变异验证（4 组全部被捕获 —— 说明 2.x/3.x 的判据是**载重**的）

## 二、复核发现的问题（4.x 实质未完成）

tasks.md 把 4.1–4.6 **全部勾成 `[x]`**，但 `git show 7aba8c8` 的提交信息自称
**「第4组（骨架版，视觉后迭代）」**。核对源码后，以下三条**不是"视觉待迭代"，是功能缺失**。

> **补充（同日二次核查）**：除了下面 4.5/4.6，**4.1 也被发现缺"可调整目录"**——
> `stepFileDirWidth` / `clampRestoredDirWidth` 是**死导入**（见下 P0）。原报告漏了这一条，
> 系二次深挖（顺着 `onDirWidth` 的消费链）才暴露。教训：**"import 了但没用"也是缺口信号**，
> 光看"函数存在 + 单测绿"会漏掉没接线的功能。

### 🔴 P0 — 4.1「可调整目录」未落地（死导入）

- `file-layout.ts` 的 `stepFileDirWidth`（键盘 16px 步进 + Home/End）与 `clampRestoredDirWidth`
  **写全了、单测也绿**（`file-layout.test.ts` 断言 ArrowRight→248 等）。
- 但 `WorkspaceFileView.tsx` 里二者**只出现在 import 语句中**（第 21/27 行），**零消费**；
  全组件搜 `onPointerDown`/`onMouseDown`/`resize`/拖拽 **零命中** ⇒ 目录宽**实际不可调**。
- 后果：tasks 4.1「可调整目录」是虚的；且 4.6 声称的「宽度调整」键盘路径同样不存在
  （`stepFileDirWidth` 的 Home/End/Arrow 正是为此写的，却没人调用）。

### 🔴 P1 — 4.5「真实差异导航」未接线（两颗死按钮）

- `WorkspaceFileView.tsx` 1016–1031 行的「上一差异」「下一差异」**没有任何 `onClick`**，
  仅按 `tools.prevDiff`/`tools.nextDiff` 决定禁用与否。
- 全 renderer 目录搜索 `goToDiff` / `revealFirstDiff` / `getLineChanges` / `findController`
  **零命中** ⇒ 差异导航从未接上真实命令。
- `MonacoEditors.tsx` 的 `CodeEditor` / `DiffCodeEditor` **不暴露任何编辑器实例**
  （无 `onMount` 引用外抛）⇒ 父组件**在结构上无法**发命令。这是先决条件缺失。

  **接线路径（已核实）**：`WorkspaceFileView.tsx:57` → `import { MonacoDiffEditor } from "./MonacoEditor"`
  → `WorkspaceFileView.tsx:1165` 渲染 `<MonacoDiffEditor …/>` → `MonacoEditor.tsx:112`
  `MonacoDiffEditor`（懒加载门）→ 加载完成后 `MonacoEditor.tsx:131` `createElement(LazyDiffEditor(), props)`
  → `MonacoEditors.tsx:46` `DiffCodeEditor` → `@monaco-editor/react` 的 `<DiffEditor>`。

  要外抛实例，改点只有一处：`MonacoEditors.tsx` 的 `CodeEditor`/`DiffCodeEditor` 加
  `onMount={(editor) => onEditorRef?.(editor)}` 透传；`MonacoEditor.tsx` 的
  `MonacoCodeEditor`/`MonacoDiffEditor` 需把 `onMount`（非 `data-*`/`aria-*`，当前被
  `editorAttrs` 过滤掉，**不会**透传）显式转发；`WorkspaceFileView` 再用 `useRef` 接住
  diff editor，从 `getModifiedEditor()`/`getOriginalEditor()` 发 `goToDiff`。
  ⚠️ 懒加载**加载中**时渲染的是 `MonacoFallback`（尚无实例）⇒ 导航按钮须按
  `tools.*` 判据保持禁用，待实例就绪才可用（与现有禁用语义一致）。
- 旁证：`diffCount: diffEligibility.ok ? 1 : 0`（919 行附近）—— **凭空写死 1**，
  从未从 Monaco 算真实差异数。于是 `resolveToolEnablement` 里
  "差异数 > 0 才启用" 的判据永远为真，"无差异不假跳转"这条承诺**没有实现支撑**。

### 🔴 P2 — 4.5「查找」根本不存在

- tasks 4.5 写「接入**查找**、换行、真实差异导航及模式控件」，但工具栏（968–1051 行）里
  **没有查找按钮**，也没有任何 `findController` / `trigger("actions.find")` 调用。
- `file-tools.ts` 算了 `tools.find`，**但组件从未消费它**（grep `tools.find` 零命中）——
  纯逻辑层的判据成了死代码。

### 🔴 P3 — 4.6「键盘」完全没做

- tasks 4.6 写「完成**键盘**、tooltip、焦点恢复、工具栏换行和持续错误反馈」，
  并声称覆盖场景「文件阅读键盘操作与离线加载」。
- `WorkspaceFileView.tsx` **没有任何 `onKeyDown`/`onKeyUp`**，无 `tabIndex`、无
  `role="listbox"/"option"`、无方向键处理、无焦点恢复逻辑。
- 测试侧：`file-two-side-read.test.ts` 与 `workspace-file-view.test.ts` 里
  **没有任何键盘相关断言** ⇒ 4.6 声称的"验证"不存在。
- 仅 tooltip（9 处 `title=`）与工具栏换行属实。

### 🟡 P4 — 测试判据口径偏弱（U1 同类问题复发）

第 4 组的"能力断言"对差异导航只做了**字符串存在性**检查：

```ts
expect(html).toContain("上一差异");
expect(html).toContain("下一差异");
```

这**不检查按钮是否被接线**——正因如此，两颗死按钮顺利通过了 52 条测试。
U1 已三度复发同一教训：**"渲染不渲染"类判据必须钉接线，不能只钉字符串**。
（本次 4 组变异中，①②③④ 被捕获的判据都是"接线契约"类，恰恰说明该口径有效——
而 4.5/4.6 缺的正是这类。）
