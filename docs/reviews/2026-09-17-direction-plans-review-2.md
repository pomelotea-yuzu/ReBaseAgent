## 4. 超出建议的加固（7 处）

1. **权威关系段补了优先序末端**：「当前 change 的实现契约与完成状态仍以 OpenSpec 为准，路线不能替代其变更流程」——审阅报告未提，但这是必要的，否则路线文档会越权于 change。
2. **编号表加了「是否代表顺序」列**，并额外说明「§11 是依赖与集成安排，同期工作可独立推进，不要求上一条中所有工作完成后才启动下一条」。
3. **可用性矩阵写入 K1–K4 的触发条件**，使排期矩阵同时成为打包节点判据。
4. **A 完成度加了免责**：「预算不等于实耗或按工时折算的完成率」。
5. **K0 表得出的实质结论**：Trace-as-Test 被识别为**包外能力**（只有包 API / CLI，无桌面入口），并禁止「把 CLI 通过写成 exe 可达」。
6. **R2.1 补了未提的边界**：「R1 导入拒绝的符号链接不能借导出转为支持，硬链接只按独立文件字节导出」。
7. **行号加了时效声明**：「以上行号为 2026-09-17 核查位置，实施时重新定位」；open-source 另加「下载包能否宣称包含某项能力，以路线 §9.1 的实包验收记录为准」。
