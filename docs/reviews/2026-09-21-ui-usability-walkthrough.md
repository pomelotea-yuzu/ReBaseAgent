## 2. 已复现问题

### R1 [P1] 整体固定列使文件阅读在常见宽度下不可用

打开隔离父运行，进入文件页，选择第 1 轮结束和 a.txt。默认 1210px 视口下，运行列表 320px、步骤目录 384px，文件页仅剩约 506px；文件页内部再常驻约 288px 文件目录，实测 Monaco 修改侧编辑器约 106px，短句被切成多行。在 1024px 视口，文件目录仍受 `lg:w-72` 控制常驻，修改侧编辑器约 5px。800px 时文件页只剩约 81px，产生整页横向滚动，页签和文字挤成竖条。

文件区在小于 1024px 时切换列表/内容的能力确实存在，但不能解决外层两列占宽；视口宽度也不能代表编辑器可用宽度。

- 证据：[默认宽度 diff](2026-09-21-ui-walkthrough-assets/22-file-diff.png)、[1024px](2026-09-21-ui-walkthrough-assets/32-file-width-1024.png)、[800px](2026-09-21-ui-walkthrough-assets/05-files-800.png)。
- 定位：`RunList.tsx:45`、`SpanTree.tsx:128`、`WorkspaceFileView.tsx:352`、`:597`。
- 方案落点：§4、§13、§17。文件页占据主工作区，不常驻步骤目录；依据内容容器宽度收起文件目录及切换 diff，不能只切换 Monaco 为 inline 就视为解决。

### R2 [P2] 查看其他步骤会直接丢失编辑草稿

隔离父运行选择 write_file，进入编辑，输入 `UI_REVIEW_DRAFT preserve me`；点击最后的 LLM 调用，再回到 write_file，编辑器已经关闭。重新打开恢复的是原结果，不是草稿，过程中没有放弃提示。

- 证据：[离开前](2026-09-21-ui-walkthrough-assets/16-draft-before-navigation.png)、[返回后](2026-09-21-ui-walkthrough-assets/17-draft-after-navigation.png)。
- 定位：`DetailPanel.tsx:1043` 起的组件局部编辑状态。
- 方案落点：§9.5、§18.1。草稿按 run/span/field 保存于会话状态；页签与步骤切换只改变阅读位置。保留草稿不等于恢复写入授权。

### R3 [P2] 错误重跑按请求成功收尾，失败呈现与草稿处理不一致

把父运行 write_file 的结果改为 `UI_REVIEW_FORCE_ERROR`，预检并授权后提交。服务返回 HTTP 503，子运行真实终止事件为 `errored / error`，但 renderer 的 `forking` 为 `success`、`forkError` 为 null，自动选择失败子运行，详情停在“尚未选择 span”。返回父运行时编辑器与草稿已丢失。这里的 success 是内部操作状态，本轮没有观察到单独的“运行成功”toast，不能把两者混写。

列表上的“出错终止”文字存在，但其绿色徽标仍与正常完成相同；分支树错误节点也用绿色状态点。旧“无正文，仅有工具调用”的错误解释在新记录中已修正，HTTP 503 原因可在失败调用详情中读取。

- 证据：[失败子运行落点](2026-09-21-ui-walkthrough-assets/20-fork-error-result.png)、[返回父运行](2026-09-21-ui-walkthrough-assets/21-parent-draft-after-error.png)、[完整错误详情](2026-09-21-ui-walkthrough-assets/10-failure-detail.png)。
- 定位：`store.ts:285` 起的 `forkAt` 在信封 ok 后直接设置 success；`RunList.tsx:15` 的颜色仅区分 crashed；`BranchTree.tsx` 同类状态派生。
- 方案落点：§3、§9.5、§12、§17.1。核实子运行自有终止事件，失败保留提交草稿，提供错误步骤入口，统一失败语义色。旧自审 P2-1 本轮有隔离路径的动态证据，未将结论冒充所有入口均已实测。

### R4 [P2] 执行中离开后没有全局反馈，完成会抢走当前阅读位置

提交隔离成功续跑后，立即切换到普通创建记录 `run_muapnwud`。页面不再显示进行中操作，约 7 秒后自动改选新子运行 `run_muaps3pw_m1lr`，打断正在阅读的记录。

- 证据：[执行中切换后](2026-09-21-ui-walkthrough-assets/24-fork-navigation-during.png)、[完成后被改选](2026-09-21-ui-walkthrough-assets/25-fork-completion-steals-selection.png)。
- 定位：`store.ts:305` 的无条件 `selectRun`，局部详情承载执行反馈。
- 方案落点：§12、§18。活跃操作独立于页面保存，切页后有常驻状态入口；用户离开原流程后只通知结果，不自动导航。关联/核对能力仍是 U 新任务。

### R5 [P2] 创建期间锁住整个工作区，失败记录入口只有文字

普通和隔离创建期间显示“执行中…（真实调用，请勿关闭应用）”，关闭、取消和 Esc 都被禁用，背景运行也无法点击；未显示已等待时间。失败后文本框内容仍保留，这是应保留的行为，但提示仅给出 run ID 并让用户去列表找，没有直接打开失败记录的动作。

- 证据：[创建等待](2026-09-21-ui-walkthrough-assets/07-create-waiting.png)、[创建失败](2026-09-21-ui-walkthrough-assets/09-create-failed.png)、[隔离等待](2026-09-21-ui-walkthrough-assets/12-isolated-waiting.png)。
- 定位：`CreateRunDialog.tsx:53` 起的 modalLocked；`store.ts:364` 起的创建错误分支。
- 方案落点：§10、§12。创建工作区与全局操作状态组合；关闭查看不等于停止，未支持真实取消时不提供假取消。通过可信失败 run ID 直接查看错误，不能解析错误文案获得关联。

### R6 [P2] 打开记录与执行完成后均没有结果概览

打开已有隔离运行、普通创建成功或隔离创建成功，详情都停在“尚未选择 span”，最终输出必须自行找最后的 LLM 调用。隔离说明和预算入口占据详情顶部，但未回答本次结果是什么。

- 证据：[打开已有运行](2026-09-21-ui-walkthrough-assets/03-isolated-open.png)、[普通成功记录](2026-09-21-ui-walkthrough-assets/08-create-completed.png)、[隔离创建成功](2026-09-21-ui-walkthrough-assets/13-isolated-created.png)。其中普通截图是在失败场景完成后重新打开成功记录补拍，不冒充创建完成瞬间截图。
- 方案落点：§3、§4。首次进入运行默认概览，输出/错误优先，提供步骤、文件变化和父子对比入口。

### R7 [P2] 从文件页返回轨迹再回来，会丢失检查点与文件选择

选择父运行“第 1 轮结束”的 a.txt，确认能看到初始/修改 diff；切轨迹，再切文件，自动回到初始检查点且没有选中文件。第一次进入文件页也默认初始状态，用户需要主动找已完成检查点才能看到变化。

- 证据：[查看变化](2026-09-21-ui-walkthrough-assets/22-file-diff.png)、[返回后重置](2026-09-21-ui-walkthrough-assets/23-files-return.png)。
- 定位：`WorkspaceFileView.tsx:63` 的局部 selection/path；`DetailPanel.tsx:1604` 起的条件挂载。
- 方案落点：§13.1、§18.1。保存每运行的检查点、路径、列表/内容模式及阅读位置；首次进入最近自有完成步骤，有明确跳转目标时优先定位。恢复选择仍须重新校验引用。

### R8 [P2] 对比仍缺少输出差异，四列指标标题被挤没

选择本轮隔离父子运行，对比只含指标，没有编辑前后内容和最终输出；两列 run ID 均显示 `run_mua`。加入另外两条运行后，右侧面板仍约 256px，DOM 实测“状态”指标名宽度为 0，四列 ID 均相同。

- 证据：[两条对比](2026-09-21-ui-walkthrough-assets/27-compare-two.png)、[四条对比](2026-09-21-ui-walkthrough-assets/28-compare-four.png)。
- 定位：`ComparePanel.tsx:121` 固定宽度、`:181` 取 ID 前 7 位。
- 方案落点：§7.1、§15。独立宽幅对比，双运行默认展示修改与输出；四条指标保留名称列及可辨身份。不同根不可比提示应按实际对象数量表述，不固定写“两条链”。

### R9 [P2] 分支树仍裁切节点内容，点击后的落点与提示不符

从刚完成的子运行进入分支树，当前节点在下方远处，视图仍从旧记录开始。节点按钮可见高约 74px，而含累计数据的内容高约 98px，尾行被裁。点击普通创建节点改变选中运行，但仍停留在树上，与“点击节点查看详情”的文字不一致。57 条记录时查找困难，运行列表仍无任务/ID 搜索。

- 证据：[进入分支树](2026-09-21-ui-walkthrough-assets/26-tree.png)、[点击节点后](2026-09-21-ui-walkthrough-assets/29-node-click.png)。
- 定位：`BranchTree.tsx:161` 的 overflow-hidden、`:218` 的提示，`shared/derive.ts` 的固定节点高度。
- 方案落点：§7、§14。默认聚焦当前分支，提供定位/搜索；区分选中、打开与加入对比，节点尺寸容纳规定行数。

### R10 [P2] 创建时核对模型与返回配置的路径不完整

隔离创建已显示当前模型和接入地址；纯对话创建仍没有这些信息。输入任务后想去设置核对，弹层挡住右上角设置按钮，没有就近设置入口。关闭创建、查看设置、再次新建，输入已丢失。表单和确认区还直接展示大量 `config_hash`、`write_authorized`、空工具表等实现说明。

- 证据：[纯对话创建](2026-09-21-ui-walkthrough-assets/06-create-form.png)、[隔离创建](2026-09-21-ui-walkthrough-assets/11-isolated-create.png)、[设置](2026-09-21-ui-walkthrough-assets/30-settings.png)、[返回空表单](2026-09-21-ui-walkthrough-assets/31-create-return-empty.png)。
- 定位：`CreateRunDialog.tsx:93` 的 settingsLine 只在隔离区渲染；`:34` 起的局部表单状态。
- 方案落点：§10、§16。两种模式都显示模型摘要和配置入口，返回保留任务；技术字段按需展开，但源目录采集范围、模型请求边界和本次授权保持可见。

### R11 [P2] 模态创建框没有限制键盘焦点

填写任务使创建按钮可用，将焦点放到创建按钮，按 Tab，焦点直接进入背景的步骤按钮；后续 Tab 继续遍历背景 LLM/工具。鼠标被遮罩拦住而键盘可进入背景，操作边界不一致。

- 证据：[焦点截图](2026-09-21-ui-walkthrough-assets/34-focus-escapes-modal.png)、[五次 Tab 的焦点记录](2026-09-21-ui-walkthrough-assets/34-focus-sequence.json)。
- 定位：`CreateRunDialog.tsx:102` 使用 `<dialog open>`，不是 `showModal()`，也没有焦点约束。
- 方案落点：§17.2、§19。改为创建工作区后按页面管理焦点；仍保留的真正模态框须约束 Tab/Shift+Tab、隔离背景并在关闭后恢复触发点，不把此结论未经验证推广到所有对话框。

## 3. 与旧报告的关系及已有改善

2026-09-15 报告的四列标题消失、短 ID 重复、节点裁切、节点点击不符、固定导航占宽和缺概览，本轮仍可复现。2026-09-19 自审关于“请求成功不等于运行成功”的问题，本轮在隔离 result fork 上取得动态证据。

以下已有能力应复用，不重复列为待开发：

- 隔离创建、只读续跑预检、显式副本授权、轮末边界说明，以及完整文件 IPC 和只读 diff 已可实际操作。
- 隔离创建已显示当前模型；旧报告“新建运行不显示模型”需收窄到纯对话模式。
- 新失败记录可展示 HTTP 状态、错误正文和占位零值说明；旧“失败原因全部缺失”已不成立。失败状态色和失败入口仍有问题。
- 普通创建失败时当前表单仍保留任务；问题在关闭/配置往返、步骤导航及分叉失败收尾，不能写成所有失败都会清空输入。
- 本轮实际读到原始和修改后文件文本，diff 的数据来源正确；布局可读性问题不能混同为文件内容损坏。

## 4. 方案调整与优先顺序

1. 先落实草稿生命周期、错误结局核实及独立操作状态，再开放可靠的跨页执行体验。R2/R3/R4 是具体回归入口。
2. 基础布局与概览可独立推进，先保证文件/编辑正文空间，再收敛导航、术语和信息密度。R1 在 1024px 已有内容不可用证据，不能仅以 C 的局部窄屏验收替代。
3. 在现有 A3 能力上接通创建、步骤、文件、结果与双运行对比，补文件阅读恢复、配置返回和失败定位。
4. 分支树、四条指标、状态色与键盘路径纳入同一轮验收。既有提案及归档保持原样，后续实施行为变化再进入 U 的 OpenSpec。

## 5. 数据保护与限制

原 `settings.json` 已按字节备份并恢复，恢复后 hash 一致；走查前存在的 56 个 trace/附件文件全部逐文件复核，变化数为 0；测试源目录 a.txt 保持原文。本轮新增的 5 条带 `UI_REVIEW_` 标识的记录及其引用附件保留，便于后续复现。测试 Electron、Vite 和模拟服务已关闭。

首次在本轮独立 Electron runtime 下启动时出现 safeStorage 解密错误；走查中的系统加密也显示不可用。本轮没有在正常用户启动环境下复现，因此仅记为环境限制，不推断已保存凭据损坏或新增通用缺陷。没有把原配置或凭据写进报告和截图。

本轮只改文档和记录截图；没有执行产品单元测试、全仓质量门禁或发行打包。新 UI 尚未实现，P1 原型和 P3 外部试用也尚未完成。取消、未知操作核对、缺父链降级及 200% 缩放仍需后续验证。
