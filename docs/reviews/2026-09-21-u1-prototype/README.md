## 1.3 核对结论（宽窗口 1440 / 1360）

任务 1.3 要求人工核对三件事，均在本原型上核对通过：

### ① 首次打开与无运行入口

- 首次加载列表且无选择时，原型选中最近可读摘要对应的运行并 **直接进入概览**（不要求先选 span）。
- 概览首屏即给出「结果 → 来源 → 本次消耗」三段，正常结束直接显示已记录最终输出。
- 数据目录没有运行时显示 **新建运行 / 录制接入** 两个实际入口，无营销欢迎页。
- 证据：`screenshots/overview-1440x900.png`、`screenshots/overview-1360x860.png`、`screenshots/empty-1440x900.png`

### ② 失败概览定位真实自有调用

- 本 run 以 `error` 结束且**有**带 error 的自有 `llm.call` 时：概览显示「自有 LLM 错误」+ 真实错误正文
  + **「打开该调用并展开所属 step」** 可点击入口；失败前正文另起一块标为「失败前输出（作为中间输出保留，不冒充最终结果）」。
- 本 run 以 `error` 结束但**自有 LLM 没有**错误详情时：显示「错误详情未记录」，
  **不虚构**失败调用入口；页头仍如实标「出错终止」。
- 证据：`screenshots/x-error-own.png`、`screenshots/x-error-nodetail.png`

### ③ 文件承载区不附带步骤目录

- 该断言由 **DOM 结构** 保证，而非靠断点隐藏：文件页容器（`#pane-files`）与步骤目录（`#stepsdir`）
  是**兄弟**节点，文件页容器内**不可能**存在步骤目录节点。
  测量脚本对四个尺寸逐个做了结构断言 `文件页内结构上无步骤目录节点 = true`。
- 文件页占满主工作区；不可用附件带文字标签（`缺失`），二进制项标 `二进制`，不渲染空编辑器冒充「文件是空的」。
- 证据：`screenshots/files-1440x900.png`、`screenshots/files-1360x860.png`、`screenshots/x-files.png`

## 1.4 核对结论（1024 / 800 / 640 / 200%）

### ④ 多尺寸与放大下关键阅读可达

| 应用内容视口 CSS 宽度 | 断点档 | 运行导航 | 步骤目录 | 正文详情宽 | 横向溢出 |
|---|---|---|---|---|---|
| 1440 | ≥1280 | 常驻 264 | 常驻 232 | **944** | 无 |
| 1360 | ≥1280 | 常驻 264 | 常驻 232 | **864** | 无 |
| 1024 | 960–1279 | 概览常驻 264；文件页自动收起 | 常驻 232 | **528** | 无 |
| 800 | 720–959 | 按需打开（默认收起） | 按需打开（默认收起） | **800** | 无 |
| 640 | <720 | 单工作区，辅助列表替换正文 | 不常驻 | 单列 | 无 |

- 四个尺寸下正文详情宽均 **≥ 480px**（design D2 的二次约束）；步骤目录出现时正文仍 ≥ 528px。
- 页面 **在全部尺寸下均无横向溢出**（测量脚本逐尺寸断言 `横向溢出 = false`）。
- 证据：`steps-*.png`、`files-*.png`、`overview-*.png`、`narrow640-aux.png`、`zoom200-steps.png`

### ⑤ 自动折叠后恢复用户布局

| 阶段 | 视口 | 运行导航 | 结果 |
|---|---|---|---|
| 用户在宽窗口把导航拖到 340px | 1440 | 可见 340 | 偏好被记录（仅本会话） |
| 缩窄到 1024 并进入文件页 | 1024 | **自动收起** | 符合 960–1279「文件页暂时收起运行导航」 |
| 回到 1440 并回概览 | 1440 | **可见 340** | 用户偏好**恢复**，未被自动折叠覆盖 |

- 同时：键盘聚焦分隔条后按方向键可调整宽度，结果被夹到合法范围（实测 296 / 216）。

## 原型阶段抓到并修掉的三个真实缺陷

原型不是"画完就算"，本轮在验证过程中命中三个缺陷——**它们正是原型要提前暴露的那类问题**：

1. **`[hidden]` 被 `display:flex` 盖过 ⇒ 四个 pane 同时渲染。**
   `[hidden]` 只是 UA 样式表里的 `display:none`，作者写的任何 `display:flex` 都会赢。
   首版 1440 截图里概览/步骤/文件三块并排出现，正是这个原因。
   修法：显式补 `[hidden]{display:none!important}`，并在测量里加 `可见pane数` 断言（恒为 1）。
2. **文件页仍带着步骤目录。** 首版把步骤目录嵌在共用的 `.body` 里，切到文件页时它仍在 DOM 中。
   D2 只要求 960–1279 档"暂时收起"，但 ≥1280 档会露出来——**违反断言③**。
   修法：把步骤目录移进只包住步骤页的 `.steps-wrap`，与文件页成为兄弟节点，由结构保证不出现。
3. **正文被压到 240px。** D2 要求「≥1280 时步骤目录需保证详情至少 480px，否则收起」。
   首版没有这条约束，1440px 下正文只有 240px——正是走查 R1 的同一类问题。
   修法：加 `min-width:480px` 二次约束，实测四个尺寸全部达标。

## 未验事项（不得当作已通过）

- **真实 Electron 窗口、真实 200% 系统/应用缩放**：本轮用 Chrome 的 CSS 视口等价测量
  （200% 缩放等效于 CSS 视口减半，此处以 640px CSS 视口判定），**未**在 Electron 内实测 `zoomFactor`。
- **真实数据**：全部为内置示例数据。真实 trace 上的布局需在实施后用同一组 fixture 复现。
- **文件内部行为**：检查点选择、路径恢复、diff 模式自适应属 U2，本原型只用静态示意证明"外壳没有多余步骤目录"。
- **内容安全**：原型未包含真实 HTML/远程图片载荷，安全呈现的验证在实施阶段做。
- 因此 1.3/1.4 的勾选仅代表 **原型核对完成**，不代表 U1 的桌面验收通过。
