## ⚠️ apply 时必带的修正：`check:*` 应为「引用」而非「复制」

**问题**：design.md 表格自称 `check:test` / `check:lint`「不是复制体，是同一个表达式」，但实测两者的取值与既有 `test` / `lint` **逐字相同** ⇒ 字面上恰恰**就是**复制体。`check:typecheck` 同样有问题（根 `package.json` 本就有 `typecheck`，取值逐字相同），design/tasks 却把它措辞为「新增」。

**正解——引用既有脚本，物理上无法分叉**：

```json
"check:typecheck": "pnpm typecheck",
"check:test": "pnpm test",
"check:lint": "pnpm lint"
```

无递归风险（`pnpm test` → `test` 脚本 → `pnpm -r test`，无回路）。
`check:build` **保持** `pnpm --filter "./packages/*" build` —— 它与既有 `build` 取值不同，是设计里明说的**刻意收窄**。

## 已知坑（勿踩）

1. **`check:build` 必须收窄到 `packages/*`** —— `apps/desktop` 的 `build` 是 `electron-vite build`（前端打包链），拉进 CI 既与 non-goal「不跑 Electron 打包」直接冲突，又每次白付打包时间。`apps/desktop` **无跨包消费者**（无 `exports`，无人依赖它），其类型安全由 `check:typecheck`（`tsc --noEmit`，无副作用）承担，且**必须排在 build 之后**（它要解析 workspace 包的 `dist/*.d.ts`）。
2. **`check:test` 不得改成「根 vitest + `--root <包路径>`」** —— 模块双实例会导致 `instanceof` 假阳性（2026-09-10 实测 trace-test 因此报 2 个 `instanceof TraceTestConfigError` 失败）。必须是逐包执行、cwd = 包目录。
3. **`packages/replay/test/model-ab-cli.test.ts` 的 4 个 CLI 冒烟以 `dist/model-ab-cli.js` 存在为守卫**（`skipIf(!existsSync(CLI_PATH))`）—— build 范围配错或顺序颠倒会**静默 skip**（replay 66 → 62），而 **CI 依然全绿**。故 CI 顺序固定 **build → test**。spec 已为此立独立 Requirement（「跨包 CLI 冒烟不得静默跳过」）。
4. **`packages/trace-test` 无任何 CLI spawn**（8 个测试文件 grep `spawn|child_process|dist/` 零命中）—— 配 build 范围时**别按旧记忆**。唯一 CLI dist 冒烟在 `replay` 包里。
5. **已登记的平台风险**（不在 B1 修，tasks 4.4 只登记）：`packages/llm-proxy/test/handler.test.ts:472` **硬编码端口 58772**（runner 端口被占会假红）；`apps/desktop/test/app-icon.test.ts:7` 写死绝对路径 `"D:/ReBaseAgent/apps/desktop"`。
6. **`npx -y @fission-ai/openspec@1.12.0` 需联网，版本必须钉死**（npm 上的裸 `openspec` 是占位包）。校验失败属真实信号，不得跳过该步骤绕过。
7. **本机 pnpm 直调**（Git Bash 下 `pnpm` 不可用，corepack shim 路径转换 bug）——见 `HANDOFF.md` §五。
8. **renderer 资源规范不在 CI 覆盖范围**：`apps/desktop/scripts/release-check.mjs` 的 Monaco 静态审计属 `release:verify`、需要产物路径，CI 永不执行。**CI 绿 ≠ 打包产物正确**，已在 spec 的 non-goal 章节诚实声明。
