# ReBaseAgent v0.4.0-rc.1 发行候选 — 调试草稿保护、操作追踪、执行闭环、分支对比与录制/实验工作区

Agent 的时间旅行调试器。不止回放 Agent 做了什么，而是让你改变它做了什么。

Agent 跑歪时，bug 往往不在你的 loop 代码里，而在某一步的上下文里。云端平台能看但数据出境，本地抓包工具只读不可改。ReBaseAgent 让你回到跑歪的那一步，改掉脏掉的上下文，只重跑必要的那段 —— 轨迹保存在本地，真实模型请求按你的配置发往服务商。

## 相对 v0.3.0-k1 新增（一）：调试草稿保护与操作追踪

**① 草稿按编辑身份保存在会话内** —— result、system_prompt、user_message、messages 的编辑草稿按「父本 run + 调用 span + 字段」隔离保存；创建表单与模型 A/B 整批臂配置（含未通过校验的项）同样保留。导航往返、收起、Esc 都保留输入，明确放弃才重置。

**② 退出确认** —— 带着未放弃草稿关闭窗口（标题栏关闭 / Alt+F4 / app.quit）会弹出原生退出确认，默认「返回」；确认只放行本次退出，取消后已输入的文字原样保留。

**③ 草稿可定位** —— 调用旁显示草稿标记，步骤页提供本运行草稿列表；从列表跳回原 run / span / 字段，来源失效时保留输入供复制，不静默丢弃。

**④ 主动操作登记** —— 新建运行、结果重跑、prompt fork、代理重发、模型 A/B 提交均登记真实状态、幂等键、终态信封与结果 run ID；「结果待看」计数提示未读结果，点击直达；「结果交存并锁定」与「运行成功」分开表述。

## 相对 v0.3.0-k1 新增（二）：执行闭环与部分读取

**① 创建与重跑的统一执行工作流** —— 桌面端主动执行入口归一：判重、占槽、授权核对、执行与结果回执走同一套流程；重复提交被就近拦截并给出原因。

**② 引用父本的执行先核对来源** —— 五类引用父本的主动入口在执行前重新核对被引详情的可读性与完整性：详情加载失败拒绝执行，父链不完整（ownOnly）同样拒绝，均返回明确错误码；渲染层的禁用状态不作为保护依据。

**③ 父链缺失时结构化降级读取** —— 祖先 trace 文件缺失时，run 详情照常打开：标注「父链不完整（缺失祖先 run：…）」，只呈现当前 run 自有且通过校验的内容；用量区不补零、不推算——沿链祖先的指标如实显示为未知，缓存命中率不基于残缺数据计算。父文件恢复后重试即全量重验。

## 相对 v0.3.0-k1 新增（三）：分支对比升级

**① 宽幅指标表** —— 多分支对照为整页指标表：状态 / 步数 / tokens / 耗时 / 分叉点并排呈现，960px 视口以上左右并排、以下上下排列；显式选两条进入详细比较，单侧文件入口直达。

**② 详细比较页** —— 左右两列呈现两条 run 的输出与步骤目录，顶部提供「指标表 / 文本差异 / 交换左右 / 返回来源」；修改证据区记录分叉信息：改动字段、原值与新值、从头重跑还是共享前缀。

**③ 分支树视图** —— 节点为运行、连线为一次分叉：任务摘要、稳定短 ID、模型、状态、本 run 增量；入边标注分叉时改动的字段与分叉点 span id；支持完整 ID / 任务关键词搜索、视口缩放、图与关系列表切换、勾选节点加入对照（最多四条）。

**④ 比较导航** —— 「返回来源」回到进入比较前的位置；从单侧 run「返回比较」后焦点回到比较头部；只读反证保证比较对象身份一致。

## 相对 v0.3.0-k1 新增（四）：录制/消息/实验工作区

**① 独立录制工作区** —— 代理配置（监听端口 / upstream base_url）、保存并应用、真实监听状态与本地接入地址集中在一个全局工作区；「保存的启用意图」与「真实监听状态」分开呈现。

**② 消息工作区与结果区** —— 代理录下的 run 提供独立的 messages 编辑器与资格判据；结果区按登记派生：切换页面、重载后结果仍在。

**③ 模型实验工作区** —— A/B 臂编辑（最多 4 臂）、采样参数 JSON、与父本完全相同的空 fork 整批拒绝；先校验并预览计划（费用确认）后执行；批次结果按 experimentId 分组，各臂实际生效的参数以计划核对为准（实机验证：temperature 0.5 / 1.5 分别生效并落 trace）。

## 这版能做什么

- **录制 — trace 格式 v1 / v2**：JSONL 事实源，一 run 一文件，append-only；v2 在 `agent.step` 上带文件检查点字段，v1 照旧可读（两版本严格匹配，字段错配即拒）。
- **执行 — 纯 TypeScript 的 Agent 执行引擎**：OpenAI 兼容协议直连（DeepSeek / GLM / Qwen / Kimi 开箱即用），零厂商 SDK。
- **零摩擦录制 — 本地 LLM 录制代理**：独立录制工作区配置监听端口与 upstream，应用里把 `base_url` 指向本地代理即可录制；key 仅暂存内存、不落盘、不回传渲染层。
- **查看 — 三栏调试台**：导航 / 目录 / 详情三栏可调；概览页看结果与消耗；独立文件页；span 时间线逐步回看每一步模型当时看到的完整上下文；状态徽章全界面一个判据。
- **文件阅读**：检查点快照选择与导航、按真实变化筛选、路径查找、按宽度自适应的并排/inline diff、完整原文 + 查找/换行/复制、会话内恢复阅读位置、两侧状态诚实标注 —— 全程只读。
- **预算地图**：token 花在哪了，按消息 / 工具分布可视化。
- **时间旅行（四种改法，互不冲突）**：
  - (a) **改某步 `tool_result` 从该步重跑**：前缀全部本地命中，只有分支点之后才真正调 API；
  - (b) **隔离文件续跑**：带写工具的 run 在隔离副本世界里真重跑，源目录与父 run 逐字节不变；
  - (c) **prompt fork**：编辑 system_prompt 或首条 user_message，从头重跑一条独立新轨迹；
  - (d) **代理 messages 重发**：代理录下的 run 可编辑 messages 经代理重发，单请求级最小分叉。
- **模型 A/B 实验**：同上下文多臂并排（最多 4 臂），独立实验工作区，先校验并预览计划（费用确认）后真实调用；结果按批次分组、跨页存活；分支树按「换 model/params」归组。
- **缓存记账**：前缀缓存命中/未命中单独记账；缺数据显示「未知」，不伪装成零命中；父链不完整时指标不补零、不推算。
- **LLM 失败详情**：失败标记、span 级错误详情（含 HTTP 状态码）、key 脱敏落盘（实机验证：`****9999`），重启后仍可查。
- **多分支对照**：宽幅指标表 + 详细比较页 + 分支树，最多 4 条分支并排；修改证据记录每次分叉。
- **调试草稿保护**（本版新增）：会话内按编辑身份保存、退出确认、草稿可定位。
- **操作追踪**（本版新增）：主动操作登记、幂等键、终态信封与结果 run ID、结果待看计数。
- **部分运行读取**（本版新增）：父链缺失时结构化降级，缺失项不补零、不推算，恢复后全量重验。

> 类比传统调试器：上下文预算地图是 Profiler，改 tool_result 重跑是「改一行代码重跑」，
> 隔离文件续跑是「带副作用的操作也能安全回滚重跑」，分支树 + 宽幅指标表是「并排看两个分支的代价与结局」，
> 操作追踪是「调用历史面板」，草稿保护是「未保存更改警告」。

## 已知限制（诚实声明）

- **代理父本分叉未在本轮实机验收中验证**（验收环境无代理录制父本）；Trace-as-Test 为包外能力（exe 内不含），不计入本包验收。
- **执行中的 run 不出现在左侧列表**，完成后才出现——这是列表刷新时机的现行设计。
- **UI 未显示版本号**：窗口标题固定为 ReBaseAgent；核验版本请比对 exe 的 SHA-256。
- 文件视图仍然只读，且只列出**本 run 自己写过的**文件；不提供导出、跨 run 文件 diff（结果导出在下一步路线里）。
- 目前只构建了 **Windows x64**，macOS / Linux 尚未出包。
- 接入仍需手工：要么在代码里接 SDK，要么把应用 `base_url` 指向本地录制代理。一键埋点与 Anthropic 协议尚未支持（代理只绑 `127.0.0.1`、仅 OpenAI-compatible `/v1/chat/completions`）。
- 时间旅行默认 **world-free 重放**；隔离文件续跑是例外（副本世界里真执行写操作）。prompt fork、代理重发、模型 A/B 与隔离续跑都是**真实重跑**，会按 provider 计费。
- 模型 A/B 是**实验对比**，不做「哪个模型更好」的排名；不产出臂间差值或胜出臂结论。
- 批量写盘占用尚无长期管理：隔离快照与共享附件会随 run 累积，清理引用计数尚未实现，重度使用请留意 `data/` 体积。
- 渲染层无 error boundary；代理失败 run 的调用级错误采集等遗留项归后续 change。
- 不做：中间消息任意编辑、span 级 diff、模型 A/B 排名、NSIS 安装包、arm64 构建。
