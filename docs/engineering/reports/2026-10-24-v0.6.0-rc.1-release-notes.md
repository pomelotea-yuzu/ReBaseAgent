## 相对 v0.5.0-rc.1 新增

1. **MCP 只读诊断（MCP0+MCP1）**——zip 附带 `mcp/` 自包含目录：让你正在用的 AI 工具
   （WorkBuddy、Trae、Cursor 等支持 MCP 的客户端）直接查询 ReBaseAgent 的运行记录——
   运行清单、步骤正文、两侧比较、检查点文件，全部**只读**（零写入/零执行/零出网）。
   配置一行：`node <解压目录>\mcp\dist\cli.js --data-dir <解压目录>\data`。
   完整能力边界（预算/游标/凭据过滤/费用）见仓库 `docs/guide/mcp-readonly-diagnostics.md`。
   已在 WorkBuddy 5.9.0 真实客户端完成代表任务两轮验收与 Trae 3.4.4 第二客户端验证。
2. **隔离 prompt 实验（R2.2）**——在根初始快照上做单变量 prompt 实验：改 system prompt /
   模型参数从同一基线重跑，跨运行检查点与文件比较、单侧导出；trace v3 记录。
3. **内部重构**——渲染层模块拆分（行为无变化，63 个巨型组件文件收敛为组合层）。

## 这一版能做什么

从 0.5.0-rc.1 的"录下 Agent 运行、时间旅行调试"之上：

- 在**你现有的 Agent 工具里**直接问"上次为什么失败"：AI 客户端通过 MCP 读运行记录、
  引用错误消息/文件清单/哈希，全程不改动你的数据；
- 用隔离实验回答"换一句 prompt / 换一组参数会不会更好"：同基线、单变量、可比。

## 已知限制

- 仅 Windows x64 便携版；首次运行有 SmartScreen 提示（未购买代码签名，属未签名程序常规提示，
  可用包内 SHA256SUMS.txt 核验）。
- MCP 需要 Node.js ≥ 20（WorkBuddy 等客户端自带；zip 不携带 Node 运行时）。
- 不透传 `structuredContent` 的客户端（含 WorkBuddy/Trae）看不到 MCP 续读游标：
  超大文件只能读首段与清单事实（指南 §8 如实说明）。
- 人工实机验收未执行（自动门禁/离线冒烟/zip 解压自验全绿；见构建记录）；R2.2 视觉主观项
  待发行前人工验收。
- 隔离父本/分支上的 prompt fork 与模型 A/B 仍禁用；macOS/Linux 打包未提供。
