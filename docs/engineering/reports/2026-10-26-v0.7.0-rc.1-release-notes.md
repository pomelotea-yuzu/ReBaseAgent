# ReBaseAgent v0.7.0-rc.1 发行候选 — 隔离项目验证、MCP 测试证据查询

Agent 的时间旅行调试器。不止回放 Agent 做了什么，而是让你改变它做了什么。

Agent 跑歪时，bug 往往不在你的 loop 代码里，而在某一步的上下文里。云端平台能看但数据出境，本地抓包工具只读不可改。ReBaseAgent 让你回到跑歪的那一步，改掉脏掉的上下文，只重跑必要的那段 —— 轨迹保存在本地，真实模型请求按你的配置发往服务商。**本版起，修复结果可以在受限容器里跑固定检查，并通过 MCP 把验证记录交给你的 AI 工具查询**，全程只读、记录可回查。

## 相对 v0.6.0-rc.1 新增（一）：隔离项目验证（R3）

把「改完到底能不能跑」从一句断言变成**受限容器里的固定检查记录**。

- **在历史检查点上验证**：在文件页选择一个检查点，展开「项目验证」，对当时的源码快照跑 `typecheck` 或可信 `test`；源目录与运行记录不被改写。
- **环境准备与执行分开授权**：先只读预览来源、模板、下载来源与限额；确认后准备环境（固定镜像 digest + 固定工具链），再单独确认本次执行。两份确认互不替代，计划变化后旧确认失效。
- **受控边界**：只支持 Windows x64 + Docker Desktop（Linux containers）与 `node-ts-v1` 模板；受测源码限 `src/**/*.ts`，命令只有 `typecheck` / `test` 两个枚举，不接受自定义命令、依赖、镜像或限额；正式测试阶段容器断网。
- **结局分层、证据可回查**：退出码、TAP 计数、证据完整性与请求收尾分别记录；超时、输出超限、环境失败、停止未确认等不冒充通过。日志与产物按有界切片读取，缺项如实标注。
- **双验证比较**：两条验证并排显示来源、命令、环境、限额与结局；只有全部已记录条件一致、证据完整且左侧失败右侧通过时，才显示「同条件失败→通过」。
- **导出所测输入**：按 R2.1 口径把验证快照的精确源码导出到空目录，写入前重核快照绑定；不含日志、产物或补丁，也不代表测试通过。
- **停止与未知**：执行中可请求停止，确认所有工作负载静止后才落 `cancelled`；daemon 断连或清理无法确认时报 `unknown` 并保持阻断，不伪造成功。

## 相对 v0.6.0-rc.1 新增（二）：MCP 测试证据查询（MCP2）

发行 zip 的 `mcp/` 目录从 **七工具** 扩为 **十三工具**：在原有运行清单、步骤正文、运行比较与检查点文件查询之外，新增六个验证记录查询工具：

- `list_verifications` / `get_verification`：按运行、检查点、命令、结局精确筛选，读取记录摘要、命令与实际环境；
- `read_verification_log`：按验证/命令/流定位日志，码点切片与 `totalBytes` / `nextOffset` / `remaining` / `truncated` 如实返回；
- `inspect_verification_artifacts` / `read_verification_artifact`：产物清单、排除规则与可用性，按清单 path 读取并核验附件哈希；
- `compare_verifications`：固定两侧身份，返回条件比较与受限结论，并给出日志/产物/精确输入的回查引用。

边界不变：**只读**查询，不执行验证、不写盘、不调用模型、不出网；桌面与 MCP 使用同一套投影与比较判据；完整结果 64 KiB 预算、按码点收窄、认证游标续读；验证记录缺失、损坏、未封存或来源漂移都按稳定码失败，不补写、不猜同名来源。已用 WorkBuddy 5.9.2 真实客户端回查 R3 实际记录，并与桌面端对同一对象逐项对照；查询前后真实数据根逐文件指纹不变。

## 这版能做什么

- **录制 — trace 格式 v1 / v2 / v3**：JSONL 事实源，一 run 一文件，append-only；旧版本照旧可读。
- **执行 — 纯 TypeScript 的 Agent 执行引擎**：OpenAI 兼容协议直连（DeepSeek / GLM / Qwen / Kimi 开箱即用），零厂商 SDK。
- **零摩擦录制 — 本地 LLM 录制代理**：应用里把 `base_url` 指向本地代理即可录制；key 仅暂存内存、不落盘、不回传渲染层。
- **查看 — 三栏调试台**：导航 / 目录 / 详情三栏可调；概览、步骤、文件页与 span 时间线；状态徽标全界面一个判据。
- **时间旅行（四种改法）**：改某步 `tool_result` 从该步重跑；隔离文件续跑；prompt fork；代理 messages 重发。
- **隔离 prompt 实验（R2.2）**：根初始快照上的单变量实验、v3 记录、跨运行检查点/文件比较与单侧导出。
- **隔离项目验证（R3，本版新增）**：受限容器固定检查、双验证比较、精确输入导出，记录可回查。
- **MCP 只读诊断（十三工具，本版新增六个）**：外部 AI 客户端查询运行、检查点与验证记录。
- **文件阅读与导出**：检查点快照选择、按真实变化筛选、并排/inline diff、完整原文与查找、整目录导出。
- **模型 A/B 实验与多分支对照**：同上下文多臂并排（最多 4 臂）、宽幅指标表、分支树；不做胜出臂排名。
- **缓存记账 / 预算地图 / 草稿保护 / 操作追踪 / 部分运行读取**：沿用 0.6.0 已交付口径。

> 类比传统调试器：结果导出是「把复现材料打包给同事」，上下文预算地图是 Profiler，改 tool_result 重跑是「改一行代码重跑」，隔离文件续跑是「带副作用的操作也能安全回滚重跑」，隔离 prompt 实验是「固定其余变量只改一个输入的对照实验」，隔离项目验证是「在固定环境里跑一次可回查的测试」，MCP 只读诊断是「把断点上下文开放给你其它的调试工具」。

## 已知限制（诚实声明）

- **本版自动化门禁与离线冒烟全绿（desktop 225 文件 / 3474 用例；zip 组装三段自验、解压后十三工具自跑、打包后离线冒烟 12 判据全过），§9.1 人工实机验收未执行**；R3 面板的视觉/键盘/窄窗/200%/原生目录对话框实机取证也尚未完成。
- **R3 只声明模板范围**：仅 Windows x64 + Docker Desktop（Linux containers）+ `node-ts-v1`；真实项目接入（I 组 7.1/7.2）挂账未排期；不支持 WSL / 远程 Docker / Podman，也不会自动改用宿主命令。
- **R3 的环境来源**：首次准备需要联网拉取固定镜像与 npm 工具链（带完整性校验），正式测试断网；基础镜像经 DaoCloud 源按 digest 拉取，与 Docker Hub 官方源的一致性核对、Alpine 基础包逐包许可汇总仍未完成。
- **R3 不自动发起模型修复**：修复必须来自已记录的运行分支；人工改文件若没有记录，不会被描述成 Agent 修复。
- **MCP 需要 Node ≥ 20**（部分客户端自带；zip 不携带 Node 运行时）；首次使用前先启动一次桌面主程序生成 `data/` 目录。
- **不透传 `structuredContent` 的客户端（含 WorkBuddy / Trae）看不到 MCP 续读游标**：超大正文/清单只能读首段，分页同理（指南 §8，属已钉住的客户端行为边界）。
- **MCP2 未用本发行包重跑外部客户端验收**：WorkBuddy 5.9.2 的十三工具回查与桌面同对象对照基于源码/开发数据根；S16 外部实测基于 `v0.6.0-rc.1` 七工具包。
- **执行中的 run 不出现在左侧列表**，完成后才出现——列表刷新时机的现行设计。
- **UI 未显示版本号**：窗口标题固定为 ReBaseAgent；核验版本请比对 zip 内 `SHA256SUMS.txt` 的 exe SHA-256。
- 文件视图只读，且只列出本 run 自己写过的文件；跨 run 文件比较由实验比较视图承载。
- 目前只构建了 **Windows x64**，macOS / Linux 尚未出包。
- 代理接入仍需手工（SDK 或本地录制代理）；一键埋点、Anthropic 协议与内置 Agent 调用外部 MCP 工具尚未支持。
- 时间旅行中的隔离续跑、prompt fork、代理重发、模型 A/B 与隔离 prompt 实验都是**真实重跑**，会按 provider 计费；R3 验证本身不调用模型，MCP 查询零模型调用。
- 批量写盘占用尚无长期管理：隔离快照、验证记录与共享附件会随使用累积，重度使用请留意 `data/` 体积（本版 zip 约 100.7 MB，主因 `mcp/` 依赖闭包）。
- 渲染层无 error boundary；部分遗留项归后续 change。
- 不做：中间消息任意编辑、span 级 diff、模型排名、NSIS 安装包、arm64 构建、MCP 受控执行（按路线归 MCP3）。
